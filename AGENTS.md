# AGENTS.md — Rules for every agent in this repository

This file applies to the orchestrator and every dev agent (Claude Code,
Codex, Herdr-managed sessions, anything else). Read it before touching
anything. It is changed only on Eugen's explicit instruction.

## 1. Who and what

- **Operator:** Eugen (`eandres`, GitHub `JohnAndrewsX`). German speaker.
- **Project:** Seldon — engine (Rust), plugin (QML), logbook spec, contract.
- **Target platform:** Omarchy 4 "Quattro" (Arch, Hyprland, Quickshell
  shell process, plugin system). Reference: the local repo at
  `~/.local/share/omarchy` (`shell/README.md`, `shell/plugins/`) — *code is
  truth*; then https://plugins.omarchy.org/develop.html; then the Arch Wiki.

## 2. Language policy

- Talk to Eugen in **German**: briefings, questions, handovers, PR text
  addressed to him.
- **Everything in this repository is English**: code, comments, commit
  messages, docs, schema, ADRs, file and folder names, identifiers, enum
  values, log and error messages of the engine, UI strings of the plugin.
- The **logbook content** a user writes is in the user's language; Seldon
  never assumes English there. UI labels are English for v1
  (i18n is a later ADR).

## 3. Contract first

`schema/*.json` is the only agreement between engine and plugin.

- The plugin reads **only** `~/.local/state/seldon/index.json` (and the
  files it points to). It never parses Markdown, YAML or logs.
- The engine is the **only writer** to the logbook and the index.
- A change to a schema needs: an ADR, a bump of `contractVersion`, updated
  fixtures in `fixtures/`, and both sides updated in the same PR or in two
  PRs that are merged together. No exceptions.
- `fixtures/index.sample.json` must always validate against the schema and
  must always be rich enough to render every plugin surface. The plugin team
  develops against the fixture; the engine team keeps it true.

## 5. How work flows

Every unit of work is a **work package** `WP-NNN` in `work/`. The
orchestrator moves it `queued → active → completed`. A WP file has:
goal, inputs, outputs, acceptance tests, assigned role, dependencies.

1. Pick the WP the orchestrator assigned. Read it fully. Read every file it
   lists under *inputs*.
2. Work on a **git worktree** `wt/WP-NNN` on branch `wp/NNN-short-slug`.
   Never on `main`.
3. Keep commits small and English: `engine: add pacman collector (WP-004)`.
4. Run the WP's acceptance tests locally before handing back. If a test
   cannot run on your machine, say so explicitly in the handover.
5. Handover = a PR (or a `work/active/WP-NNN/HANDOVER.md` if no remote):
   what was done, what was not, how it was verified, open questions.
6. The reviewer role approves or sends it back. Only the orchestrator moves a
   WP to `completed`.

WIP limit: one active WP per dev agent. The orchestrator may run up to four
dev agents in parallel on independent WPs.

## 6. Zones (where you may write)

- **Green — this repository.** Free, within the WP.
- **Yellow — the test logbook** at the path given by `SELDON_LOGBOOK`
  (default `fixtures/logbook/` or a temp dir). Engine tests write here.
  Never point the engine at Eugen's real logbook unless the WP says so.
- **Red — the host system.** No `pacman`, no `sudo`, no edits under
  `~/.config` outside `~/.config/omarchy/plugins/jax.seldon` (the dev
  install of the plugin), no systemd changes. Collectors only *read*
  `/var/log/pacman.log`, snapper, `omarchy` CLI output.

## 7. Engineering rules

Engine (Rust):
- Edition 2024, `cargo clippy -- -D warnings` clean, `cargo fmt` clean.
- Allowed crates: `clap`, `serde`, `serde_json`, `serde_yaml` (or
  `gray_matter`), `chrono`, `anyhow`, `thiserror`, `regex`, `ulid`,
  `jsonschema` (tests), `notify` (feature `watch` only), `toml`,
  `dialoguer` (wizard). Anything else needs a one-line justification in
  the PR and reviewer approval.
- No async runtime. No network. Static musl release build.
- Every command supports `--json`. Exit codes: 0 ok, 1 user error, 2 engine
  error, 3 logbook not initialised.
- Idempotency is a feature: running any collector twice produces no new
  events. Tests prove it.
- Append-only files are never rewritten. Generated files (`STATUS.md`,
  `ledger/*.md` views, `index.json`) carry a header line
  `<!-- generated by seldon; do not edit -->`.

Plugin (QML):
- Follow the built-in plugins' patterns (`omarchy.clock`, `omarchy.agents`).
  Use `qs.Ui` components and `Style` tokens; never hard-code colours or
  fonts — the plugin must follow the active Omarchy theme.
- Never block the shell thread. Data comes from `FileView` watching
  `index.json` and from `Process` calls to `seldon`, both asynchronous.
- `omarchy plugin validate plugin/` and `qmllint -I "$OMARCHY_PATH/shell"`
  must pass on every commit.
- No symlinks in the plugin folder. No `omarchy.*` IDs.
- The plugin must render a useful state when: engine missing, logbook not
  initialised, index missing, index stale. Each state has a one-click fix.

Docs:
- Specs are normative. If code and spec disagree, fix one and say which.
- ADRs are immutable once accepted; supersede, don't edit.

## 8. Safety

- Never commit secrets, tokens, real hostnames or Eugen's private paths.
- Collectors redact anything that matches the redaction rules in
  `docs/SPEC-ENGINE.md §7` before an event is written.
- The plugin runs unsandboxed in the shell process. It therefore never
  executes shell strings built from logbook content. Only fixed commands
  with fixed argument lists.

## 9. When in doubt

Ask the orchestrator; the orchestrator asks Eugen. Destructive and uncertain
exclude each other.
