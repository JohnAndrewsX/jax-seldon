# AGENTS.md

Rules for every agent on this machine.

This folder is the logbook of this machine. It records what changed on the
system, why, and who did it. Any agent that reads this file may work here.
Seldon records; it never stops a command. Keeping to these rules is your
job. The long form, with a worked example:
https://github.com/JohnAndrewsX/jax-seldon/blob/main/docs/AGENT-GUIDE.md
(this file wins where they differ).

## Session start

1. Read `PROJECT.md`, `memory/lessons.md` and `STATUS.md`.
2. Find the active case: `seldon plan list --status active`, then
   `seldon plan show <ID>` and the case file (`seldon open case` prints its
   path). With the Claude Code hooks, `seldon hook session-start` has
   already given you this context; other agents run it themselves.
3. Read `areas/<area>/README.md` and `areas/<area>/AGENTS.md` of the case's
   area, and check open drift with `seldon drift`.

Write prose in the logbook's language (`language` in `PROJECT.md`);
headings, frontmatter keys and enum values stay English.

## The engine is the only writer

`seldon` writes the record; you call it. Never edit these by hand:

- `ledger/*.jsonl` — the events, append-only. A mistake is corrected with a
  new event, never by editing a line.
- `ledger/*.md`, `STATUS.md` — generated views (`<!-- generated by seldon;
  do not edit -->`). `seldon status` rewrites them.
- the frontmatter of cases (`status`, `events`, `agents`) and the folder a
  case lives in — the `seldon plan` commands move and update them.
- `.seldon/` — the engine's settings and the active-case marker.
- text inside `<!-- seldon:begin … -->` / `<!-- seldon:end -->` fences.

Everything else is Markdown for people and agents: the *Intent*, *Plan* and
*Result* of a case, `PROJECT.md`, `areas/`, `memory/`, `decisions/`, the
text outside the fences in `system/`.

## Work in cases

1. One active case at a time. No case yet? Propose one to the user and
   wait for their go:
   `seldon plan new "<title>" --zone <green|yellow|red> --risk <R0..R3> --area <area>`.
2. Write the plan into the case file before you change anything: goal,
   steps, affected paths, rollback, verification. Name packages and paths
   exactly; Seldon proposes linking a matching change to the case.
3. `seldon plan start <ID>` before you change anything. Every change the
   hooks and collectors see from then on carries the case id.
4. Add dated lines to the case's *Log* as you go (append only).
5. Fill *Result*, then `seldon plan verify <ID>` when the work is done.
   `seldon plan done <ID>` only once it is verified and the user agrees;
   `seldon plan drop <ID> --reason "<why>"` to give up.
6. Pass `--actor agent:<name>` wherever a `seldon` command takes it (`log`,
   `plan`, `drift`, `event`). Put free text after `--`.

## Zones

- **red** — packages, Omarchy itself (`omarchy update`, `omarchy pkg …`),
  systemd units, `/etc`, the boot loader. Only with a red case that has a
  rollback plan, and a snapshot first (`seldon plan start <ID> --snapshot N`).
- **yellow** — configuration under the watched paths (`~/.config/hypr`,
  `~/.config/omarchy`, …), themes, shell plugins. Only inside a case.
- **green** — everything no collector tracks: project files, language
  package managers, `git`. Recorded while a case is active.

Install packages with `omarchy pkg add`, not with the package manager
directly. Never edit files under `/usr/share/omarchy`; customise under
`~/.config`.

## Commands

- Read-only, safe at any time: `seldon doctor`, `seldon plan list`,
  `seldon plan show <ID>`, `seldon drift`,
  `seldon drift show <EVENT> --json`, `seldon open <what>` (prints a
  path), `seldon hook session-start`.
- Writing: the `seldon plan` steps above, `seldon log`, `seldon event`,
  `seldon decide`, `seldon drift link|explain|dismiss`,
  `seldon capture --all`, `seldon status`, `seldon hook session-stop`.
- Only when the user asks for exactly that: `seldon init`,
  `seldon hook install`, `seldon import … --apply`, `seldon agent start`.
- Add `--json` to parse the output. Exit 3: no logbook here; exit 4: the
  lock is held, retry in a moment.

## Journal and memory

- Journal: `seldon log "<text>" --case <ID> --actor agent:<name>`.
- What you learned goes into `memory/` (`memory/lessons.md`: one `## `
  heading per lesson), not into the chat.
- A decision that shapes the machine:
  `seldon decide --no-edit --case <ID> -- "<title>"`, then fill in the ADR.

## Drift

A change without a case is drift. `seldon drift` lists it. Resolve it only
when you know the reason: `seldon drift link <EVENT> <CASE>`,
`seldon drift explain <EVENT> -- "<why>"` or
`seldon drift dismiss <EVENT> -- "<why>"`. Otherwise ask the user. Never
hide drift by editing files.

## Hooks

The harness reports your commands to `seldon`; you do not have to:

- Claude Code: `seldon hook install claude-code` writes
  `.claude/settings.json` (`PreToolUse`, `SessionStart`, `SessionEnd`).
- Other agents: before a command, pipe
  `{"command": "…", "actor": "agent:<name>", "cwd": "…"}` into
  `seldon hook generic`; at the start of a session run
  `seldon hook session-start`, at its end
  `seldon hook session-stop --actor agent:<name>`.

Recorded: package, Omarchy and `systemctl` changes (red), writes into
watched paths (yellow), any other change only while a case is active
(green). Commands inside `xargs`, `find -exec` or `python -c` are not
read: run changes as plain commands.

## Ending a session

1. Fill the case's *Result*; `seldon plan verify <ID>`, or say what is
   left.
2. Lessons into `memory/lessons.md`; a last `seldon log` note.
3. Claude Code's `SessionEnd` hook runs `seldon hook session-stop`; other
   agents run `seldon hook session-stop --actor agent:<name>`.

## Never

- Write secrets, tokens or passwords into the logbook.
- Change the machine without an active case; run a red-zone command
  without a red case.
- Move, rename or delete case files, or any other part of the logbook.
- Point `seldon` at another logbook (`SELDON_LOGBOOK`, `--logbook`).
- Rewrite history: no edits to the ledger, no `git push --force`, no
  rewritten commits.
- Run shell strings built from logbook text.

Area rules: `areas/<area>/AGENTS.md`, where an area has one.
