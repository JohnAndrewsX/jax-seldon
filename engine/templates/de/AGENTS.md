# AGENTS.md — Regeln für jeden Agenten auf dieser Maschine

Dieser Ordner ist das Logbuch dieser Maschine. Er hält fest, was sich am
System geändert hat, warum, und wer es war. Jeder Agent, der diese Datei
liest, darf hier arbeiten. Lies vor dem Start `STATUS.md`, `PROJECT.md` und
`memory/lessons.md`.

## The engine is the only writer

`seldon` schreibt die Aufzeichnung; du rufst es auf. Nie von Hand ändern:

- `ledger/*.jsonl` — die Ereignisse, nur anhängen. Ein Fehler wird mit
  einem neuen Ereignis korrigiert, nie durch Ändern einer Zeile.
- `ledger/*.md`, `STATUS.md` — erzeugte Ansichten (`<!-- generated by
  seldon; do not edit -->`). `seldon status` schreibt sie neu.
- die Frontmatter von Cases (`status`, `events`, `agents`) und den Ordner,
  in dem ein Case liegt — das erledigen die `seldon plan`-Befehle.
- `.seldon/` — die Einstellungen der Engine und die Markierung des aktiven
  Case.
- Text innerhalb der Zäune `<!-- seldon:begin … -->` / `<!-- seldon:end -->`.

Alles andere ist Markdown für Menschen und Agenten: *Intent*, *Plan* und
*Result* eines Case, `PROJECT.md`, `areas/`, `memory/`, `decisions/`, der
Text außerhalb der Zäune in `system/`.

## Work in cases

1. Ein aktiver Case zur Zeit. Noch keiner? Schlag einen vor und warte:
   `seldon plan new "<Titel>" --zone <green|yellow|red> --risk <R0..R3> --area <bereich>`.
2. `seldon plan start <ID>`, bevor du etwas änderst. Jede Änderung, die
   Hooks und Collectors danach sehen, trägt die Case-ID.
3. Schreib den Plan in die Case-Datei: Ziel, Schritte, betroffene Pfade,
   Rollback, Prüfung.
4. `seldon plan verify <ID>`, wenn die Arbeit getan ist, `seldon plan done
   <ID>`, sobald sie geprüft ist; `seldon plan drop <ID> --reason "<warum>"`
   zum Aufgeben.
5. Gib `--actor agent:<name>` überall an, wo ein `seldon`-Befehl es annimmt
   (`log`, `plan`, `drift`, `event`).

## Zones

- **red** — Pakete, Omarchy selbst (`omarchy update`, `omarchy pkg …`),
  systemd-Units, `/etc`, der Bootloader. Nur mit einem roten Case mit
  Rollback-Plan, und vorher ein Snapshot (`seldon plan start <ID> --snapshot N`).
- **yellow** — Konfiguration unter den beobachteten Pfaden
  (`~/.config/hypr`, `~/.config/omarchy`, …), Themes, Shell-Plugins. Nur in
  einem Case.
- **green** — alles, was kein Collector verfolgt: Projektdateien,
  Paketmanager von Programmiersprachen, `git`. Wird aufgezeichnet, solange
  ein Case aktiv ist.

Pakete mit `omarchy pkg add` installieren, nicht direkt mit dem
Paketmanager. Nie Dateien unter `/usr/share/omarchy` ändern; Anpassungen
nur unter `~/.config`.

## Journal and memory

- Journal: `seldon log "<Text>" --case <ID> --actor agent:<name>`.
- Was du gelernt hast, gehört nach `memory/` (`memory/lessons.md`: eine
  `## `-Überschrift pro Lektion), nicht in den Chat.
- Eine Entscheidung, die die Maschine prägt:
  `seldon decide --no-edit --case <ID> -- "<Titel>"`, danach das ADR ausfüllen.

## Drift

Eine Änderung ohne Case ist Drift. `seldon drift` listet sie auf. Löse sie
nur auf, wenn du den Grund kennst: `seldon drift link <EVENT> <CASE>`,
`seldon drift explain <EVENT> -- "<warum>"` oder
`seldon drift dismiss <EVENT> -- "<warum>"`. Drift nie durch Ändern von
Dateien verstecken.

## Hooks

Der Harness meldet deine Befehle an `seldon`; du musst das nicht tun:

- Claude Code: `seldon hook install claude-code` schreibt
  `.claude/settings.json` (`PreToolUse`, `SessionStart`, `SessionEnd`).
- Andere Agenten: vor einem Befehl
  `{"command": "…", "actor": "agent:<name>", "cwd": "…"}` an
  `seldon hook generic` übergeben (stdin); zu Beginn einer Sitzung
  `seldon hook session-start`, an ihrem Ende
  `seldon hook session-stop --actor agent:<name>` aufrufen.

## Never

- Geheimnisse, Tokens oder Passwörter ins Logbuch schreiben.
- Einen Red-Zone-Befehl ohne roten Case ausführen.
- Geschichte umschreiben: keine Änderungen am Ledger, kein
  `git push --force`, keine umgeschriebenen Commits.

Bereichsregeln: `areas/<bereich>/AGENTS.md`, wo ein Bereich eine hat.
