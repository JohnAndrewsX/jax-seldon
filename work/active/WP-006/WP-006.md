# WP-006 — `log`, `event`, `plan` commands, case state machine, journal append

## Goal
Humans and agents can write to the logbook through the engine: notes,
manual events, and the full case lifecycle.

## Inputs
docs/SPEC-ENGINE.md §3, docs/SPEC-LOGBOOK.md §3 §4, docs/CONTRACT.md
(fixed argument lists the plugin will use), schema/case.schema.json,
schema/event.schema.json.

## Outputs
- `seldon log "<text>" [--case --actor --tag]` → `manual/note` event + journal append `## HH:MM · actor · case?`.
- `seldon event <source> <kind> --subject S [--detail --case --actor --meta k=v]`.
- `seldon plan new "<title>" [--zone --risk --area --priority]` → `work/queued/C-YYYY-NNN-slug.md` from the case template; `case-created` event; area created under `areas/` on first use.
- `seldon plan start|verify|done|drop <ID> [--snapshot N] [--reason]` — state machine `queued → active → verification → completed`, `* → dropped`; file moves between folders; `started`/`closed`/`snapshotBefore` set; `.seldon/active-case` written on start and cleared on done/drop; Log section append-only; journal stub on done.
- `seldon plan list [--status --area]`, `seldon plan show <ID>`, `seldon decide "<title>" [--case] [--no-edit]`, `seldon open <what> [--editor]`.
- Ledger append with flock (`~/.local/state/seldon/lock`), month rollover by event timestamp.
- Git autocommit `seldon: <summary>` when `git.autocommit = true` and not `--no-commit`.

## Acceptance tests
- State transitions enforced (invalid transition → exit 1 with message).
- Files move folders; frontmatter updated; body preserved.
- Log section is append-only (test: content before the Log section is byte-identical after three appends).
- `plan start` writes `.seldon/active-case` and records `snapshotBefore` when `--snapshot` is given.
- Journal entries are appended, never rewritten; `cases:` frontmatter list updated.
- All free text is taken as one argv element (no shell interpolation anywhere).

## Constraints
Allowed crates only. Every command has `--json`. Case ids `C-YYYY-NNN`
are allocated by scanning all three work folders (never reuse an id).
