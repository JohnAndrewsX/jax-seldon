# WP-081 — A lost or corrupt state directory leaves a trace

Role: Engine Dev (Opus, high). Operator decision 2026-10-04: no contract
change; a ledger note of an existing kind, a capture line and a doctor check.

## Goal

When the engine has to take a new baseline because its state directory
(`~/.local/state/seldon`: cursors, manifest, owned files) is missing or
unreadable although the logbook already holds collector events, the gap is
recorded in the ledger, printed by `capture` and shown by `doctor` — never
silently re-baselined.

## Inputs

engine/src/collectors/mod.rs (`Ctx::baseline`, cursors; the comment at
~line 270 about silently starting over), engine/src/commands/capture.rs,
engine/src/commands/doctor.rs (add a check; WP-079 edits the snapper check
and two constants in the same file at the same time — stay out of those),
the config collector's manifest and owned.json handling (WP-069/070
handovers: a corrupt manifest re-baselines silently), schema/event.schema.json
(`kind` enum: use `note` with `source: seldon`; no schema change),
docs/SPEC-ENGINE.md §3/§4, docs/user/{en,de}/10-troubleshooting.md and
11-update-and-uninstall.md (state-directory backup and restore, WP-056),
engine/tests/{collectors,doctor,idempotency}.rs.

## Outputs

- Detection: a collector has no cursor (or an unreadable/corrupt cursor,
  manifest or owned file) while the ledger holds at least one event of that
  source → "state loss" for that source. First run of a fresh logbook is
  not a loss.
- Ledger: one `note` event per capture that detected a loss, source
  `seldon`, subject `state-reset`, detail naming the sources and the baseline
  time, `meta` with the affected files' kinds; written once per loss (the
  next capture has cursors again, so no repeat; a test proves idempotency).
- `capture` prints a warning line (human and `--json` warnings) naming the
  sources and pointing at the restore steps in the user guide.
- `doctor` gets a check "State directory": ok / warn when the last capture
  recorded a state reset (read from the ledger, newest `state-reset` note)
  with the restore hint; the check also reports a corrupt manifest or owned
  file as a problem instead of letting the next capture re-baseline it
  silently (coordinate the wording with WP-070's checks).
- SPEC-ENGINE sentences; user guide 10 (what the warning means) and 11
  (restore) in en and de (de re-stamped in a separate docs(de) commit);
  CHANGELOG.

## Acceptance

`just check` 0; mutants: detection removed → test fails; note written twice
→ idempotency test fails; doctor silent on a corrupt manifest → test fails.
