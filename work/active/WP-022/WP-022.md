# WP-022 — Start agent from a case

## Goal
One button on a case card sends an agent to work the case: the configured
launcher runs with the case context from `seldon hook session-start`, and
the case is the active case while the agent works.

## Inputs
docs/PLAN.md (WP-022 row), docs/SPEC-PLUGIN.md §5 (Work row: "Start
agent"), §10, docs/SPEC-ENGINE.md §2 (config.toml), §8 (session-start
block, hook install), docs/CONTRACT.md, decisions/ADR-0014 ADR-0017,
work/completed/WP-009/HANDOVER.md (session-start, hook install),
work/completed/WP-020/HANDOVER.md (CaseCard actions), `$OMARCHY_PATH/bin/omarchy-agent*`
and `omarchy agent prompt --help` (read-only), memory/host.md item 8.

## Outputs
- Engine: `seldon agent start <caseId> [--launcher NAME] [--json]`
  (owner: `engine/src/commands/agent.rs`): sets `.seldon/active-case`
  (via `plan start` rules if queued? — no: the case must already be
  active; a queued case is refused with the hint `seldon plan start`),
  builds the prompt from `hook session-start` output plus "Work case
  C-… in <logbook>; every mutating command is recorded", runs the
  launcher from `config.toml [agent] launcher` (default
  `omarchy agent prompt --inline <text>`; alternatives documented:
  `omarchy-launch-floating-terminal-with-presentation claude …`) detached
  like `open --editor`; `--json` reports `{launched, launcher, case}`;
  never runs a shell string: the launcher is an argv list from config
  with `{prompt}` substituted as one argument.
- Plugin: *Start agent* on an active case's card (two-press arming), argv
  `seldon agent start <id> --json`; result line; `canWrite` gating; the
  Work tab shows "agent: <name>" on the case while `agents:` lists one.
- CONTRACT.md gains `seldon agent start <caseId> --json` (orchestrator
  edits docs on handover).
- Tests: engine tests with a stub launcher (argv recorded, prompt text as
  one argument, detached, failure reported), plugin harness scenarios.
- `docs/TESTING.md`, `plugin/README.md`; `engine/hooks/README.md` fallbacks.

## Acceptance tests
- `just check` exit 0.
- `seldon agent start C-… --json` with a stub launcher records exactly
  one argv with the prompt as one element and returns `launched: true`
  in under a second; a queued case → exit 1 with the hint; a missing
  launcher → exit 1 with the message.
- From the panel, the button on an active case calls the engine with the
  validated id; the result line shows the launcher.
- On the test host with the real `omarchy agent prompt` (unlocked
  session only; ORCHESTRATION.md §11 rule): an agent window opens with
  the context block; the host is restored afterwards.

## Constraints
No shell strings; the launcher argv comes from config, validated (first
element must be an executable name without `/` or an absolute path);
the prompt is one argument. Two workers: the engine part first (engine
dev), the plugin part when the engine command is on main — or one worker
owning both if the orchestrator assigns it so.
