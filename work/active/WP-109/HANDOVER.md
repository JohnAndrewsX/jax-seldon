## Decisions (ADR silent or WP-refined)

1. **`attention = "all"` is the whole pre-ADR derivation**, not "nothing
   routine, crisis by harm test": §5 calls it the rollback and the WP's
   acceptance asks it to reproduce the pre-ADR golden index. It does,
   byte for byte (verified against the old `index.sample.json` before the
   fixture changed; now pinned by `fixtures/index.attention-all.json`).
2. **A routine rule left out of `routine` does not apply; the event falls
   to the next row** (theme switch → attention `other`; a `system-link`
   under `systemd/user` → crisis; `-Syu` member → attention). That is the
   ADR's "drop `theme` to make theme switches attention again", stated
   generally.
3. **Rule ids** (`drift show`, `--all`): routine `sysupgrade`, `upgrade`,
   `keyring`, `omarchy-update`, `plugin-toggle`, `theme`,
   `omarchy-default`, `system-link`, `routine-paths`, `theme-assets`,
   `theme-repo`; attention `sysupgrade-red`, `upgrade-red`, `downgrade`,
   `package`, `omarchy-other`, `plugin`, `config`, `config-remove`,
   `other`; crisis `always-red`, `always-red-paths`; `attention-all`
   under the rollback.
4. **`theme-assets` and `theme-repo`** come from the WP's Omarchy-first
   section (orchestrator), which narrows §2's "`~/.config/omarchy/**`
   (themes included) → attention": non-code theme files and
   `backgrounds/**` routine, code files (`*.lua`, the four terminal
   configs, `vscode.json`) attention, a theme with `.git` routine.
   `theme-repo` needs a third value of the one capture mark
   `meta.matches` (§5 names two); still one string key, no schema change.
5. **`*.sample` under `~/.config/omarchy/hooks/` is never a crisis**
   (WP: "`*.sample` is not"; `omarchy-hook` skips it): an edited sample
   is attention `config`, a byte-equal one routine `omarchy-default`.
6. **Plain full upgrade** = argv `-S` + `-u`, no target, program
   `pacman`, `yay` or `paru` (§2 row 1 names bare `yay`); the rollback
   keeps ADR-0013's pacman-only test. A non-`alwaysRed` downgrade inside
   one (`-Syyuu`) is attention `downgrade` (no row names it: total row).
   A transaction without a command line is attention `other` (nothing
   says it was plain).
7. **Dependencies follow the highest class of their transaction's
   explicit members from the whole ledger**, also when those are
   resolved or cased; a transaction without an explicit member is
   attention `other`. An item's class is taken over its *open* members
   (after `--only`, routine leftovers simply leave the list).
8. **`omarchy update` attribution at index time**: an `install` or
   `upgrade` of `omarchy`/`omarchy-dev` whose version is the update's
   `to`, inside a plain full upgrade, at most 31 days before the update
   and not after it (the collector's lookback); a pacman `downgrade` is
   no attribution; both versions package-shaped (`N…-N`).
9. **A routine item named by an open case's Plan is shown as attention**
   (class `attention`, rule kept, e.g. `theme`), so `explain|dismiss`
   accept it like any listed item.
10. **`series.drift` ignores proposals** (they depend on today's open
    cases) and takes a group's class over all its caseless members.
11. **Agent refusal**: "active case" = status `active` only (not
    `verification`); decided on the item's class; checked before any
    write; `SELDON_ACTOR` counts like `--actor`.
12. **Built-in templates** are matched by file name too
    (`seldon-theme-set.sh`, `seldon-watch.service`): the same bytes under
    another name are not explained. The unit's `ExecStart` prefix may not
    contain whitespace; the file is re-read and must hash to the event's
    `hashTo`. With an unreadable `owned.json` the templates still
    explain and the file is kept.
13. **Watch-list upgrade**: both earlier default lists count (the
    released five-list and WP-089's unreleased six-list; a five-list also
    gains `~/.local/share/applications`). Done in `capture` only (where
    watch paths matter), saved under the lock; a failed save is a warning
    and this capture still watches the new paths.
14. **New `[drift]` keys are not serialised while default**, so a later
    engine's defaults reach configs `init` wrote; `alwaysRed` keeps its
    old behaviour (written).
15. **doctor**: the two new rows come last (existing tests index rows by
    position); the `drift` row is `ok` with the `non-default:` marker and
    only `degraded` for an unknown routine id (a user's own choice is not
    a problem, it is shown).
16. **Old events without marks classify by path** (§5): an old copy of
    an Omarchy default under `~/.config/hypr` stays attention; §5's
    "Omarchy-default copies leave `index.drift`" holds for marked (new)
    events, `.bak.*` and `shell.json` (by path).
17. **Schema**: besides `crisis`, the *description* of `drift[].zone` is
    updated too (it named the computed yellow, which is gone). No name,
    type or presence changes; `contractVersion` 1.
18. **Command JSON**: `drift --json` items and `drift show` gain `class`
    and `rule`, `drift --json` a `routine` count (additive; the plugin
    reads `drift show`'s `members` only).
19. **REBUILD.md** "open questions" lists open drift only (routine is
    history), like the index.
20. **Fixture dating**: the new rows lie before 09-30 21:41 so the
    plugin harness keeps its "today" numbers, the top 33 Changelog rows
    and the first crisis; `tests/plugin` changed only for counts and for
    the open group (mesa instead of the routine `-Syu` group) — no
    behaviour expectation of the plugin was changed. After the merge,
    WP-110's `quiet-crisis` scenario forges one yellow crisis by jq; the
    sample now has a real yellow crisis (the hook), so the jq also makes
    that one attention (setup only; its expectations unchanged in kind).
21. **`OMARCHY_PATH`** is a new read-only source of the config collector
    (Omarchy's shipped files, hashed when an event's file may be its
    copy); under `SELDON_TEST_GUARD` without the variable it is
    `<guard>/omarchy`, never the host's tree.

## Open questions

1. **Security (stage 2): `OMARCHY_PATH` is a trust root for
   `omarchy-default`.** The evidence compares a new file with
   `$OMARCHY_PATH/config/<rel>`; whoever controls the capture's
   environment could point it at a directory holding a copy of a planted
   hook and make that hook routine. The default `/usr/share/omarchy` is
   root-owned; the variable is Omarchy's own and the engine already
   passes it on to Omarchy's programs. Options: accept (an attacker with
   the user's environment can edit the ledger too, ADR-0028 F8), or
   trust only a root-owned `OMARCHY_PATH` for evidence. Not decided
   here; ADR-0028 §2 names `$OMARCHY_PATH`.
2. **RSS margin.** The watcher's peak on the ×10 fixture is 9.9–10.0 MB
   against 10 MB (Check results). Not a failure, but the next fixture
   growth will need the build to hold fewer copies of the ledger.
3. **`theme-assets` / `theme-repo`** narrow §2's "themes included" row
   (Decision 4); they come from the WP text, please confirm they stand.
4. `docs/user/de/05-cli-reference.md`: `docs-check` warns that the
   English page changed since the translation's source line (the help
   block of `seldon drift` gained `--all`); the generated block itself is
   current. For WP-111 (user guide).
5. ADR-0028 §5 says "Omarchy-default copies leave `index.drift`" on the
   first build; old events carry no mark and classify by path (Decision
   16). If the orchestrator wants old unmarked copies routine, that needs
   a by-content check at index time (reading `$OMARCHY_PATH` from the
   index build), which I did not add.

**Blockers**

- **B1 — order.** `alwaysRedPaths` now comes right after the two
  evidence rows (`class.rs` `Rules::config`), before `routinePaths`,
  as ADR §2 orders it; SPEC-ENGINE §5 item 4 follows. A file there that
  also matches `routinePaths` (a `<base>.bak.<epoch>`) is routine
  `routine-paths` only when it holds the content the ledger last
  recorded for `<base>`: the `hashTo` of the latest config event of
  `<base>` before the backup, or the `hashFrom` of the first one at or
  after it (`History::holds_base_content`; by time only, because the
  refresh writes the backup and the default in one second and the base
  sorts first by name — a test pins that). A base the ledger never
  recorded, other content, a newer base record or a name ending in
  `.bak.` without an epoch: crisis. The ledger is scanned only for such
  a backup (no index structure, no RSS cost). The four reviewer probes
  → crisis; a real refresh pair in `~/.config/uwsm` (backup = old
  content, base = Omarchy's default from a trusted tree) → routine both
  (`omarchy-default`, `routine-paths`), unit and CLI.
- **B2 — `theme-repo`.** The theme directory must be no link and hold a
  real `.git` directory (`symlink_metadata(..).is_dir()` for both),
  Omarchy's `! -L && -d .git`. Tests: a `.git` file and a `.git` link
  (CLI) and a linked theme directory (unit: the walker never enters a
  linked directory, so `evidence` is asked directly) → no mark.
- **B3 — watcher unit.** The template counts only when the program of
  `ExecStart=<prefix>/seldon watch` (`%h` expanded) is this engine: the
  running executable's canonical path, or a regular file of the same
  size and SHA-256 (the binary's digest is computed once per process,
  only when a unit file appears). Tests: the engine by its own path and
  a copy in `~/.local/bin` → explained; a foreign `seldon` under
  `~/.cache/evil/`, the template with `ExecStartPre`, with a shell in
  `ExecStart`, and with a line appended (K11) → not explained, crisis.
  The test copies the 113 MB debug binary and hashes it: that test takes
  ~9 s (release binaries are ~5 MB).
- **B4 — stdin targets.** `PacmanCommand.stdin_targets` is set by a `-`
  word; `is_plain_full_upgrade` is false with it, so members fall to
  `follow` (no explicit member: attention `other`). Rows: `-Syu -`,
  `-S -u -`.

  `/var/cache/pacman/pkg/`, `…/.cache/yay/` or `…/.cache/paru/` (no

  crisis to a case in `verification` that lists it → refused), K15 (an
  earlier default plus `~/dotfiles` → never widened), K19 (mixed
  explicit members, the crisis member outside the item → the dependency
  is a crisis): tests added.
- **N4.** RSS margin: noted, no change (see the check results below).
- **N5.** The watch-path upgrade edits only the `watchPaths` array
  (`config::with_added_watch_paths`): the new paths are appended after
  the array's last string, every other byte stays, and the result must
  read back as the same TOML with exactly those paths added. Refused
  (file left as it is, the capture warns `config.toml was left as it
  is: …` and keeps watching its old list, doctor's `watch` row is
  degraded "an earlier default list, but config.toml cannot be extended
  without changing the rest of it" with the line to add): no top-level
  key, the key only in a table, twice, quoted, an empty or nested array,
  an unclosed array, a non-array value, the key's text inside a
  multi-line string. Tests: unit (comments, trailing comma, literal
  strings, a path with `"`) and CLI (a commented multi-line file stays
  byte-identical except for the added paths; a quoted key: untouched).
