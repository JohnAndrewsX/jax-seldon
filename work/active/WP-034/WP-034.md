# WP-034 — `seldon watch` (feature-gated) and systemd user unit template

## Goal
An optional, off-by-default watcher that rebuilds the index when the
logbook changes, with a documented systemd user unit the operator may
enable. ADR-0005 stands: no daemon by default; the shell's timer remains
the v1 path.

## Inputs
docs/SPEC-ENGINE.md §3 (`seldon watch [--interval SECS]`, feature "watch",
optional), docs/PLAN.md WP-034 row ("inotify triggers debounced index
rebuild; RSS < 10 MB; unit documented, off by default"), decisions/ADR-0005,
AGENTS.md §7 (`notify` only under the `watch` feature; no async runtime),
engine/src/index/ (`rebuild_if_initialised`, `derive`), engine/src/commands/
{status,capture}.rs (lock use), engine/Cargo.toml (features), memory/
rust-notes.md, memory/pitfalls.md.

## Outputs
- Cargo feature `watch` (default off) pulling `notify` (one-line
  justification in the handover: the only allowed watcher crate per
  AGENTS.md §7); the binary without the feature prints "built without
  the watch feature" and exits 1 for `seldon watch`.
- `seldon watch [--interval SECS] [--json]` (with the feature): watches
  `ledger/`, `work/`, `journal/`, `decisions/`, `system/`, `memory/`
  recursively and `.seldon/logbook.toml`; debounces (default 2 s, the
  `--interval` floor) and runs the index rebuild under the lock; ignores
  its own writes (`index.json` lives in the state dir, `ledger/*.md`
  views and `STATUS.md` are generated — skip events for generated files
  so the loop does not re-trigger); logs one line per rebuild to stderr
  (`--json`: one JSON line per rebuild); exits on SIGTERM/SIGINT cleanly;
  exit 3 when the logbook is not initialised.
- `engine/systemd/seldon-watch.service` (user unit, `%h` paths, documented
  `ExecStart=%h/.local/bin/seldon watch`, `Restart=on-failure`, hardening
  lines that do not break a user unit) and `engine/systemd/README.md`:
  install with `systemctl --user enable --now seldon-watch` only by the
  user; the wizard never installs it (AGENTS.md §6 red zone for workers).
- Tests (feature-gated, `cargo test --features watch`): a file change in
  a scratch logbook triggers exactly one rebuild within the debounce
  window; a burst of N changes triggers one; a generated-file write
  triggers none; the lock is respected (a held lock delays, does not
  crash); RSS measured in a test under 10 MB on the ×10 fixture (read
  `/proc/self/status` VmRSS; assert with margin).
- `justfile`: `check` also compiles and tests with `--features watch`
  (or a `check-watch` recipe included in `check`); CI unchanged otherwise.
- `docs/TESTING.md` engine notes; SPEC-ENGINE §3 wording for the
  orchestrator in the handover.

## Acceptance tests
- `just check` exit 0 incl. the feature build; `cargo clippy --features
  watch -- -D warnings` clean.
- inotify triggers a debounced rebuild (tests above); RSS < 10 MB on
  the ×10 fixture; the unit file is documented and off by default.
- Without the feature the command fails clearly; the musl release build
  (`just build-release`) still works without the feature.

## Constraints
No async runtime (notify's default backend is thread-based: use its
blocking `RecommendedWatcher` with a channel); no network; never run
`systemctl --user enable` on the dev host (guard); tests through
common::Env with SELDON_TEST_GUARD.
