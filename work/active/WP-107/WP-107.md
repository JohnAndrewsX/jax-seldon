# WP-107 — Config replay with an exact marker

Role: Engine Dev (Opus, high). 0.1.5, after WP-103. From the WP-103
reviews (stage 2 follow-up; round-2 verification N1/N2).

## Goal

The config replay no longer depends on whole-second timestamps: the
cursor carries the id of the last event the capture wrote, and the
replay reads strictly after that event. This removes the three known
limits WP-103 names in SPEC-ENGINE §4.

## Inputs

engine/src/collectors/config.rs (`replay`, `collect_from`, the window
WP-103 built), engine/src/collectors/mod.rs (cursor shape), the WP-103
handover and review packets (private folder; scenario tests r10, r13,
c03 in the reviewer's scratch notes), docs/SPEC-ENGINE.md §3/§4.

## Outputs

- The config cursor stores the id of the last config event the capture
  wrote (optional field, old cursors load and fall back to the WP-103
  window); the replay reads strictly after that id.
- Tests: r10 (removal at the check time), r13 (a previous change applied
  to a same-content twin), c03 (a change in the same second as the
  restored cursor's check, real time), plus every WP-103 restore test.
- SPEC §4: the three known limits removed; CHANGELOG.

## Acceptance

`just check` 0; mutants. Review: stage 1 Opus, stage 2 Fable (engine core).
