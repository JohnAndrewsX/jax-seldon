# WP-083 — doctor warns before the capture that would record a state reset

Role: Engine Dev (Opus, high). 0.1.3 wave. Proposal 1 of the WP-081 review.

## Goal

When the state directory is missing, unreadable or bound to another logbook
while the ledger already holds collector events, `seldon doctor` says so
*before* the next capture takes a new baseline — the moment a restored
backup still prevents the gap.

## Inputs

engine/src/commands/doctor.rs (the `state` rows of WP-070 and `check_reset`
of WP-081), engine/src/commands/capture.rs (`Binding`, `loss()`, the
state-reset note of WP-081), engine/src/collectors/mod.rs (cursors),
engine/tests/doctor.rs, docs/SPEC-ENGINE.md §3 (doctor), docs/user/{en,de}/
10-troubleshooting.md and 11-update-and-uninstall.md (state-directory
backup and restore), work/completed/WP-081/HANDOVER.md.

## Outputs

- A `degraded` `state` row "the next capture will record a state reset for
  <sources>: cursors missing / unreadable / bound to another logbook" with
  the fix "restore the state directory from a backup now (user guide), or
  run `seldon capture` to accept the new baseline"; for the
  another-logbook case the fix says there is nothing to restore. The row
  uses the same detection as capture (share the code; no second
  implementation) and appears only when the ledger holds at least one
  event of a collector source (the WP-081 rule, including its F1 fix).
- The row disappears after the capture (the reset row of WP-081 takes
  over) and never appears for a fresh logbook or a collector that never
  ran here.
- Tests: missing cursors with events → row; fresh logbook → no row; other
  logbook's cursors → row with the no-restore fix; after `capture` → the
  WP-081 row instead; mutants per claim.
- SPEC-ENGINE §3 doctor list; user guide 10 and 11 en+de (de re-stamped
  in a separate docs(de) commit); CHANGELOG.

## Acceptance

`just check` 0; mutants per claim in the handover.
