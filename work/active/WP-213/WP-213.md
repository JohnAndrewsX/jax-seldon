# WP-213 — the roadmap after the 0.3.0 numbering decision

Docs only. Operator decision 2026-10-12 (E86): the next release is
**0.3.0**, by `docs/VERSIONING.md` as it stands (a compatible addition —
new keys, IPC targets, plugin surfaces — is a minor release before 1.0).
The work packages and plans written before that call the current work
"0.2.x" / "0.2.y" and the contract-3 release "0.3".

Role: Docs Dev (Opus, medium). Reviewer: Opus.

**Do.** Renumber every forward-looking release label, never a historical
one:
- what ships from `next` now (the former "0.2.x" and "0.2.y" packages that
  are merged or in review at the time of this WP) → **0.3.0**;
- packages still queued under "0.2.x"/"0.2.y" → "0.3.x" (a later 0.3
  release; a compatible addition is still a minor bump, so name it "a
  0.3 minor or patch release" where the WP adds a surface);
- the former "0.3" (contract 3, crashes, reports, recipes, graph
  layouts) → **0.4**; "0.4" and later shift by one in the same way.
Files: `work/queued/*.md`, `docs/PLAN.md`, `STATUS.md`'s queue text,
`docs/` and `README.md` where they promise a future release (grep), the
CHANGELOG's `[Unreleased]` notes that name a release, ADR texts only
where an ADR is still `proposed` (accepted ADRs are not edited; list
those that name "0.3" in the handover instead). Past releases, completed
WPs and the private roadmap page are not touched.

**Acceptance.** A table in the handover: file, old label, new label;
a grep for "0.2.x", "0.2.y" and the contract-3 "0.3" in the edited scope
returns only historical mentions, each named; `just docs-check` green.

**Inputs.** `docs/VERSIONING.md`; `docs/PLAN.md`; `work/queued/`;
`STATUS.md`; private `reports/2026-10-09-roadmap-wps.md` (read-only).
