# WP-049 — CLI polish: shell completions, man page, help texts, clean removal commands

## Goal
`seldon` feels finished on the command line: completions for bash, zsh
and fish, a man page in the package, consistent `--help` texts, and clean
reversal commands for what `init` installs.

## Inputs
engine/src/main.rs and engine/src/commands/*.rs (clap definitions),
packaging/PKGBUILD (where completions and the man page get installed),
.github/workflows/release.yml (assets), docs/user/en/05-cli-reference.md
(WP-045, generated from --help), docs/SPEC-ENGINE.md §3 §9, AGENTS.md §7
(crate policy: `clap_complete` and `clap_mangen` need the operator's
one-line approval — granted 2026-10-02 with the WP set).

## Outputs
- `seldon completions <bash|zsh|fish>` (clap_complete) and a build-time
  or `seldon mangen` generated `seldon.1` (clap_mangen); PKGBUILD installs
  completions and the man page; `install.sh` installs completions under
  the prefix when the shell dirs exist.
- `--help` texts reviewed for every command: one sentence per command,
  consistent flag wording, examples where a flag takes a form (`--since`,
  `--`); the CLI reference check from WP-045 passes after the edit.
- `seldon hook uninstall <claude-code|generic>`, `seldon init
  --remove-theme-hook` (or `seldon setup theme-hook --remove`): remove
  exactly what was installed, recorded through the own-writes mechanism
  (WP-038) so the next capture explains the removal too.
- Tests for completions generation, man page generation, the removal
  commands (hermetic); docs: SPEC-ENGINE §3, TESTING.md, user docs page
  11 (update and uninstall) updated.

## Acceptance tests
- `just check` exit 0; `seldon completions bash | bash -n`; `man -l
  seldon.1` renders.
- Removal commands leave no drift after the next capture.

## Constraints
Only the two approved crates; no network; a guard block is reported,
never worked around.
