# WP-040 — AUR package `jax-seldon` (PKGBUILD, .SRCINFO), release workflow

## Goal
A clean Omarchy can install the engine with `omarchy pkg aur add
jax-seldon` (ADR-0016) and the plugin with `omarchy plugin add …jax-seldon-plugin.git`
(ADR-0009); a tagged release produces both automatically.

## Inputs
decisions/ADR-0001 (binary name + `jax-seldon` symlink), ADR-0009 (subtree
split), ADR-0016 (install via AUR helper), ADR-0005 + work/completed/WP-034/HANDOVER.md
(the package ships the `watch` feature; the unit is documented, never
enabled by the package), engine/Cargo.toml (`version`, `rust-version`,
features), justfile (`build-release`, musl target), engine/systemd/
(unit + README), engine/hooks or `seldon hook install` (what the package
must not do: no hook installs, no units enabled), .github/workflows/ci.yml,
docs/SPEC-ENGINE.md §3 (`version`, `--json`), AGENTS.md §7 (static musl
release build), the Arch packaging guidelines (Rust package guidelines,
`cargo fetch --locked`, `CARGO_TARGET_DIR`, `--frozen`), memory/host.md
(Omarchy 4.0.4 facts: `omarchy pkg aur add` = `yay -S`).

## Outputs
- `packaging/PKGBUILD` for `jax-seldon` (source tarball from the GitHub
  release tag, `sha256sums`, `makedepends=(cargo)` with the musl target
  or a glibc build — decide and justify: the AUR convention is a glibc
  build with `RUSTFLAGS` per guidelines; AGENTS.md §7 asks for a static
  musl release — pick musl via `rustup target` only if available in
  `makedepends` without network at build time; otherwise glibc with a
  one-line ADR note), `build()` with `--locked --release --features watch`,
  `check()` running the engine unit tests, `package()` installing
  `usr/bin/seldon`, the `jax-seldon` symlink, the systemd user unit under
  `usr/lib/systemd/user/seldon-watch.service` (installed, **not** enabled),
  `LICENSE`, the README. Nothing under `/etc`, no hooks, no `install`
  script that touches the user's home.
- `packaging/.SRCINFO` generated (see Constraints for how), kept in sync
  by the release workflow.
- `packaging/README.md`: how a release is cut (tag `vX.Y.Z` →
  workflow builds the musl binary as a release asset, updates
  `pkgver`/sha256 in the PKGBUILD, regenerates `.SRCINFO`, pushes the AUR
  repo from a deploy key stored as a GitHub secret, and runs
  `git subtree split --prefix=plugin` to `jax-seldon-plugin`), what the
  operator must set up once (AUR account + SSH key, the plugin repo, the
  secrets), and how to test a PKGBUILD locally on a disposable host.
- `.github/workflows/release.yml`: on tag push — `just check`, musl build,
  tarball + checksums as release assets, PKGBUILD/.SRCINFO update commit,
  AUR push (skipped when the secret is absent), plugin subtree push
  (skipped when the token is absent). Dry-run mode via
  `workflow_dispatch` that stops before pushing.
- `engine/Cargo.toml` version stays `0.1.0`; the first tag is `v0.1.0`
  when the operator says so (not in this WP).

## Acceptance tests
- `just check` exit 0 (the PKGBUILD is shell; `shellcheck` if installed,
  else `bash -n`).
- `.SRCINFO` matches the PKGBUILD (`makepkg --printsrcinfo` output
  byte-identical — see Constraints for where that may run).
- A build of the PKGBUILD succeeds on the **test host** in a scratch
  directory (`makepkg -f` without `-i`/`-s`; dependencies are whatever is
  installed there — if cargo/rustup is missing there, say so and stop; the
  operator adds them). Result: the package file lists exactly the files
  above (`tar tf`), `seldon --version` from the extracted binary works.
- The workflow passes `act`-free review: YAML lint plus a dry-run on a
  branch is the operator's call (network + secrets). Document the dry run.

## Constraints
`makepkg`, `pacman`, `yay`, `namcap` are red zone on the dev host (the
guard blocks them). All `makepkg` runs happen on the test host over ssh,
in a scratch dir, never with `-i`, `-s` or `--syncdeps`, and only if the
host's lock status is irrelevant for the task (ssh works while locked; do
not touch the shell there). Installing the built package anywhere is the
operator's step. No secrets in the repo. English commits like
`packaging: add PKGBUILD for jax-seldon (WP-040)`.
