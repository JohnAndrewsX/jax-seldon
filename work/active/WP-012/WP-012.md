# WP-012 — Panel actions: QuickEntry, Capture now, Open in editor

## Goal
The panel writes to the logbook through the engine: a quick journal note,
a capture, and opening the right file in the editor. Every action is a
fixed argument list; the index refresh arrives through the FileView.

## Inputs
docs/SPEC-PLUGIN.md §3 §5 §8 §10, docs/CONTRACT.md (command forms: free
text after `--`, `capture --all --json --quiet`, `open <what> --editor`),
docs/SPEC-ENGINE.md §3 (the JSON shapes of `log`, `open`, `capture`),
plugin/ (WP-011), tests/plugin/ (harnesses), work/completed/WP-006/HANDOVER.md
(`seldon log`, `seldon open`, no-tty editor path), work/completed/WP-011/HANDOVER.md.

## Outputs
- `plugin/components/QuickEntry.qml` on the Today tab: a `qs.Ui` TextField,
  optional case picker (open cases from `index.cases`), Enter sends
  `seldon log [--case <id>] -- <text>` with the text as one argv element;
  a result line (event id or the engine's error message); empty/blank text
  is refused client-side.
- *Capture now* (Changelog, and `c` key) runs `seldon capture --all --json
  --quiet` then `seldon status --json` through the service queue; the
  Changelog refreshes from the FileView when the index changes; a spinner
  while `busy`.
- *Open in editor*: Today → `seldon open journal --editor`; a case row →
  `seldon open <caseId> --editor`; Changelog month → `seldon open ledger
  --editor`; System → `seldon open status --editor`. Ids validated by the
  schema regexes before use.
- `plugin/Model.js`: `validateArgs` already accepts the forms; add helpers
  for the case picker and result formatting.
- `tests/plugin/`: harness scenarios with a fake engine recording the exact
  argv for log (incl. text starting with `-`, with quotes, with newlines),
  capture → status order, open variants; node tests for the helpers;
  a panel-view scenario for the QuickEntry.
- `docs/TESTING.md`, `plugin/README.md` updated.

## Acceptance tests
- `just check` exit 0.
- `seldon log` is called with the text as one argv element after `--`
  (fake engine proves it for `--help`, `a "b" c`, multi-line text).
- Capture triggers an index refresh via FileView (fake engine writes a new
  index; the Changelog shows the new event without a restart).
- Editor opens the right path for each variant (fake `omarchy-launch-editor`
  records the path; the engine's `open --json` output is parsed).
- Runtime smoke on the test host with the real engine (`seldon` built from
  main, copied to `~/.local/bin` there): note written to the logbook,
  capture runs, editor opens. Restore the test host afterwards.

## Constraints
As WP-011: fixed argument lists only, free text only after `--`, never
block the shell thread, tokens only, no symlinks, dev host copy-only, test
host is the runtime target, a guard block is reported, never worked around.
