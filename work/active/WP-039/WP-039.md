# WP-039 — Panel width and label fit: wider panel, tabs sized to their labels, chips that wrap

## Goal
Nothing in the panel is clipped at the operator's real scale: tab labels,
filter chips and the Changelog header line are fully readable, and the
panel is wide enough for its six tabs without crowding.

## Inputs
Operator's screenshot of the live panel on the dev host (2026-10-02):
the "Changelog" tab label is clipped at its right edge, the source
chips (`all 500`, `pacman 484`, `snapper 0`, `omarchy 0`, `plugins 1`,
`theme 3`, `config 2`, `agent 2`, `manual 2`, `seldon 6`) wrap into
three rows, the header line "6 events from seldon · newest f…" is
truncated; the operator asked for a wider panel. docs/SPEC-PLUGIN.md §5
(width `Style.space(380)`, WP-011), plugin/Panel.qml (`contentWidth:
panel.fittedContentWidth(Style.space(380))`, tabs share the width),
plugin/components/Tabs.qml (`cellWidth` = equal share), plugin/components/
ChangelogTab.qml (chips, header line), the other tabs, tests/plugin/
panel-view.sh (layout assertions, `PANEL_SHOTS`), work/completed/WP-011
and WP-041 handovers, $OMARCHY_PATH/shell/plugins/ (how first-party
panels size themselves: `Style.space`, scale), memory/omarchy-shell.md.

## Outputs
- Panel width raised to `Style.space(460)` (SPEC-PLUGIN §5 updated; the
  overlay is unaffected) — unless the built-in panels use a different
  convention worth following; say so in the handover.
- Tabs: each tab cell at least as wide as its label plus padding
  (`implicitWidth` from the label, equal share only when there is room),
  no clipping at font scale 1.0 and 1.25; keyboard digits unchanged.
- Chips: a `Flow` (or the qs.Ui equivalent) that wraps cleanly with
  consistent gaps; zero-count chips keep their dimmed style.
- Changelog header: the "N events from <source> · newest first/oldest
  first" line elides only the middle part, never the sort word; or wraps
  into two lines when the width is short.
- Every other tab checked for clipped text at 1.0 and 1.25 (Today stats
  row, Work columns, System table, Decisions list, Memory topics); fixes
  where needed, listed in the handover.
- Harness: `panel-view.sh` gains overflow assertions for tab labels and
  the header line at both scales (the text item's `contentWidth` ≤ its
  width); renders in three themes under work/active/WP-039/screenshots/.
- plugin/README.md and SPEC-PLUGIN §5 wording for the new width.

## Acceptance tests
- `just check` exit 0 with the new overflow assertions.
- Renders show no clipped labels at 1.0 and 1.25 scale.
- Live check on the dev host is the operator's (copy into the dev
  install or wait for the next plugin release); the test host live
  check per ORCHESTRATION.md §11 if unlocked.

## Constraints
Tokens only (`Style.space`, `Style.spacing`, no literal pixel sizes);
no shell-thread work; no engine commands added; a guard block is
reported, never worked around.
