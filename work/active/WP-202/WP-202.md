# WP-202 — every desk button has a key path

0.2.1. From the 0.2.0 live test (WP-126b part 2, 2026-10-11) and Fable's
release judgement (`jax-seldon-private/review-0.1.1/handovers/WP-126-release-fable.md`
§2): these buttons need a pointer today, so a keyboard-only user cannot
set up Seldon or change the desk's width from the desk:

- the setup card's steps (Create the logbook, the snapshot grant, the
  engine step);
- the Changelog's *Agent sorts N open changes*;
- Settings › Appearance: the width slider, the presets, the sidebar
  switch;
- the notices' buttons (e.g. *Restart shell* after an update).

Role: Plugin Dev (Opus, medium). Reviewer: Opus, then Fable for the
buttons that write or run a command as the user.

**Do.** Give each a key path in the desk's own idiom, with WP-126c's
proposal row as the pattern: the cursor reaches the control (a row above
or below the list, or a focus ring in a card), Enter (twice where the
action writes or runs a command, SPEC-PLUGIN §5.3) activates it, a
detour disarms (WP-126c round 3). The hint line names the keys; IPC
routes for smoke tests where they fit (navigation only). Then the live
scenarios of the next release can run without a pointer tool.

**Acceptance.** For each button a headless desk-view case reaches and
activates it by key and fails on the old code; the argv is the same as
the click's; KEYBINDINGS.md, SPEC-PLUGIN §5, guides 03/10 en/de; `just
check` green; evidence words in the handover.

**Inputs.** `plugin/sections/Today.qml` (setup card),
`plugin/sections/Changelog.qml`, `plugin/sections/Settings.qml`,
`plugin/components/desk/*` (notices); WP-126c; WP-201;
`packaging/acceptance/v0.2.0.json` limitations a–d.
