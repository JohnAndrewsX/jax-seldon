# WP-044 — GitHub install path: install.sh with checksum verification, uninstall, banner and README wiring

## Goal
A user without the AUR can install, update and remove the engine from the
GitHub release in one documented, verified step; the plugin's "engine
missing" banner and both READMEs offer this path next to the AUR one.
Operator decision 2026-10-02: both forms are offered — the checked
three-step (download, verify, run) as the primary one, the one-liner as a
convenience whose script verifies the checksum itself.

## Inputs
.github/workflows/release.yml (asset names: `seldon-X.Y.Z-x86_64-unknown-linux-musl.tar.gz`
with `seldon`, LICENSE, README, the unit and its README; `SHA256SUMS`;
`jax-seldon-X.Y.Z.tar.gz`), packaging/README.md, engine/systemd/README.md
(install of the unit from the asset), plugin/Model.js
(`INSTALL_ENGINE_COMMAND`, `UPDATE_ENGINE_COMMAND`, the banner texts),
plugin/components/Banner.qml, plugin/README.md (Requirements, Install,
Remove), README.md, docs/SPEC-PLUGIN.md §3 (degraded states and their
fixes), work/completed/WP-041/HANDOVER.md, memory/pitfalls.md.

## Outputs
- `install.sh` at the repository root (POSIX sh or bash, shellcheck
  clean): `install.sh [--version vX.Y.Z] [--prefix ~/.local] [--unit]
  [--uninstall]`; resolves the latest release via the GitHub API when no
  version is given (`curl`, `jq` optional with a `sed` fallback),
  downloads the musl asset and `SHA256SUMS`, verifies with `sha256sum
  -c`, refuses on mismatch, installs `seldon` and the `jax-seldon`
  symlink under `<prefix>/bin`, optionally the user unit under
  `~/.config/systemd/user/` (never enabled), prints `seldon --version`
  and the next step (`seldon init`); `--uninstall` removes exactly what
  it installed and says what stays (logbook, config). Idempotent; a
  re-run with the same version changes nothing. Never uses sudo. Tested
  by `tests/install/install.test.sh` against a local mock of the release
  layout (a directory served via `file://` or a tiny Python http server)
  — in `just check` (`check-install`).
- The release workflow uploads `install.sh` as a fourth asset and the
  README/plugin README point at the tagged URL
  (`https://github.com/JohnAndrewsX/jax-seldon/releases/latest/download/install.sh`).
- Plugin banner "engine missing": the fix stays a constant; the text
  gains the GitHub alternative ("or: see Install in the README") and
  the README's Install section gets the three-step form first, then the
  one-liner `curl -fsSL <url> | bash` with the note that the script
  verifies `SHA256SUMS`. `UPDATE_ENGINE_COMMAND` keeps the AUR form; the
  README explains the GitHub update (`install.sh` again).
- **AUR status note (operator, 2026-10-02):** the AUR package does not
  exist yet (registration on aur.archlinux.org is paused). README.md,
  plugin/README.md and the plugin banner must say so plainly ("AUR
  package: coming soon — use the GitHub install until then") and list the
  GitHub path first for now; the wording is a single constant/sentence so
  it can be flipped when the AUR package is live.
- `docs/user/` is not this WP (WP-045); write the install text once in
  README.md and reference it.
- SPEC-PLUGIN §3 wording for the banner text; TESTING.md row for the
  install test.

## Acceptance tests
- `just check` exit 0 with `check-install`; shellcheck clean in CI.
- A real run on this dev host: `bash install.sh --version v0.1.0
  --prefix /tmp/<scratch>` installs and verifies against the real GitHub
  release; `--uninstall` removes it. (Network is allowed for this test on
  the dev host; the engine itself stays network-free.)
- Mismatched checksum → non-zero exit, nothing installed.

## Constraints
No sudo, no writes outside `--prefix` and `~/.config/systemd/user/`
(only with `--unit`); the engine binary and plugin code are unchanged
except the banner text constant; a guard block is reported, never worked
around.
