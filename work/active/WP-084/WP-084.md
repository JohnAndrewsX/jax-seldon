# WP-084 — Redaction: proxy credentials, JSON passwords, cookie headers

Role: Engine Dev (Opus, high). 0.1.3 wave. Follow-up from the WP-062
review (gaps named there, not yet covered).

## Goal

Recorded command lines and texts no longer carry: curl/wget proxy
credentials (`-U user:pass`, `--proxy-user user:pass`, `--proxy
http://user:pass@host`), passwords inside inline JSON (`"password": "…"`,
`"passwd"`, `"secret"`, `"token"` as JSON keys), and `Cookie:` /
`Set-Cookie:` header values passed on command lines (`-H 'Cookie: …'`,
`--header`, `-b`/`--cookie` for curl).

## Inputs

engine/src/redact.rs (rule table, the key-name threshold of WP-062, lazy
compile), engine/tests/redaction.rs, docs/SPEC-ENGINE.md §7 (the rule
list), work/completed/WP-062/HANDOVER.md (the residuals accepted there:
short `--api-key=abc` values, bare `pass=x`, `PWD=` — these stay out of
scope unless the new rules cover them for free).

## Outputs

- Three rule groups with the existing placeholder style; the credential
  part is replaced, the structure (option, key, header name) stays visible.
- Tests per rule with positive and negative cases (a `Cookie` header with
  an empty value, a JSON key `"password_hint"` that must not match, an
  `-U` that is `useradd -U` and must not match); the idempotency of
  redaction (redacting twice changes nothing) for the new rules.
- SPEC-ENGINE §7 rule list; CHANGELOG line.

## Acceptance

`just check` 0; mutants per rule (rule removed → its test fails).
