# WP-054 — snapper banner: "Check again" runs a capture (issue #2)

Role: Plugin Dev (Opus, high). Source: GitHub issue #2 (operator, laptop
test of 0.1.1).

## Goal

After the user runs the snapper fix, one click clears the "Snapshots not
readable" banner instead of waiting up to 15 minutes for the next
automatic capture.

## Inputs

Issue #2 (`gh issue view 2`), plugin/Model.js (`snapperBanner` ~677,
`bannerFor`, the action vocabulary), plugin/Service.qml (`captureNow`,
`recheck`), plugin/qml Banner component, docs/SPEC-PLUGIN.md §5 (degraded
states table, "each state has a one-click fix"), tests/plugin/
model.test.js and the service-states harness, AGENTS.md §7/§8 (fixed
commands only).

## Outputs

A third action **Check again** on the snapper banner that runs
`captureNow()` (a capture is what updates the collector state in the
index; `recheck` only reloads the index); after **Run in terminal** the
banner shows the hint "When the command has finished, press Check
again"; SPEC-PLUGIN §5 row updated; plugin/README.md states table row
updated (the plugin repository gets it with the next tag); model tests
for the action set and the hint; a service-states harness case
(banner with the three actions, hint after the terminal action);
CHANGELOG `[Unreleased]` Plugin line "Fixes #2".

## Acceptance

`just check` 0 (model tests, harness, qmllint, plugin validate); the
banner's Check again calls the same capture path the pill's "Capture
now" uses (no new command string).
