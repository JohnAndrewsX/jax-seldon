# WP-079 — Snapper access by a read grant (ADR-0026 supersedes ADR-0011)

Role: Engine Dev (Opus, high). Operator decision 2026-10-04. Small, but
it touches engine, plugin and docs; one worker owns all of it.

## Goal

The one-line fix that Seldon prints for a degraded snapper collector grants
read access to the snapshot directory and nothing else. The older opt-in
(`ALLOW_USERS`) is no longer recommended, and a user who still has it set
is told how to revert it.

## Inputs

decisions/ADR-0011-*.md (to be superseded), engine/src/commands/doctor.rs
(`SNAPPER_FIX`, `SNAPPER_FIX_GRANTS`, `check_snapper`),
engine/src/collectors/snapper.rs (`NO_PERMISSIONS`, the info-file read
path of WP-060), engine/src/commands/init.rs (the optional snapper step),
plugin/Model.js (`SNAPPER_FIX_COMMAND`, `SNAPPER_FIX_GRANTS`),
plugin/README.md (States row), docs/SPEC-ENGINE.md §4,
docs/user/{en,de}/06-configuration.md and 10-troubleshooting.md,
engine/tests/{doctor,init,index,idempotency,collectors}.rs,
tests/plugin/model.test.js and the harness cases that show the snapper
banner, DECISIONS.md.

## Outputs

- decisions/ADR-0026-snapper-read-grant.md (accepted, 2026-10-04),
  superseding ADR-0011: the fix is `sudo setfacl -m u:$USER:rx /.snapshots`;
  the engine reads the snapshot info files (WP-060); it never runs the
  command itself; the plugin banner offers *Copy* and *Open terminal* as
  before. ADR-0011 gets `status: superseded` plus a one-line pointer (the
  only edit an ADR may receive). DECISIONS.md rows for both.
- `SNAPPER_FIX` and `SNAPPER_FIX_COMMAND` are the new line; the "what it
  grants" texts say: read access to the snapshot directory listing and the
  snapshot info files, nothing else (no snapshot creation, change or
  deletion). `NO_PERMISSIONS` points at the same fix.
- Revert hint for the old opt-in: when `snapper -c root get-config`
  succeeds (it does only for a listed user) and `ALLOW_USERS` names the
  current user, `seldon doctor` prints an info line with the revert
  `sudo snapper -c root set-config ALLOW_USERS=""` followed by the new
  read-grant line (the ACL that `SYNC_ACL=yes` created goes away with the
  users list, so the grant comes after the revert). Doctor runs
  `get-config` read-only through the existing `list_command` helper
  (`LC_ALL=C`); the stub-based tests cover: listed user, not listed, no
  snapper.
- init's optional snapper step prints the new line and the new grants text.
- SPEC-ENGINE §4 sentences, user guides 06 and 10 in en and de (de pages
  re-stamped in a separate docs(de) commit), plugin/README States row,
  CHANGELOG lines (Engine, Plugin, Docs).
- Tests updated: every test that asserts the old command asserts the new
  one; one test proves the revert hint appears only for a listed user.

## Constraints

Never run `setfacl`, `snapper set-config` or anything under `sudo` on this
host (AGENTS.md §6 red zone). All checks are hermetic with the snapper
stub. Do not edit `doctor.rs` outside the snapper check and the two
constants (WP-081 adds a check elsewhere in that file at the same time).

## Acceptance

`just check` 0; mutants per item in the handover; `grep -rn ALLOW_USERS`
over engine/, plugin/ and docs/ shows only the revert hint, the ADRs and
history.
