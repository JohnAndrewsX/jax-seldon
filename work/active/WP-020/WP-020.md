# WP-020 — Work tab: three-column list, case card, new-case sheet

## Goal
The planning desk in the panel: cases by status, one card per case, and
the four state actions plus "new case" without a terminal.

## Inputs
docs/SPEC-PLUGIN.md §5 (Work row of the tab table), docs/CONTRACT.md
(`plan new --zone z --risk r -- <title>`, `plan start|verify|done|drop <id>`,
`open <caseId> --editor --json`), docs/SPEC-ENGINE.md §3 (plan JSON shapes,
defaults), docs/SPEC-LOGBOOK.md §3 (statuses, zones, risks, WIP),
schema/index.schema.json (`cases.{queued,active,completed}`, `steps`,
`proposedEvents`, `path`), fixtures/index.sample.json (8 cases),
plugin/ (WP-012: Panel, tabs, Service queue, QuickEntry patterns),
tests/plugin/ (harnesses, fake engine), work/completed/WP-{011,012}/HANDOVER.md.

## Outputs
- `plugin/components/WorkTab.qml` (tab id 3, digit `3`): three columns
  Queued · Active (incl. verification) · Completed (last 50); the WIP limit
  shown ("2 / 3 active"); cursor and Enter per the WP-011 keyboard rules.
- `components/CaseCard.qml`: id, title, status, zone/risk, area, steps
  done/total, `proposedEvents` badge, created/started/closed, actions by
  status: queued → Start; active → Verify, Drop; verification → Done,
  Drop; completed → Open; every action is a fixed argv list through the
  service queue with the id validated by the schema regex; the result
  line shows the engine's message; index refresh via FileView.
- `components/NewCaseSheet.qml` (`+` key or button): title (free text
  after `--`), zone and risk pickers (defaults yellow/R1), optional area
  slug (validated `^[a-z0-9-]+$`), priority; Enter runs `plan new`; the
  field keeps its text on a refused call (WP-012 pattern).
- `plugin/Model.js`: `workColumns`, `caseActions`, `planArgs`,
  `planResult` helpers; `validateArgs` already covers the forms.
- Tests: node tests for the helpers; `service-states.sh` scenarios with
  exact argv for `plan new` (title `--help`, quotes), each state action,
  a refused transition (engine exit 1 → message shown, nothing else);
  `panel-view.sh` scenarios for the three columns on the sample, the
  card, the sheet, keyboard flow, FileView refresh after a fake `plan start`
  moves a case.
- `plugin/README.md`, `docs/TESTING.md` updated; screenshots of the Work
  tab in three themes on the test host.

## Acceptance tests
- `just check` exit 0 (qmllint zero warnings, tokens, both harnesses).
- On the sample: Queued 3, Active 3 (2 active + 1 verification), Completed
  2; the `proposedEvents` badge on the case that has them; WIP text.
- create/start/verify/done from the panel against the fake engine with the
  exact argv; a refused `done` from active shows the engine's message.
- Runtime smoke on the test host with the real engine: new case → start →
  verify → done from the panel; files move folders; the index refreshes.
- Theme sweep (three themes incl. one light) with screenshots.

## Constraints
As WP-012: fixed argument lists, free text after `--`, ids validated,
never block the shell thread, qs.Ui + tokens only, dev host copy-only,
test host is the runtime target (restore it), a guard block is reported,
never worked around.
