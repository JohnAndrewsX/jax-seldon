# WP-031 — Charts: Heatmap, Series, DriftBars, RiskDonut, Timeline (+ The Plan)

## Goal
The Prime Radiant slots show real charts from the index's `series`,
in theme colours, with hover details, and the overlay still opens without
frame drops.

## Inputs
docs/SPEC-PLUGIN.md §6 §7, schema/index.schema.json (`series.heatmap`,
`series.packages`, `series.drift`, `series.risk`, `series.timeline`,
`cases`), fixtures/index.sample.json and index-variants/,
plugin/Overlay.qml + components/overlay/ (WP-030: slots, `periodData`,
`placeholder` flag, `call view`), plugin/Model.js (period helpers),
tests/plugin/overlay-view.sh, work/completed/WP-030/HANDOVER.md
(decisions: "All" period, The Plan row, risk not windowed), memory/omarchy-shell.md.

## Outputs
- `plugin/components/overlay/{Heatmap,Series,DriftBars,RiskDonut,Timeline}.qml`
  drawn with `Canvas` or `Shape` from the slot's `periodData` only (no
  work on open: the data is precomputed in the service; drawing happens
  once per data/size change; no per-frame layouts):
  - Heatmap: 366-day calendar grid (weeks × weekdays), colour by event
    count with 5 steps derived from the theme accent via `Util.alpha`;
    hover: day, counts by source.
  - Series: explicit/total package counts as two lines over the period;
    hover: date, counts.
  - DriftBars: opened vs resolved per ISO week; hover: week, counts.
  - RiskDonut: R0–R3 shares with a centre label; hover: risk, count.
  - Timeline: releases, snapshots, case spans (open ones run to today),
    crises on one axis; hover: the entry's label and date.
  - The Plan (sixth slot, from SPEC §6): active cases with steps
    done/total and agent, as a compact list (reuse CaseCard pieces).
- Each chart has an empty state ("no data in this period"), an accessible
  text summary (`call view` reports each chart's summary numbers), and
  resizes with the grid modes from WP-030.
- `plugin/Model.js`: pure chart-data helpers (bins, scales, colour steps)
  with node tests; no QML-side aggregation beyond geometry.
- Tests: `overlay-view.sh` scenarios asserting each chart's summary
  numbers per period on the sample, the empty states on the
  not-initialised variant, hover read-outs via `call view`, and a frame
  budget: the first frame after `open` must not run chart aggregation
  (assert via a counter exposed in the harness) — plus a profile note in
  the handover (`quickshell` frame timing or `QSG_RENDER_TIMING=1` on an
  unlocked host).
- Renders in three themes at 1920×1080 and 2560×1440 under
  work/active/WP-031/screenshots/; README and TESTING updated.

## Acceptance tests
- `just check` exit 0.
- Each chart renders from the fixture series; hover details work in the
  harness (`call view` carries the hovered item after a synthetic hover,
  or the hover text is exposed as a property the harness reads).
- Theme colours only (token check passes; no literal colours).
- No frame drops on open: documented profile on the test host when
  unlocked; in the harness, no aggregation on the first frame.

## Constraints
As WP-030: tokens only, no synchronous heavy work on open, fixed argument
lists (no engine commands), dev host copy-only, a guard block is reported,
never worked around, lock status before keys/screenshots.
