# WP-009 — Hooks

## Goal
A Claude Code session inside the logbook records every mutating command it
runs, gets context at start, and leaves a journal stub at the end. Other
agents get the generic form.

## Inputs
docs/SPEC-ENGINE.md §8, docs/CONCEPT.md (Agents and the logbook),
fixtures/hooks/claude-code-*.json (WP-002), the Claude Code hooks
documentation (PostToolUse / SessionStart / Stop JSON shapes — read the
current docs, do not guess), memory/host.md.

## Outputs
- `seldon hook claude-code` — stdin PostToolUse JSON → classify `tool_input.command` (pacman/yay/paru, `omarchy pkg|plugin|theme|update|install`, `systemctl enable|disable|start|stop|mask`, `cp|mv|install|tee|sed -i` into watched paths, `git` inside `~/.config` or the logbook) → `agent/command` event with `actor: agent:claude-code`, `case` from `.seldon/active-case`, redacted command line. Silent stdout, exit 0 always, < 5 ms.
- `seldon hook generic` — stdin `{"command","actor","cwd"}`.
- `seldon hook session-start` — prints the context block (STATUS summary, active case with steps, last 5 journal lines, `memory/lessons.md` headings).
- `seldon hook session-stop` — journal stub `## HH:MM · agent:NAME · CASE` ("session ended; N events recorded"), `capture --all`, `status`, commit.
- `seldon hook install claude-code [--settings PATH]` — merges the three hooks into `<logbook>/.claude/settings.json` without clobbering existing hooks; idempotent; prints what it did.

## Orchestrator notes (2026-10-01)
- ADR-0017 is normative: the hook writes the `command` event on
  **PreToolUse** with the start time (`ts`), redacted `meta.command`,
  actor `agent:claude-code`, case from `.seldon/active-case`, optional
  `meta.toolUseId` in `extra`; PostToolUse writes nothing for a command
  already recorded; denied/failed commands are still recorded (ADR-0012 §6
  keeps them out of drift). Query sub-commands (`pacman -Ss|-Si|-Sl|-Sg|-Sp|-Sw|-Sc`,
  `-Q*`, `-T`) are never mutating (ADR-0017 §5).
- ADR-0014 §4: `Edit`, `Write`, `MultiEdit` whose `file_path` lies under
  `watchPaths` → `source: agent, kind: command, subject: <tool lowercased>`,
  `meta.command "<Tool> <path>"`, path written with `~`; a path matching
  `[redaction] skipPaths` is recorded redacted — reuse
  `collectors::config::SkipPaths`.
- Move the command parser (`command_intent`, `parse_command`,
  `is_plain_full_upgrade`, `OMARCHY_UPDATE_NAMES`, `is_mutating`) out of
  `collectors/pacman.rs` into a neutral `engine/src/pkgcmd.rs`; the pacman
  collector and (later) WP-008 import it. The hook must not import
  `collectors::pacman`.
- **One shared attribution pass before `append`** (ADR-0014 §1 + ADR-0017
  §2–§4; decision from the WP-005 review): a neutral
  `engine/src/attribution.rs` called once by `capture` over all collector
  events of the run (pacman keeps its transaction-level logic; the pass
  owns the window rule for config/theme/plugins). Proof per source:
  pacman — package name or full upgrade; config — the path appears as an
  argv word of the command (absolute, `~` or home-relative) or as an
  Edit/Write hook event with that path; theme — `omarchy theme set <slug>`
  / `omarchy-theme-set <slug>`; plugins — `omarchy plugin add|remove|enable|
  disable|update <id or URL ending in the id>`. The fixture's 10-01
  `bindings.conf` change (agent:claude-code, C-2026-004 via `sed -i`) is the
  test.
- `seldon event` default actor becomes `system` (not `human`); `--actor`
  stays. For `theme-set` fill `meta.from` from the theme cursor, else the
  latest `theme-set` in the ledger, else omit (WP-005 decision 7).
- `session-stop`: journal stub + `capture --all` + autocommit; call the
  index/status rebuild only if `commands::status` exists on your branch
  (WP-007 lands it in parallel) — otherwise leave one clearly marked call
  site and say so in the handover.
- `hook install claude-code` writes PreToolUse (Bash, Edit, Write,
  MultiEdit), SessionStart, Stop entries into `<logbook>/.claude/settings.json`,
  merging with existing hooks; test with `fixtures/hooks/` and a settings
  file that already has hooks.
- Module ownership: `commands/hook.rs`, `pkgcmd.rs`, `attribution.rs`,
  `engine/src/commands/event.rs` (actor default only), `engine/hooks/`
  additions, `engine/tests/{hooks,attribution}.rs`. WP-007 owns `index/`,
  `commands/{index,status}.rs`; WP-015 owns `schema/`, `fixtures/`.
- Tests through `common::Env` only; never the real XDG dirs; `< 5 ms` is
  measured with the release profile in a `cargo bench`-style check or a
  timed test with a generous bound in debug.

## Acceptance tests
- Hook JSON fixtures classify correctly (mutating → event, non-mutating → nothing, secret-bearing → redacted).
- Always exit 0, even on malformed stdin or a missing logbook.
- `session-start` prints the context block (golden).
- `hook install` writes a valid `.claude/settings.json` fragment and leaves pre-existing hooks intact (fixture with existing hooks).

## Constraints
Never record stdin/stdout of commands, only the command line. The hook
must not block an agent: any failure is logged to stderr and swallowed.
