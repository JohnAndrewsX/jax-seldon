# WP-085 — The panel shows capture warnings

Role: Plugin Dev (Opus, high). 0.1.3 wave. Follow-up from WP-081: the
engine's `capture --json` carries `warnings` (today: the state reset);
the panel discards them.

## Goal

A warning returned by a capture the plugin started (*Capture now*, *Check
again*, the `c` key, the bar's right click, the start-up capture) is
visible in the panel until the next capture without that warning, with the
restore hint the engine gives.

## Inputs

plugin/Service.qml (`captureNow`, `captureResult`), plugin/Model.js
(`captureResult`, banner model, `callWarning`), plugin/components (the
banner/notice components used for the snapper and engine banners),
docs/SPEC-PLUGIN.md §3/§5, plugin/README.md (States table),
tests/plugin/fake-seldon (add a knob for `warnings`), tests/plugin/
service-states.sh and panel-view.sh, docs/user/{en,de}/10-troubleshooting.md
(states table), work/completed/WP-081/HANDOVER.md (warning text), WP-068
(callWarning, busy, retry) and WP-078 handovers.

## Outputs

- `Model.captureResult` keeps `warnings` (list of strings); a non-empty
  list becomes a neutral-tone notice in the panel ("Capture warned: …",
  first line of each warning, full text on hover or in the Changelog tab
  as the engine wrote it) with one action *Open guide* only if a fixed
  URL/page exists for it, otherwise no action; the notice clears when a
  later capture returns no warnings. Style tokens only, no shell strings
  built from the text (AGENTS.md §8).
- Harness: fake-seldon knob `FAKE_SELDON_CAPTURE_WARNINGS`; service-states
  case: a capture with a warning shows the notice, the next clean capture
  clears it; panel-view case for the rendering; a mutant per claim.
- SPEC-PLUGIN §3 sentence; README States row; user guide 10 en+de row (de
  re-stamped in a separate docs(de) commit); CHANGELOG Plugin line.

## Acceptance

`just check` 0; `omarchy plugin validate plugin/` and qmllint on every
commit; mutants in the handover.
