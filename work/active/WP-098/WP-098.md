# WP-098 — The test host follows main

Role: Engine Dev (Opus, high). 0.1.4 wave, independent (scripts/,
justfile, engine/src/lib.rs + main.rs version only, docs). Operator
request 2026-10-05: the test host always runs the current main build so
the operator can follow development live; productive machines run only
releases (install.sh + `omarchy plugin update`), unchanged.

## Goal

After every green main check the orchestrator runs one command that puts
the main build of engine and plugin on the test host, restarts the shell
when the plugin changed, and proves it works. The build says what it is.

## Inputs

scripts/guard.sh and the git-ignored scripts/guard-hosts.local (the test
host list; hostnames never in the repository), justfile (`build-release`,
`e2e`), docs/TESTING.md (live test host procedures, lock checks),
docs/ORCHESTRATION.md §11 (lock-screen rule), memory/local.md,
plugin/Model.js `versionCore` (accepts `+build` metadata),
schema/index.schema.json (`engineVersion` is a free string),
engine/src/lib.rs `VERSION`, WP-090 (shell restart after a plugin
change; Quickshell keeps compiled code).

## Outputs

- **Dev version marker:** a build from main reports
  `0.1.3+main.<short sha>` (`seldon --version`, `--json`, the index's
  `engineVersion`) when built with `SELDON_BUILD=main.<sha>`; release
  builds stay plain. Tests: both forms; the plugin still parses it
  (`versionBelow`).
- **`scripts/deploy-test-host.sh`** + `just deploy-test-host`:
  - target host only from `SELDON_TEST_HOST`, and only if it is listed in
    scripts/guard-hosts.local — anything else is refused (exit 1), so a
    productive machine can never be a target;
  - refuses unless `main` is clean and HEAD equals origin/main, and the
    last main check log says exit 0 (path as argument);
  - builds the static release binary with the marker, copies it to the
    host's `~/.local/bin/seldon` (previous kept as `seldon.prev`);
  - syncs `plugin/` into the host's plugin dir (the release git clone is
    moved aside once to a dated backup; afterwards the dir is a plain
    copy with a `.seldon-dev-build` file naming the commit);
  - restarts the shell only when the plugin files changed and
    `omarchy-shell lock status` reports unlocked and not secure;
    otherwise prints "restart pending";
  - smoke: `seldon --version`, `seldon doctor --json`, `seldon capture
    --json` on the host's test logbook, `jax.seldon.service status`
    (status ok, engine version = the marker, no restart notice);
  - writes one JSON line per deploy to a log on the host and prints a
    summary; `--dry-run` shows what it would do.
- **Back to a release on the test host:** `--release vX.Y.Z` installs that
  release with install.sh and the plugin from the release repository, and
  warns that state written by a newer build may not load (move
  `~/.local/state/seldon` aside first; WP-091's downgrade note).
- Docs: TESTING.md section "Test host follows main", ORCHESTRATION.md §11
  one line (deploy after each green main check + push), DEVELOPMENT.md.

## Acceptance

`just check` 0; the script's refusals tested hermetically (unknown host,
dirty tree, failed check log, locked shell) with stubs for ssh; one real
deploy to the test host done by the orchestrator after merge. Review:
stage 1 Opus (install path to a real machine).
