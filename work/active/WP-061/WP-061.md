# WP-061 — git: autocommit stays in the logbook repository, refuses a detached HEAD, reports failures; file-scoped import undo

Role: Engine Dev (Opus, high). Size: M. Wave: 2. Depends: WP-060
(`commands/doctor.rs`, `tests/doctor.rs`).
Findings: F-504, F-452, F-503 (engine and doctor part; the index/plugin
part waits for an operator decision), F-142, F-541 (only the
`.git/index.lock` check).

## Goal

The autocommit only ever writes to the logbook's own repository, on a
branch, and a commit that keeps failing is visible.

- **F-504** — `logbook/git.rs` builds every git command with the
  repository variables removed (`GIT_DIR`, `GIT_WORK_TREE`,
  `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`,
  `GIT_COMMON_DIR`, `GIT_NAMESPACE`, `GIT_CEILING_DIRECTORIES`) or with
  explicit `--git-dir`/`--work-tree`. Build the `Command` in git.rs and run
  it through the existing `sys::run_command`; do **not** edit `sys.rs`
  (WP-064 owns it in this wave).
- **F-452** — when `git symbolic-ref -q HEAD` fails, the autocommit is
  skipped with "HEAD is detached" (stderr and `--json` `git`), doctor
  `check_git` degraded with the fix.
- **F-503 (engine)** — a failed autocommit prints one warning line on
  stderr and carries the error in `--json` `git`; exit code stays 0
  (the data was written). `doctor` checks for a stale `.git/index.lock`
  (this also covers that part of F-541), a detached HEAD and a commit
  dry run, each with a fix line.
- **F-142** — `import --apply` commits pending changes first (or refuses
  a dirty tree — choose and document) before its first write, and the
  undo hint names only the files the import wrote.
