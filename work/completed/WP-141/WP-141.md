# WP-141 — pacnew and pacsave in the record

Ships in 0.2.0 on the integration branch `next` (branch from and merge into `next`). Operator decision 2026-10-07 after the study of the first predecessor "Omar" (private: refs/omarchy-agent-predecessor-STUDY.md in the orchestrator's notes; the study and the copy never go into this repository). (P1)

Role: Engine Dev (Opus, high). Small.

**Goal.** Seldon names the most common cause of breakage after an Arch
update: a configuration file pacman left as `.pacnew` (the new default
was not applied) or `.pacsave` (the user's file was moved aside).

**How.**
- The pacman collector already reads `/var/log/pacman.log`. pacman
  writes `warning: /etc/x installed as /etc/x.pacnew` and
  `… saved as … .pacsave` there.
- Each occurrence becomes an event:
  - kind and subject as SPEC conventions fit;
  - the path;
  - the transaction's `txId`;
  - **attention** under ADR-0028, crisis when the path is under an
    `alwaysRedPaths`-equivalent system file (mkinitcpio, limine,
    systemd, pam).
- No `/etc` read. Whether the `.pacnew` was merged later is not
  known; say so in SPEC.
- The desk's Changelog shows it with the hint "merge with `pacdiff`".
  This is a text hint, never a command run.

**Acceptance.**
- Fixture lines for both forms.
- Idempotent.
- The class test.
- `just check` is green.
