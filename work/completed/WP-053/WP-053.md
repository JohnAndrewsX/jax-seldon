# WP-053 — snapper messages are locale-independent (issue #1)

Role: Engine Dev (Opus, high). Source: GitHub issue #1 (operator, laptop
test of 0.1.1 with `LANG=de_DE.UTF-8`).

## Goal

Seldon recognises snapper's permission error in every locale: the
collector stores `NO_PERMISSIONS`, `doctor` and `init` print the fix
line, exactly as `docs/user/*/01-getting-started.md` step 3 shows.

## Inputs

Issue #1 (`gh issue view 1`), engine/src/collectors/snapper.rs (~81),
engine/src/commands/doctor.rs (~322), engine/src/commands/init.rs (the
snapper line of the wizard), every other place that spawns `snapper`
(grep `Command::new("snapper")` and the shim in tests), docs/TESTING.md
(snapper shim), ADR-0011, SPEC-ENGINE §4 (collectors).

## Outputs

Every snapper invocation runs with `LC_ALL=C` (one helper that builds
the command, used everywhere); a test feeds a localized stderr through
the shim with `LANG=de_DE.UTF-8` set in the environment and asserts
`NO_PERMISSIONS`, the doctor fix line and the init hint; SPEC-ENGINE §4
one sentence ("snapper is run with `LC_ALL=C`; its messages are matched
in English"); CHANGELOG `[Unreleased]` Engine line "Fixes #1".

## Acceptance

`just check` 0; the new test fails without the `LC_ALL=C` change
(mutant shown in the handover); `--jsonout` paths unchanged.
