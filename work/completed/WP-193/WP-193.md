# WP-193 — Release highlights: at most ten points per version

0.2.0, **before WP-126**. Origin: study of Tom Ballard's Omarchy work
(2026-10-09, `jax-seldon-private/study-tcballard/`), operator decision E68.
Ideas only, no code taken.

**Placement.** A small WP of its own, not folded into WP-126: the
mechanism (CHANGELOG convention, `packaging/release-notes.sh`, its test,
the rule in VERSIONING.md) can merge now and in parallel; WP-126 then only
writes the 0.2.0 points, and WP-188 the 0.3.0 points (amendments there).

Role: Docs Dev / Scaffold (Opus). Small. Reviewer: Opus (approves alone:
text tooling; `release.yml` is not changed). No ADR.

**Problem.** The release body is the whole CHANGELOG section
(`packaging/release-notes.sh`, WP-048). For 0.1.4 that is about 6 000
words (`CHANGELOG.md:434-1026`); a user cannot see what changes for them.

**Goal.** Each release from 0.2.0 opens with at most ten points "what
changes for you", in user words; the full section stays one click away.
One source: the CHANGELOG.

**Do.**
- CHANGELOG convention (header note of `CHANGELOG.md` and
  `docs/VERSIONING.md`): every version section from 0.2.0 opens with
  `### Highlights` (after the standing paragraph for plugin 0.1.0 users,
  VERSIONING.md:87-91, while it applies), 1–10 bullets, one line each,
  user words, no WP numbers; **Breaking** items appear there too. `[Unreleased]` gets an
  empty `### Highlights` now so WP-126 fills it.
- `packaging/release-notes.sh X.Y.Z`: for versions ≥ 0.2.0 prints the
  release body as the standing paragraph (if present), then the
  Highlights, then one link to the full section in
  `CHANGELOG.md` at the tag. Exit 1 when a ≥ 0.2.0 section has no
  Highlights, more than ten bullets, or a bullet over one line. Older
  versions print as today.
- `tests/release/release-notes.test.sh`: cases for the new body, a missing
  Highlights block, eleven bullets, a wrapped bullet, a 0.1.x section
  unchanged.
- `docs/VERSIONING.md`: the rule, an example, who writes the points (the
  release WP).

**Acceptance.** `release-notes.test.sh` green with each failing case
proved (fixture, CI); `release-notes.sh 0.1.4` prints exactly what it
prints today (fixture); docs-check green.

**Inputs.** `CHANGELOG.md`; `packaging/release-notes.sh`;
`tests/release/release-notes.test.sh`; `docs/VERSIONING.md`;
`.github/workflows/release.yml` (where the body is used, read only);
WP-126, WP-188; the study: REPORT.md §3 item 5, FINDINGS.md §5.2 item 8,
HANDOVER.md (WP-126 amendment), debate/judgement.md verdict 7; Tom's
pattern for reference only: `build-omarchy-plugins/CHANGELOG.md:5-16`.
