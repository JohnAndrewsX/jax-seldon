# WP-080 — Release provenance: GitHub artifact attestations, verified by install.sh

Role: Packaging Dev (Opus, high). Operator decision 2026-10-04: GitHub
Attestations now, minisign later if needed; install.sh never refuses only
because the verification tool is missing.

## Goal

Every release asset carries a build-provenance attestation created by the
release workflow, and install.sh verifies it when `gh` is available.

## Inputs

.github/workflows/release.yml (pins by commit SHA with a version comment,
WP-072 policy; `permissions` blocks per job), install.sh (download, SHA256SUMS
check, `need`, `fail`, flags), tests/install/install.test.sh (hermetic
checks with stubs), README.md and plugin/README.md install sections,
docs/user/{en,de}/01-install*.md and 11-update-and-uninstall.md,
SECURITY.md, packaging/README.md, docs/VERSIONING.md, CHANGELOG.md.

## Outputs

- release.yml: `actions/attest-build-provenance` (pinned by commit SHA, version
  in a comment, like the other actions) attests the musl tarball, SHA256SUMS,
  install.sh and the source tarball; the job gets `id-token: write` and
  `attestations: write` (least privilege; `contents` stays as it is). Decide
  and document whether the step also runs in dry runs (`workflow_dispatch`):
  prefer running it so the step is exercised, unless an attestation for a
  dry-run artifact has a downside you can name.
- install.sh: after the checksum check, if `gh` is on PATH, run
  `gh attestation verify <tarball> --repo "$REPO"`; a failed verification
  refuses the install ("nothing installed"); a missing `gh` prints one notice
  line that only the checksum was checked. New flag `--require-verified`:
  fail when `gh` is missing or verification fails. `--help` and the header
  comment describe it. Keep the script POSIX-sh compatible as it is today.
- tests/install/install.test.sh: stubs for `gh` (verify ok, verify fails,
  gh absent) × (`--require-verified` on/off); the existing checks stay green.
- Docs: README install sections (one sentence + the flag), user guides 01
  and 11 en+de (de re-stamped in a separate docs(de) commit), SECURITY.md
  ("verifying a release"), packaging/README, VERSIONING release checklist
  line, CHANGELOG (Packaging and docs).
- A release dry run on the branch (`gh workflow run release.yml --ref
  <branch>`, then `gh run watch`) must be green; cite the run id in the
  handover and whether the attest step ran.

## Constraints

No secrets, no new third-party actions besides `actions/attest-build-provenance`.
Do not touch PKGBUILD or the AUR job.

## Acceptance

`just check` 0 (includes the install tests and shellcheck); dry run green;
mutants: a tampered tarball with a stubbed failing `gh` is refused, and
`--require-verified` without `gh` exits non-zero.
