# WP-130 — Guard: stop false positives on text, keep every real block

Role: Engine Dev (Opus, high). Operator decision 2026-10-06: the
orchestrator may improve `scripts/guard.sh`; every rule is a row in the
test table, which the operator sees before the merge.

## Goal

The PreToolUse guard (`scripts/guard.sh`, tested by
`scripts/guard-test.sh`) blocks what AGENTS.md §6 forbids on the dev host
— and nothing else. Today it matches words in the whole command text, so
it blocks harmless commands several times a day.

## Inputs

scripts/guard.sh, scripts/guard-test.sh, scripts/guard-hosts.local
(git-ignored, read only), AGENTS.md §6, `.claude/settings*.json` (how the
hook is wired). False positives seen (2026-10-03 … 2026-10-06), each must
become an "allow" row:
- read-only package queries: `pacman -Q`, `-Qq`, `-Qi`, `-Ql`, `-Sp`
  (print only), `pacman -Sp --print-format …`;
- the words only as text: in `echo`/`printf` arguments, in a heredoc body
  written to a file (`cat > file <<'EOF' … sudo … EOF`), in `grep`/`rg`
  patterns (`grep -n 'pacman -U' …`), in `git commit -m` messages, in a
  `herdr agent prompt "…"` text, in `jq` filters;
- Omarchy command names in text (`omarchy update`, `omarchy plugin add`)
  inside the same contexts; `omarchy … --help` and `omarchy commands`;
- a `mkdir "$HOME/.config/…"` under a scratch HOME (`HOME=/tmp/… ` or a
  test dir), `sudo setfacl` inside a test file's text;
- a read-only `grep` over `$OMARCHY_PATH/migrations` or `install.sh`.
Real blocks that must stay (each a "block" row): `sudo …`, `pkexec …`,
`pacman -S/-U/-R/-Syu …`, `yay`/`paru` installs, `systemctl` (system and
`--user` enable/start/stop), `omarchy update`/`omarchy pkg add`/`omarchy
plugin add|remove` *as commands*, writes under the real `~/.config`
outside `~/.config/omarchy/plugins/jax.seldon`, `rm -rf` of the real
`~/Seldon` or `~/.local/state/seldon`, and the existing ssh/test-host
rules (keep them exactly).

## Outputs

A guard that decides on the *command position* of each pipeline/list
element (after `;`, `&&`, `||`, `|`, `$(…)`, backticks, `sudo`-like
wrappers, `env VAR=…`, `bash -c '…'`/`sh -c` bodies parsed recursively),
not on words anywhere in the text; quoted strings and heredoc bodies are
data unless they are the argument of `bash -c`/`sh -c`/`eval`. Fail
closed: a command it cannot parse is blocked with a message naming why.
The test table grows by every row above (allow and block) and keeps all
existing rows. A short comment block at the top of guard.sh states the
rule. Fix the stale comment that cites "HERDR-SETUP.md §5".

## Acceptance

`bash scripts/guard-test.sh` all rows green; `just check` 0; a mutant
list (e.g. drop the `bash -c` recursion → a row fails). Review: stage 1
Opus, stage 2 Fable (security). **Merge only after the operator has seen
the test table** (the orchestrator shows it).
