# WP-082 — Snapper collector: one date per snapshot across list and info files

Role: Engine Dev (Opus, high). 0.1.3 wave. Follow-up from WP-073/079.

## Goal

A snapshot keeps one date whether the collector read it from `snapper list`
(local time) or from the info files (UTC), including a snapshot made in the
repeated hour when summer time ends. Switching between the two read paths
(the read grant of ADR-0026 makes the info-file path the normal one) never
records a false `snapshot-delete` plus `snapshot`.

## Inputs

engine/src/collectors/snapper.rs (list path, info-file path, the cursor's
per-snapshot dates, the comment near line 396 about the DST gap),
docs/SPEC-ENGINE.md §4 (the "Known limit … to be fixed later" sentences),
engine/tests/collectors.rs, fixtures (the snapper stub and info-file
fixtures), work/completed/WP-073/HANDOVER.md and WP-060/HANDOVER.md,
schema/external/snapper-list.schema.json (description) and
fixtures/README.md:205 (both carry a "not verified on the dev host"
history sentence).

## Outputs

- One canonical instant per snapshot: decide and document the rule (for
  example: the info file's UTC time is canonical when both are available;
  a list time that is ambiguous because of a DST fold is resolved against
  the info file, or against the snapshot's number order when no info file
  can be read), so that a switch of read path never changes a snapshot's
  recorded date. Cursor entries written by earlier versions are migrated
  without events (as WP-073 did for missing dates).
- Tests: a snapshot in the repeated hour read first from the list then
  from the info files (and the other way round) produces no event; a real
  deletion and reuse of a number still does; the DST-gap case of the
  existing comment stays covered.
- SPEC-ENGINE §4: replace the "Known limit … to be fixed later" sentences
  with the rule.
- History sentences: verify the `snapper --jsonout list` shape read-only on
  this host (reading is allowed; never `set-config`, never `sudo`) against
  schema/external/snapper-list.schema.json; if it matches, drop the "not
  verified on the dev host" sentences in the schema description and
  fixtures/README.md:205 and say so in the handover; if it does not match,
  report the difference and change nothing there.
- CHANGELOG line.

## Acceptance

`just check` 0; mutants per claim in the handover (rule removed → the
switch test records a false pair).
