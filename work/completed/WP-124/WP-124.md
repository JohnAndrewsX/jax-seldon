# WP-124 — Bulk triage: `agent ask`, `drift propose`, `drift apply`, the proposal in the desk (ADR-0036)

Ships in 0.2.0 on the integration branch `next` (branch from and merge into `next`). Plan: decisions/ADR-0034-desk.md and the 0.2.0 plan (orchestrator's private notes); the prototype is the spec of look and behaviour (path in the brief).


Role: Engine Dev (124a) then Engine + Plugin Dev (124b) — one agent, two
stages, or two agents in sequence (Opus, high). 124a after WP-120; 124b
after WP-122 and 124a. Supersedes WP-095.

**Goal.** One click in the Changelog sends the default agent to sort the
open changes; the agent comes back with a proposal built on evidence; one
click applies it; crises stay with the user, item by item.

**Inputs.** ADR-0034 §6; ADR-0028 §3; ADR-0027 §2, §5; ADR-0030;
WP-095 (its scope and the ADR it asked for), WP-101 (`agent start --new`
path, prompt rules, `SELDON_ACTOR`/`SELDON_ATTENDED`), WP-094 skill
(`drift.md`, `case.md`); `engine/src/commands/{agent,drift}.rs`,
`engine/src/reconcile.rs`; SPEC-ENGINE §3, §5, §8; CONTRACT.md fixed
argv; `fixtures/index.sample.json` v2 `triage`; AGENTS.md §8.

**Outputs (124a, engine).**
- ADR-0036 "Agent prompts carry identifiers, never logbook text;
  proposals are evidence or nothing" (accepted on the 2026-10-06 word,
  §6).
- `seldon agent ask triage|drift <eventId>|case <caseId> [--launcher]
  --json`: validated ids, fixed prompt templates that name the skill
  file, same launcher checks and env as `agent start`, refusal without a
  default agent names the fix; the template-command test covers them.
- `seldon drift propose --json` (stdin JSON; `--file` for tests): schema
  of items, id validation, evidence resolution (journal time, event id,
  snapshot number, case id, case plan line), refusal of an item without
  resolvable evidence (exit 1, names the item), proposal file under the
  state dir, `triage` in the index; a new proposal replaces an unapplied
  one and says so.
- `seldon drift apply <proposalId> [--item <eventId>]… --json`: actor
  human unless `--actor`; link/explain through the existing paths with
  `resolutionDetail` "proposed by agent:<name> — <evidence>"; crises
  only by `--item`; idempotent; `applied` recorded; `--json` lists done,
  skipped, refused.
- Skill `triage.md` (en): read ledger, cases, journal; what counts as
  evidence; never explain a crisis away; write the proposal, stop.
- SPEC-ENGINE §3 and §5, CONTRACT.md argv table (`agent ask …`, `drift
  apply …` — the plugin never runs `propose`), guide 04 en/de.

**Outputs (124b, desk).**
- Changelog list head: "Agent sorts N open changes" (fixed argv `agent
  ask triage --json`, busy state, refusal shown); the proposal detail
  (Apply proposals / Discard sticky bar, items with evidence, crisis
  block with one click each → `drift apply <id> --item <eventId>`);
  after apply the result line and the index refresh through the FileView.
- Event and case details: **Ask agent** → `agent ask drift|case <id>`.
- `Model.js`: `triageView`, `askArgs`, `applyArgs`; harness scenarios
  (button only when N > 0 and an agent exists; argv exactness; a
  proposal with a crisis item never applies it via Apply; idempotent
  second apply reports skipped).

**Acceptance.** `just check` 0; engine tests: id validation, prompt holds
no logbook text (mutant), evidence refusal, idempotent apply, crisis
guard, `--json` shapes, exit codes; harness rows done; **live check on
the test host**: a lived-in logbook with ≥ 5 open attention items and 1
crisis → one click, the agent returns a proposal within the session, one
click applies, the crisis is still open, the ledger shows the evidence
lines; count clicks and prompts. Review: stage 1 Opus, stage 2 Fable
(prompt injection through evidence text, unsandboxed plugin, apply
semantics).
