# WP-212 — the real-home guard knows every file the live engine writes

0.2.x, tests only, urgent: it blocks every full check on a host that runs
the released 0.2.0. From the orchestrator's gates n020r/n020s and dev-194's
checks (2026-10-12): since the dev host runs 0.2.0, its periodic capture
writes `~/.local/state/seldon/recent-config.json` about every 15 minutes.
`tests/plugin/real-home-guard.sh` allows only `index.json`, `lock`,
`cursors.json` and `manifest.json` (`real_engine_files`), so a capture
during a run reads as a leak ("recent-config.json changed") and fails
desk-view or service-states.

Role: Plugin Dev (Opus, medium). Reviewer: Opus.

**Do.** Allow every file the engine itself writes into its state directory
during routine work (`recent-config.json` from `collectors/recent.rs`,
`autocommit.json`, `owned.json`, and any other; read `engine/src` for the
full list and say which are routine), ideally derived from or checked
against the engine's constants so the list cannot drift again (a test that
fails when the engine names a state file the guard does not know). Paths
that are never the engine's still fail. No change to the guard's other
rules (config.toml, logbook, machine, runtime dir).

**Acceptance.** `tests/plugin/real-home-guard.test.sh` rows for each
allowed file and for a non-engine file; the drift test fails when a new
state file is added to the engine without the guard; a full check on the
dev host passes across a live 0.2.0 capture; `just check` green; evidence
words in the handover.

**Inputs.** `tests/plugin/real-home-guard.sh`,
`tests/plugin/real-home-guard.test.sh`; `engine/src/collectors/recent.rs`,
`engine/src/index/autocommit.rs`, `engine/src/collectors/config.rs`;
private `gates/gate-n020r.log`, `gates/check-dev-194-r5.log`.
