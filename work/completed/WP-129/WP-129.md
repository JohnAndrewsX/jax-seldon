# WP-129 — The hook records an agent's privileged commands

Ships in 0.2.0 on the integration branch `next`: branch from `next`, merge
into `next`.
- Operator decision 2026-10-07 (E14 a): "ja, als kleines Paket für 0.2.0".
- Source: the printer setup of 2026-10-07. An Omarchy agent ran
  `pkexec lpadmin -p … -m everywhere -E` from `~/Work`, the user typed
  the password, `/etc/cups/printers.conf` changed, and Seldon recorded
  nothing.

Role: Engine Dev (Opus, high). Small.

**Goal.** Every command an agent runs through a privilege wrapper is in
the record, even when Seldon does not know the program. A command that
is already recorded under its own class must not produce a second event.

**Today.** SPEC-ENGINE §8: the hook records only these classes:
- package commands;
- `omarchy …` routes and `omarchy-*` scripts;
- `systemctl enable|disable|start|stop|mask|unmask`;
- writes into watched paths;
- `git` inside the config home or the logbook;
- snapshot commands.

`pkgcmd.rs` already unwraps `sudo`, `doas`, `pkexec` and `run0` (F-531)
and knows the probes (`sudo -l`, `pkexec --version`, `command -v`).

**Inputs.**
- AGENTS.md §3/§7/§8.
- docs/SPEC-ENGINE.md §5 (classification, ADR-0028 rows) and §8 (hooks).
- `engine/src/pkgcmd.rs` (wrappers, command position).
- The hook code (`commands/hook.rs`).
- ADR-0028 (attention by consequence), ADR-0031 (password prompts as
  Omarchy).
- The omarchy skill's "Privilege Escalation" section
  (`$OMARCHY_PATH/default/agents/skills/omarchy/`).

**Outputs.**
- A new hook record class:
  - **Privileged command.** A command whose position (after `bash -c`,
    `eval`, wrappers and `;`/`&&`/`|`) starts with `sudo`, `doas`,
    `pkexec` or `run0`, runs a real program (not a probe), and is not
    already recorded by an existing class.
  - Kind and subject: follow SPEC conventions, for example
    `privileged-command` with subject = the program's basename (`lpadmin`).
  - Detail: the redacted command line, clipped per ADR-0025.
  - Actor and case: as the other hook records have them.
  - `meta.wrapper` holds the wrapper name.
- Classification under ADR-0028: **attention**, never routine, never a
  crisis by itself. A program in `alwaysRed` is already a crisis through
  its own class. If the case the agent works on is open, the record links
  to it like other hook records.
- An ADR amendment, or an ADR-0028 row note, for the new row, as
  `proposed`. The operator accepts it.
- Tests:
  - `pkexec lpadmin -p X -v ipp://… -E` → one event, attention.
  - `sudo nmcli con up x` → one event.
  - `pkexec pacman -S x` → only the package event, no second event.
  - Probes (`sudo -l`, `pkexec --version`, `command -v sudo`) → none.
  - Inside `bash -c '…'` and after `&&` → recorded.
  - A secret in the arguments is redacted.
  - Idempotent on a replayed hook payload.
- SPEC-ENGINE §8, guide 04 (what the record contains) en/de, CHANGELOG.

**Acceptance.**
- `just check` is green.
- `just check-perf` keeps the hook budget.
- Live on the test host: an agent adds the **second network printer** via
  `pkexec lpadmin` (the operator types the password). Exactly one
  `privileged-command` event appears, linked to the case if one is open.
- No AGENTS.md change: the hook only reads the command text.

**Dependencies.** None on `next`. WP-131 (collector hashes for CUPS) comes
after this one.
