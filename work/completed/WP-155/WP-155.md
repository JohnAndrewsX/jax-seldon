# WP-155 — deploy-test-host: a mode for `next`

Ships in 0.2.0 on `next`. Needed by WP-126's live sweep. The orchestrator
deployed `next` to the test host by hand on 2026-10-07 for T2; that
should be the script's job.

Role: Engine Dev / Packaging (Opus, medium). Small. It targets the script
on `main` **and** `next`. Merge it into `main` first, then into `next`.

**Goal.** `scripts/deploy-test-host.sh --branch next GATE_LOG` deploys
the `next` build with the same safety as the main build.

The same refusals apply: a listed test host only, a pinned machine-id, a
clean checkout of `next` at HEAD equal to `origin/next`, and a gate log
whose `head <sha>` is HEAD or an ancestor with no engine, plugin or schema
change since.

The version is `X.Y.Z+next.<sha>`. The backup goes to
`~/.local/state/seldon-dev/backup-before-next-<ts>/` (`shell.json`, the
state dir, the engine, the plugin).

**Acceptance.**
- `tests/deploy/deploy-test-host.test.sh` rows for the new mode.
- A green CI run on the branch before the merge: it is a shell script,
  and shellcheck runs only in CI.
