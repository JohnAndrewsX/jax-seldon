# WP-007 — `index`, `status`, ledger `.md` view, STATUS.md

## Goal
The engine produces the contract output the plugin consumes, and the
generated Markdown projections, fast and atomically.

## Inputs
docs/CONTRACT.md, schema/index.schema.json, fixtures/index.sample.json,
fixtures/logbook/ (WP-002), docs/SPEC-ENGINE.md §6, docs/SPEC-LOGBOOK.md
§2 §5.

## Outputs
- `engine/src/index/` — reads all `ledger/*.jsonl`, case files, today's and yesterday's journal, `decisions/*.md` frontmatter, `system/*.md` fenced sections, `memory/*.md` frontmatter + first 20 lines, `areas/*/`; produces `index.json` per the schema (newest 500 events, last 50 completed cases, 366 heatmap days, 10 snapshots; `series.*` computed).
- Atomic write (temp file + rename) to `~/.local/state/seldon/index.json`; `seldon index --check` validates against the schema.
- `seldon status` — regenerates `STATUS.md` and the index; human output summarises.
- `ledger/YYYY-MM.md` generated view (SPEC-LOGBOOK §5) with wikilinks for cases and the generated header line.
- `STATUS.md` with the generated header line; user text outside generated fences preserved.
- `cargo bench` for the index build on ×10 fixtures.

## Orchestrator notes (2026-10-01)
- The derivation rules are ADR-0012 §6–§10 (plus §11–§15), ADR-0013 §1–§4
  (drift groups: leader id, `txId`/`members`, computed zone, routine class
  with `[drift] alwaysRed` from config), ADR-0015 (proposedCase = leader's,
  token rule with the trailing-period clause, `series.drift` counting).
  The reference implementation is `scripts/validate-fixtures.py` (`derive`)
  — read it, then write the Rust; where the two disagree, the golden test
  decides and you report the difference (do not edit the fixture).
- Module ownership: `engine/src/index/` (builder, series, views),
  `engine/src/commands/{index,status}.rs`, `engine/benches/`, the generated
  `ledger/YYYY-MM.md` and `STATUS.md` writers. WP-009 runs in parallel and
  owns `commands/hook.rs`, `pkgcmd.rs`, `attribution.rs`; WP-015 owns
  `schema/` and `fixtures/`. Wire the index rebuild into `capture` and the
  WP-006 commands with one call each (`index::rebuild_if_initialised`),
  CONTRACT.md rule 2; keep those edits to one line per command.
- `index.state.collectors` comes from `cursors.json` (`ok`, `message`,
  `fix`, `lastRun`); `snapper` degraded shows there (ADR-0011).
- Generated Markdown (`STATUS.md`, `ledger/*.md` views) follows the
  logbook `language` for prose; headings and keys stay English (decision
  from the WP-002 review).
- `drift show <id> --json` (CONTRACT.md) belongs to WP-008; do not add it.
- The sample's `generatedAt` is fixed in the fixture; the golden test
  compares modulo `generatedAt`, `engineVersion`, `logbook.git` and uses
  `SELDON_NOW` = the fixture's `generatedAt` for "today".
- Tests through `common::Env`/`support::Bench` only; never the real XDG dirs.

## Acceptance tests
- `seldon index` on `fixtures/logbook/` equals `fixtures/index.sample.json` modulo `generatedAt`, `engineVersion`, `logbook.git` (golden test; this is the WP-002 golden owner's test landing here).
- < 100 ms on ×10 fixtures (release build, asserted in CI).
- Atomic write: a reader never sees a partial file (test with a concurrent reader loop).
- Output validates against `schema/index.schema.json`.

## Constraints
No daemon, no async. If `fixtures/index.sample.json` turns out to be
unreachable from the fixture logbook, fix the fixture (Schema Keeper
reviews), not the schema.
