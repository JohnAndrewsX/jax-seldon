# WP-176 — Contract forward compatibility: `contractReadableFrom`

0.2.0, **before the tag** (operator decision 2026-10-09, E55). From the
prototype 0.3 debate (`jax-seldon-private/prototype-0.3/debate-2026-10-09/`,
SYNTHESIS.md §2 item 2, NEW-1; finding of the G3 devil's advocate).

Role: Engine + Plugin Dev. Small. Reviewer: Opus; Fable stage 2
(contract). ADR: proposed by this WP, the operator accepted the direction
(E55) and accepts the ADR text.

**Problem.** `plugin/Model.js` (around line 249) refuses an index whose
`contractVersion` differs from the plugin's, and `plugin/BarWidget.qml`
(around line 45) then dims the pill with no counts. The engine (install
script, later pacman/AUR) and the plugin (`omarchy plugin update`) update
on separate paths. When 0.3 moves the index to contract 3, every user with
a 0.3 engine and a 0.2.0 plugin loses the crisis colour in the bar until
they update the plugin. Cheap to fix only inside the contract-2 window
(CONTRACT.md rules on the pre-tag window, ADR-0035 §6: optional field,
fixtures, both sides in one PR); after the tag it needs a bump itself.

**Do.**

- **ADR (proposed):** "Contract forward compatibility" — amends
  CONTRACT.md rule 3: the index carries an optional integer
  `contractReadableFrom` (1 ≤ value ≤ `contractVersion`), "the oldest
  plugin contract that can read this index without misreading a field it
  keys on". A later contract bump must list per field why a v2 reader does
  not misread; only then does the engine write `readableFrom: 2`.
- `schema/index.schema.json`: the optional field with that description.
- Engine 0.2.0 writes `contractReadableFrom: 2`; `seldon index --check`
  accepts it; `fixtures/index.sample.json` carries it; the reference
  derive and `scripts/validate-fixtures.py` follow.
- Plugin 0.2.0: status `ok` when `contractVersion >= CONTRACT_VERSION`
  and `contractReadableFrom <= CONTRACT_VERSION` (absent field = equal to
  `contractVersion`, i.e. today's strict rule); otherwise
  `contractMismatch` as today. When the index is newer but readable, a
  quiet notice (SPEC-PLUGIN's notice slot): "The engine writes index v<N>;
  this plugin reads v2 — update the plugin", with Omarchy's plugin-update
  command as a fixed argv (find it in `omarchy commands --json`).
  `manifest.seldon.contractVersion` stays 2. The preview's own check
  (`seldon preview` JSON) is a different schema and stays strict.
- Tolerance tests (`tests/plugin/model.test.js`): the v2 fixture with
  `contractVersion: 3, contractReadableFrom: 2`, unknown top-level keys,
  an event and a drift row with unknown `source`/`kind`, an unknown
  timeline kind → status ok, counts equal, pill tone urgent on the
  fixture's crisis; unknown sources fall back to the default glyph and
  unknown timeline kinds are filtered. A second case:
  `contractReadableFrom: 3` → mismatch. Engine test: the index carries 2.
- CONTRACT.md rule 3 reworded; SPEC-PLUGIN the notice; CHANGELOG.

**Acceptance.** The tests above; `just check` green; the plugin with the
v3-readable fixture shows the bar coloured on the test host (orchestrator
live check).
