# WP-021 — Drift sheet: link / explain / dismiss

## Goal
Every open drift item can be resolved from the panel: link it to a case,
explain it (retroactive case), or dismiss it with a reason. Groups
resolve as one. The list empties as the index rebuilds.

## Inputs
docs/SPEC-PLUGIN.md §5 (Changelog row sheet, crisis strip), docs/CONTRACT.md
(`drift link <id> <case> [--only]`, `drift explain <id> [--only] -- <text>`,
`drift dismiss <id> [--only] -- <reason>`, `drift show <id> --json`),
docs/SPEC-ENGINE.md §3 §5 (drift JSON shapes, fan-out, `--only`, stale
leader, ADR-0021 fold), decisions/ADR-0008 ADR-0013 ADR-0015 ADR-0020
ADR-0021, schema/index.schema.json (`drift[]`, `events[].resolution`,
`resolutionDetail`, `txId`, `members`), fixtures/index.sample.json (4 drift
items), plugin/ (WP-020 merged: Panel, EventRow, NewCaseSheet pattern,
Service queue, arming), tests/plugin/, work/completed/WP-008/HANDOVER.md.

## Outputs
- `plugin/components/DriftSheet.qml` opened from a drift row (Enter on an
  open drift row in the Changelog, or the crisis strip → first crisis):
  item summary (subject, kind, zone, group "+N more" with the member list
  from `index.events` by `txId`, proposedCase), three actions:
  - **Link**: case picker (open cases, the proposed case preselected) →
    `drift link <id> <case> --json` (`--only` toggle for groups);
  - **Explain**: intent text (+ optional zone/risk/area) →
    `drift explain <id> [--only] [--zone --risk --area] --json -- <text>`;
    the result shows the created case id with "Open case";
  - **Dismiss**: reason text → `drift dismiss <id> [--only] --json -- <text>`.
  Writing actions follow the WP-020 pattern (Enter twice or click;
  fields keep their text on refusal; result line with the engine message;
  `canWrite` gating; catcher blocked while editing; Esc keeps the draft).
- Changelog: open drift rows show the "Resolve…" affordance; after the
  FileView refresh the resolved rows show the folded resolution (`linked
  to C-…`, `explained · C-…` per ADR-0021, `dismissed: <reason>`); the
  crisis strip count and the pill follow the index; "+N more" from
  `summary.openDrift − drift.length` when the 200 cap bites (ADR-0020).
- `plugin/Model.js`: `driftArgs` (`{args}`/`{error}`), `driftResult`,
  `driftItemFor(eventId)`, `caseOptionsFor(item)` (proposed first);
  `validateArgs` already covers the forms.
- `plugin/Service.qml`: `drift(action, input)` through the queue, one at a
  time; `driftResult` in the snapshot.
- Tests: node tests; `fake-seldon` answers `drift link|explain|dismiss|show`
  in the engine's JSON shapes and rewrites its index (folds the
  resolution, removes the item, re-keys a group after `--only`);
  service-states scenarios with exact argv (text `--help`, quotes,
  `--only`, refused unknown case, no-op re-run `resolved: 0`); panel-view
  scenarios: open the sheet from a row and from the strip, link with the
  proposed case, explain creates a case shown in Work, dismiss a group →
  three rows folded, strip count drops, `--only` leaves a smaller group;
  keyboard flow; refused call keeps the text.
- `plugin/README.md`, `docs/TESTING.md` updated; offscreen renders of the
  sheet in three themes (live sweep when the test host is unlocked).

## Acceptance tests
- `just check` exit 0 (zero qmllint warnings, tokens, both harnesses).
- On the sample: the four items open the sheet; the proposed case is
  preselected for the theme item; the group sheet lists 3 members.
- Each action calls the engine with validated ids and the text after
  `--`; the list empties after rebuild (fake engine) and the pill/strip
  follow; a re-run on a resolved item shows "already resolved".
- Runtime smoke with the real engine on the test host (IPC-driven if the
  session is locked; keys and screenshots only when unlocked —
  ORCHESTRATION.md §11 rule).

## Constraints
As WP-020: fixed argument lists, free text after `--`, ids validated,
never block the shell thread, qs.Ui + tokens only, dev host copy-only, a
guard block is reported, never worked around, lock status checked before
any `wtype`/`grim`.
