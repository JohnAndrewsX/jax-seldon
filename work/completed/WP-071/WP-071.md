# WP-071 — shell parser: one parser for hook and attribution; pkexec, run0 and option clusters; version/help not mutating; `>&` and heredoc cases

Role: Engine Dev (Opus, high). Size: L. Wave: 4. Depends: WP-063 (hook
behaviour and SPEC §8 PreToolUse paragraph settled), WP-057.
Findings: F-530, F-531, F-532, F-534, F-536.

## Goal

The hook and attribution read a command line the same way, and the
shared lexer handles the cases the review found.

- **F-530** — `command_intent` (pkgcmd.rs ~231-298) is built from the
  shared `parse_shell`/`command_argv` (~607-669); attribution.rs (~64)
  uses it; a parity test runs one table of lines through both entry
  points.
- **F-531** — wrappers `pkexec`, `run0`, and value-taking option clusters
  for `sudo`/`doas` (e.g. `-u root`, `-Eu root`, `--user=root`)
  (~618-648).
- **F-532** — `yay --version`/`--help` (and `-V`/`-h`) are not
  mutating; `-Y`, `-P`, `-G` are modelled (~144-148).
- **F-534** — after `>&` a word that is not digits or `-` is a write
  target (`Pending::Write`, ~493-499).
- **F-536** — heredoc bodies inside `$(...)`, backticks and double
  quotes are cut; `<<` inside `((...))` is not a heredoc (~402-456,
  ~501-510).
