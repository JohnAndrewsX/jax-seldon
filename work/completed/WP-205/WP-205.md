# WP-205 — desk-view's today-live waits for its index

0.2.x, tests only. From the orchestrator's gate n202m (2026-10-12): on a
loaded host (load 15–18 on 16 cores) `tests/plugin/desk-view.sh` failed
twice in `today-live #1` — `journal.cases` 1 (want 7) and "No case" not
shown — on a tree whose code had passed the same gate before. The case
starts without an index (`run today-live ""`) and takes view #1 before
the fake engine's index arrives: `Model.caseOptions` of an empty index
is the "No case" option alone, so the journal field hides its picker.
The next gate on the same code passed.

Role: Plugin Dev (Opus, medium). Reviewer: Opus.

**Do.** View #1 of `today-live` waits for the index (the harness's
`wait:` step on a field the loaded index sets, as `chips.5` does later
in the same case), so the case asserts the loaded state, not a race.
Look for other cases that start with `""` and assert index-derived
fields before a `wait:` or `settle`, and give them the same wait.
No plugin change.

**Acceptance.** `today-live` passes under load: run the case 20 times
in a row while `stress`-like load runs (a busy loop per core, killed
afterwards; no package install), and with the wait removed it fails at
least once in the same run (say how often); `just check` green;
evidence words in the handover.

**Inputs.** `tests/plugin/desk-view.sh` (`today-live`, the `run`,
`wait:` and `settle` steps), `tests/plugin/harness/`;
`plugin/components/desk/JournalField.qml`; `plugin/Model.js`
(`caseOptions`); TESTING.md §3.
