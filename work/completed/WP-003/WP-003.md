# WP-003 — Engine core: config, logbook model, frontmatter, `init`

## Goal
The engine can create and read a logbook. Every later engine WP builds on
the types and I/O here.

## Inputs
AGENTS.md §7, docs/SPEC-ENGINE.md §1 §2 §3 §9, docs/SPEC-LOGBOOK.md (all), decisions/ADR-0010-logbook-path.md, decisions/ADR-0011-snapper-degraded.md (doctor message),
schema/case.schema.json, fixtures/logbook/ (WP-002), memory/host.md.

## Outputs
- `engine/src/config.rs` — `~/.config/seldon/config.toml` (serde + toml), defaults, `SELDON_LOGBOOK` and `--logbook` precedence.
- `engine/src/logbook/` — paths, `.seldon/logbook.toml`, layout creation, `.gitignore`, optional git init + first commit.
- `engine/src/frontmatter.rs` — YAML frontmatter parse/serialise for case, journal, decision, area, memory; body preserved byte-for-byte.
- `engine/src/model/{case,journal,decision}.rs` — typed structs matching SPEC-LOGBOOK §3 and case.schema.json.
- `seldon init [--path --non-interactive --language --obsidian --harness --git/--no-git]` (dialoguer wizard; `--non-interactive` takes defaults). Path step per ADR-0010: `~/Seldon` (default), `~/Documents/Seldon` (XDG `DOCUMENTS` if set), `<first existing of ~/Work, ~/Projects, ~/dev, ~/src, ~/code>/seldon`, custom.
- `seldon doctor` — engine, config, logbook, omarchy (`omarchy-version`), snapper (reports the permission problem, see memory/host.md §5), git checks; `--json`.
- `engine/templates/{en,de}/` — AGENTS.md, PROJECT.md, DECISIONS.md, areas/*/README.md, memory/lessons.md, system/*.md skeletons (English first; German prose may be a stub until WP-024).
- Exit codes 0/1/2/3/4 as SPEC-ENGINE §3; `--json` on every command.
- Follow-ups from the WP-001 review (engine/src/main.rs): `parse_error`
  must not sniff raw argv for the literal `--json` (use a lenient
  pre-parse) and must report `err.to_string()` detail, not only the error
  kind — see SPEC-ENGINE §3 "JSON shapes". Keep the
  `contract-version == plugin/manifest.json` cross-check, but note in
  `docs/TESTING.md` that it needs the monorepo layout.

## Acceptance tests
- `seldon init --non-interactive --path /tmp/x` produces the SPEC-LOGBOOK layout.
- `seldon doctor` green on that logbook (snapper may be "degraded", not red).
- Round-trip tests for case/journal/decision frontmatter (parse → serialise → identical).
- `cargo fmt --check`, `cargo clippy -- -D warnings`, `cargo test` green.

## Constraints
Allowed crates only (AGENTS.md §7). No async, no network. Never point the
engine at a real logbook in tests; use `SELDON_LOGBOOK` or a temp dir.
