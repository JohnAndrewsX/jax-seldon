# WP-128 — Redaction: continued lines with CRLF endings

Ships in 0.2.0 on the integration branch `next`: branch from `next`, merge
into `next`. Source: the Fable stage 2 of WP-102 (2026-10-07).

Role: Engine Dev (Opus, high). Small.

**Goal.** A secret on a continued line is redacted, whether the text uses
`\n` or `\r\n` line endings. That covers `seldon log`, notes, case texts,
and anything else that goes through `Redactor`.

**Problem.** The `db-client-password` rule (`engine/src/redact.rs`)
continues only on `\\\n`. The same is true of WP-097's option rules. A
Windows-edited text holding `mysql -u root \` + CRLF + `-p secret` keeps
the secret. WP-102's import normalises CRLF itself; the other paths do not.

**Inputs.** docs/SPEC-ENGINE.md §7; `engine/src/redact.rs` and its tests;
WP-097 and WP-102 handovers.

**Outputs.**
- Every rule that continues over a line break accepts `\\\r?\n`.
- Tests: each multi-line rule with LF and with CRLF, through `seldon log`
  and `redact_keeping_lines`.
- The redaction bench stays within its budget.
- SPEC §7 says CRLF is covered.

**Acceptance.**
- `just check` is green.
- A mutant that reverts the CRLF form fails a test.
- `just check-perf` redaction is within budget.

**Dependencies.** WP-102a is on `next` (it shares `redact.rs`).
