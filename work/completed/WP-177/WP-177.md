# WP-177 — Desk readability foundation: text tones from the theme, one cursor, token sweep

0.2.0 if it lands before WP-126's theme sweep, else 0.2.1 (0.2.x,
plugin only). From the prototype 0.3 debate
(`jax-seldon-private/prototype-0.3/debate-2026-10-09/`, SYNTHESIS.md §3
NEW-2; items A9/C4, C2+B9, B11, B13(a)); operator decisions E48–E63
(E54: the focus-border report to Omarchy is the operator's).

Role: Plugin Dev (Opus). Medium plugin, small tests. Reviewer: Opus;
Fable optional. No ADR (a SPEC-PLUGIN §7 rule).

**Problem.** `Color.muted` as text fails 4.5:1 in 20 of 22 themes
(Tokyo Night 1.9:1); 72 text uses of it and 9 `Util.alpha(…, 0.65)` dims
sit in `plugin/`. The default focus border (fg 25 %) is below 3:1. Hover
and keyboard selection can show two highlights at once.

**Do.**
- **Tones (A9/C4).** Port the prototype's `tintTokens`
  (`jax-seldon-private/prototype-0.3/js/app.js`) as `Model.textOn(fg, bg,
  target)` plus a `Tones` object computed once per theme change. Derive
  against the surface the desk draws on, `Color.popups.*` (`Desk.qml`,
  `Today.qml`), not `background`; an alpha < 1 surface is treated as
  opaque and SPEC says so. One text target (4.7:1), one UI target
  (3.2:1). Mix **text only**; stripes and the pill stay raw role colours.
  No black/white fallback. Replace the 72 `Color.muted` text uses and the
  9 `alpha(…, 0.65)` dims.
- **One cursor (C2+B9).** Rows use Omarchy's `CursorSurface` and
  `PointerMoveGate` (`$OMARCHY_PATH/shell/Ui/`): no hover highlight while
  keys drive; selection = accent bar + bold, ≥ 3:1 derived. Seldon's
  **own** controls (`ListRow.qml`, `KeyButton.qml`, `Arm.qml`, chips) get
  the ≥ 3:1 cue; `qs.Ui` fields keep Omarchy's focus look (no double
  frame; `_borderSpec` is private); the ring yields where the theme's
  focus composite already reaches 3:1.
- **Tokens (B11).** Named `Style` tokens where `Style.space(N)` has a
  name; `Tone.divider` for the 9 fg-0.12 literals; no ban on
  `Style.space(N)` (Omarchy writes `space(370)` itself). State fills as
  `Style.qml:82-92`: normal 0.04, hover 0.08, selected 0.18, pressed
  0.22, selection 0.35; focus defaults to hover.
- **Checks (B13a).** `tests/plugin/model.test.js`: `textOn`/`Tones` over
  committed role fixtures (tokyo-night, rose-pine, miasma; the five roles
  only) plus the host's themes under `$OMARCHY_PATH/themes/` when present;
  a theme whose own fg/bg is below 4.5 is *reported*, not failed.
  `tests/plugin/check-tokens.py`: no `Color.muted` as a Text colour;
  `Util.alpha(…, literal)` only on an allow-list.
- SPEC-PLUGIN §7 "Theming": the derivation rule, the surface, the targets.
- Handover: the measured focus-border numbers per theme, for the
  operator's upstream report (E54); this WP files nothing upstream.

**Acceptance.** 0 text uses of `Color.muted` and `alpha(…, 0.65)`;
`textOn` tests pass on the 3 committed and the host themes (bad themes
reported); `desk-view.sh` shows one highlight after a keyboard move under
a still pointer; `check-tokens.py` rules in place; `just check` green
