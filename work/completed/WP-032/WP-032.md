# WP-032 — `seldon rebuild` → outputs/REBUILD.md

## Goal
A document a human (or an agent) can follow on a fresh Omarchy install to
reach the documented state: explicit packages with their cases,
deviations with reasons, plugins, theme, user units.

## Inputs
docs/SPEC-ENGINE.md §3 (`seldon rebuild`), docs/SPEC-LOGBOOK.md (dossier
fences, `system/*.md`), docs/CONTRACT.md (`rebuild --json` is a command the
plugin may run), decisions/ADR-0003 ADR-0012 ADR-0013 ADR-0021,
engine/src/index/ (the `Built` model: events, cases, system fences,
resolutions), fixtures/logbook/ (dossier `system/*.md`, ledger),
work/completed/WP-007/HANDOVER.md, work/completed/WP-008/HANDOVER.md
(reconcile, resolutions), memory/host.md (package install facts: pacman
explicit vs dependency, `omarchy pkg aur add`).

## Outputs
- `engine/src/commands/rebuild.rs` + `engine/src/rebuild/` (builder):
  reads `index::derive`'s `Built` (no second derivation) and the dossier
  fences; writes `outputs/REBUILD.md` with the generated header and these
  sections, in the logbook language with English headings: (1) Base
  (Omarchy version from the last `update` event / dossier), (2) Packages
  — explicit installs (from pacman `install` events with `explicit: true`
  that are not later removed) grouped by case, each line `omarchy pkg add
  <pkg>` or `omarchy pkg aur add <pkg>` (AUR detection: `meta.command`
  via `pkgcmd`, else "(repo unknown)"), with the case id/title and the
  resolution reason for drift items, (3) Deviations — from the dossier
  `deviations.table` fence plus config-change events with a case or an
  explanation (path, reason, case), (4) Plugins — current list from the
  dossier `plugins.list` fence + plugin-add events (`omarchy plugin add
  <url>` when known), (5) Theme — latest `theme-set` (`omarchy theme set
  <name>`), (6) User units — `config-add|change` under `~/.config/systemd`
  with their cases, (7) Open questions — drift still open, dismissed items
  listed as "deliberately not reproduced".
- `seldon rebuild [--json]`: writes the file (atomic, header line, never
  edits user text outside the generated fence), `--json` → `{path,
  sections: {packages: N, deviations: N, plugins: N, units: N, open: N}}`;
  autocommit `seldon: rebuild`; index rebuild not needed (no ledger write).
- Tests: on the fixture logbook the document is golden
  (`engine/tests/golden/REBUILD.md`, `SELDON_BLESS`), every listed package
  traces to an event id; a reviewer walkthrough is in the handover.
- `docs/TESTING.md` engine notes; `engine/hooks/README.md` untouched.

## Acceptance tests
- `just check` exit 0; golden test on the fixture; `seldon rebuild --json`
  on a copy writes the file once and a second run writes nothing (`files:
  []`-style no-op or identical bytes).
- The document lists: explicit packages with cases, deviations with
  reasons, plugins, theme, user units; a reviewer can follow it (the
  reviewer judges readability).

## Constraints
Allowed crates only; no network; read-only reuse of `index::derive`;
tests through common::Env; a guard block is reported, never worked
around. `SPEC-ENGINE §3` edits go to the orchestrator via the handover.
