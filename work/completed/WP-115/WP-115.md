# WP-115 — Link a change to the one case that planned it; capture before a case closes (ADR-0029)

Role: Engine Dev (Opus, high). Ships in 0.1.4. No contract change. After
WP-109 (merged).

## Goal

A change made while exactly one case was active and named it in its Plan
belongs to that case, whoever typed it: the engine links it (rule 9), and
`plan verify`/`plan done` capture first so nothing lands after the close.
Found in the live test of 2026-10-06 (C-2026-004: the user's install of
`glow` became open drift after the agent closed the case).

## Inputs

decisions/ADR-0029-planned-and-active-link.md (normative, §1–§5),
ADR-0012, ADR-0014, ADR-0021, ADR-0027, ADR-0028; docs/SPEC-ENGINE.md §3,
§5, §10; engine/src/reconcile.rs, engine/src/index/build.rs (Plan token
test), engine/src/commands/plan.rs; scripts/validate-fixtures.py;
fixtures/; engine/assets/skills/seldon/ (one sentence); docs/AGENT-GUIDE.

## Outputs and acceptance

As ADR-0029 §5: the rule-9 pass, the capture in `plan verify|done` with
`--no-capture`, the widened linkable set, the fixture line, SPEC, skill
sentence, CHANGELOG; acceptance items 1–9 as tests (`just check` 0,
mutants); item 10 (live check on the fresh test host) is the
orchestrator's after the merge. Tests that read local times set `TZ` in
their helper (CI runs in UTC).
