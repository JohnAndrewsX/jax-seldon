# WP-011 — Panel: Today, Changelog, System tabs

## Goal
The panel shows real data from the index: today's journal, the changelog
with source filter and highlighted snapshot rows, and the system tab. The
crisis strip and the snapper-degraded banner appear. Everything renders in
three themes including a light one.

## Inputs
docs/SPEC-PLUGIN.md §5 §7 §8 §9, docs/CONTRACT.md (rule 1 incl. the XDG
state path and dev mode; the command forms with `--`),
schema/index.schema.json (events incl. `resolutionDetail`, drift incl.
`txId`/`members`, system, today), fixtures/index.sample.json,
fixtures/index-variants/, plugin/ (WP-010), tests/plugin/ (harness),
memory/omarchy-shell.md (WP-001 + WP-010 findings), built-in
`shell/plugins/agents/Panel.qml` for the tab pattern.

## Outputs
- `plugin/Panel.qml` with tabs (`components/Tabs.qml`), keyboard navigation
  (Tab/Shift-Tab between tabs, arrows in lists, Esc closes), the banner from
  WP-010 on top of every tab, the crisis strip ("N changes in the red zone
  need a reason") and the snapper-degraded banner (collector `ok: false`)
  with the one-line fix (Copy / Open terminal, constant command).
- Today tab: journal entries of today and yesterday (`today[]`), summary
  counts.
- Changelog tab: `events[]` newest first, `components/EventRow.qml`
  (source glyph, kind, subject, actor, case link, zone colour, folded
  `resolution` + `resolutionDetail`, group badge "+N" for drift groups),
  source filter (`pacman | snapper | omarchy | plugins | theme | config |
  agent | seldon`), snapshot rows highlighted.
- System tab: `system` section (omarchy version, theme, last update,
  package counts, deviations, snapshots, plugin counts, areas); every field
  optional (schema has no `required` there).
- `plugin/Model.js`: aggregation helpers for the tabs; `validateArgs`
  extended with `drift show <id> --json`, `[--only]`, and the `--`
  separator before free text (CONTRACT.md); reject free text that is empty.
- Service.qml: index path honours `XDG_STATE_HOME` (CONTRACT.md rule 1);
  engine probe only at shell start and on *Check again*, not every
  interval (WP-010 review, decision 5).
- `tests/plugin/`: node tests for the new helpers; harness scenarios for the
  crisis strip and snapper-degraded; fix the harness portability nit from the
  WP-010 review (`service-states.sh` aborts when `seldon` is in
  `/usr/bin`: build the base PATH from symlinks to the needed tools instead).
- `docs/TESTING.md`: three-theme procedure (one light theme) with
  screenshots on the test host; `plugin/README.md` updated.

## Acceptance tests
- `just check` exit 0 (qmllint zero warnings, token check, plugin-test).
- With the fixture index every tab renders its data; the Changelog shows
  58 events, the drift group row shows "+3", folded events show the
  resolution detail; the source filter narrows the list; snapshot rows are
  highlighted.
- Crisis strip shows "2 changes in the red zone need a reason" on the
  sample; `index-variants/snapper-degraded.json` shows the snapper banner.
- Keyboard: Tab cycles tabs, Esc closes, arrows move in lists (harness or
  `wtype` on the test host).
- Theme sweep on the test host: three themes incl. a light one, screenshots
  attached under `work/completed/WP-011/` (no hard-coded colours).
- Runtime smoke on the test host: no QML errors or warnings from
  jax.seldon in `quickshell log`.

## Constraints
As WP-010: never block the shell thread; qs.Ui + tokens only; fixed
command argument lists; no symlinks; no `omarchy.*` ids; dev host: copy
only to `~/.config/omarchy/plugins/jax.seldon`, never enable there; the
test host is the runtime target (docs/HERDR-SETUP.md §5, restart the shell
after every copy).
