# WP-120 — Contract v2 bundle (ADR-0035)

Ships in 0.2.0 on the integration branch `next` (branch from and merge into `next`). Plan: decisions/ADR-0034-desk.md and the 0.2.0 plan (orchestrator's private notes); the prototype is the spec of look and behaviour (path in the brief).


Role: Engine Dev + Schema Keeper (Opus, high). Wave 1. Writes ADR-0035
first (the bundle decided 2026-10-04 plus the two fields ADR-0034 needs),
then bumps.

**Goal.** `contractVersion` 2: everything 0.2.0 reads from the index is
written by the engine and validated by the schema; the plugin refuses
nothing it will need later in this release.

**Inputs.** STATUS.md "contract v2 bundle" and "Decided 2026-10-04";
ADR-0034 §5–§6; CONTRACT.md ("Changing the contract", rule 5 on
`meta.truncated`); `schema/*.json`; `engine/src/index/{build,model,
views}.rs`, `engine/src/model/decision.rs` (`cases`), `engine/src/lib.rs`
(`CONTRACT_VERSION`); WP-115 stage 2 (`meta.risk`); WP-081 (state loss);
the autocommit code path; `plugin/manifest.json` and `Model.js`
(`CONTRACT_VERSION`, the `contractMismatch` banner).

**Outputs.**
- ADR-0035 (accepted on the 2026-10-04 decision; the two new fields are
  ADR-0034's).
- Schema: `contractVersion` const 2; `meta.risk` on `case-created` /
  `case-started` and a ledger line for `plan set --risk`; `logbook.git.
  autocommit: {ok, at, message}`; `meta.truncated: true` beside a clipped
  text (replaces the `… (N more …)` convention only in the flag, the
  suffix stays for humans); event kind `state-loss`; `decisions[].cases`
  (array of case ids, may be empty); `triage` (optional object `{id, at,
  actor, counts: {items, crises}, path, applied}`; absent when no
  proposal exists).
- Engine: writes all of it; `seldon index --check` validates; the ledger
  stays append-only (no rewrite of old lines; `meta.risk` only on new
  records; ADR-0029's harm guard reads the record and falls back to the
  case file for old cases, as WP-115 does today).
- Fixture v2 rich enough for every desk surface (ADR-0034 §2 table, §5,
  §6): at least one decision with two cases, one proposal with a link, an
  explain and a crisis item, one `state-loss` event, one truncated detail.
- Plugin: `CONTRACT_VERSION` 2 in `Model.js` and the manifest;
  `Model.parseIndex` tolerates the new optional fields; nothing else
  (the surfaces come in WP-122–125). `engineMin` stays until WP-126 sets
  0.2.0.
- CONTRACT.md, SPEC-ENGINE §6, CHANGELOG **Breaking** entry, `docs/
  VERSIONING.md` unchanged.

**Acceptance.** `just check` 0 (schema-validate on the new fixture,
golden engine output); engine tests for every new field including "an
old ledger without `meta.risk` still indexes"; idempotency of `index`;
`seldon contract-version` prints 2; a 0.1.x plugin against a v2 index
shows the `contractMismatch` banner with both numbers (harness
`service-states.sh` case). Review: stage 1 Opus, stage 2 Fable
(contract).
