# WP-101 — One-click start, agent snapshot and close path, closed-by-agent marker, reopen

Role: Engine Dev + Plugin Dev (Opus, high). After WP-100 (rules text)
and WP-096 (actor and `SELDON_ATTENDED`; the close path needs a reliable
actor). ADR-0027 §2c, §3, §5, §6. No contract change (`tags`,
`snapshotBefore`, `status`, `actor` exist); CONTRACT.md gains the
reserved tag vocabulary.

## Goal

A case costs the user one click and one sentence: the panel's "New case"
runs the agent; the agent records its own snapshot and closes its own
case; the record shows it was the agent; a spot check or a reopen is one
click, never required.

## Inputs

From WP-100: the panel fix for `rules: outdated` (doctor has the row and
the fix; the plugin never runs doctor — run `seldon doctor --json` on
panel open with a fixed argv, or leave it to the CLI; decide); the
template gains `seldon plan snapshot <ID> <N>` once it exists (the
template-command test enforces that only existing commands appear); a
`--snapshot` given at `plan start` is validated only against "before
the first red event".


ADR-0027, engine/src/commands/{agent,plan,doctor}.rs, engine/src/

## Outputs

- `seldon agent start --new [--zone][--risk][--area] -- "<intent>"`:
  creates (title = first sentence ≤ 72 chars, Intent = text), starts,
  sets `SELDON_ACTOR` and `SELDON_ATTENDED=1`, launches with the id-only
  prompt; `--json` as `agent start`; refusal without a default agent
  names the fix.
- `seldon plan set <ID> [--zone Z] [--risk R] [--area A] [--actor]`:
  frontmatter write by the engine, Log line; exit 1 on a closed case.
- `seldon plan snapshot <ID> <N> [--actor]`: sets `snapshotBefore` when
  empty (else exit 1 naming the existing number); validates existence,
  instant after `case-started` and before the case's first red event;
  warning lines, never a refusal. Hook attribution of `snapper … create`
  / `omarchy-snapshot create` fills the field as fallback.
- Snapper collector: a `snapshot-delete` whose number is some open or
  completed case's `snapshotBefore` → Log line `rollback for <ID> pruned
  (snapshot N)` and `doctor` row.
- Advisory after the fact: a red event with an `alwaysRed` subject inside
  a case with risk below R3 → Log line, `index` warning (existing
  warnings channel; no new field).
- `plan done` by an agent actor with empty Result or unfilled
  Plan › Verification → exit 1 with the reason; human close unchanged.
  An agent close adds tag `closed-by-agent`.
- `seldon plan reopen <ID> [--actor]`: new active case "Reopen: <title>",
  Intent copied, tag `reopens:<ID>`, Log lines on both, `--json`.
- Panel: Work tab "New case" (intent field + Run, fixed argv, busy
  state, engine refusal shown); completed card marker "closed by agent"
  and a filter toggle; Reopen on every completed card (one click, no
  arming — it creates, it destroys nothing).
- Fixture: a completed case with `closed-by-agent`, a case with
  `reopens:`; schema still validates. CONTRACT.md reserved tags. SPEC-ENGINE
  §3/§4/§5, SPEC-LOGBOOK §3, SPEC-PLUGIN, guide 03/04/05 en/de, CHANGELOG.

## Added from the WP-096 review (stage 2)

- `plan set`, `plan snapshot` and `plan reopen` take `actor:
  Option<String>` and call `actor_or_env(.., parse_person, ACTOR_HUMAN)`
  before `open_logbook`.
- The refusal loop in `engine/tests/actor_env.rs`
  (`a_refused_variable_is_exit_1_and_writes_nothing`) lists all three.
- The refusal of `plan done` by an agent with an empty Result tests the
  *resolved* actor: one test closes via `SELDON_ACTOR=agent:x` without
  `--actor` and must exit 1 (otherwise the environment path bypasses the
  only guard ADR-0027 §5 keeps).
