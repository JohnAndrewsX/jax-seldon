# WP-162 — The shell crashes on every IPC restart with two bar widgets

Ships in 0.1.4 (main): **release blocker**, then 0.2.0 (next). Operator
decision 2026-10-08 E26. v0.1.4 is tagged only after this is merged and
verified live with two monitors.

Role: Plugin Dev (Opus, high). Small, careful.

**Incident.** Since plugin 0.1.3, every IPC restart of the Omarchy shell
(`omarchy-restart-shell`, so every `omarchy update`) ends in SIGSEGV when
more than one `jax.seldon` bar widget exists (two monitors). Six crashes
with one stack on the dev host (2026-10-05 and 2026-10-08). Symbolised
core: `qs::io::ipc::IpcHandler::updateRegistration` (ipchandler.cpp:318)
during `QQmlElement<ShellRoot>::~QQmlElement`; the handler is
`jax.seldon.panel`, `registeredState.enabled=false`,
`targetState.enabled=true`.

**Cause.** `plugin/BarWidget.qml` `Component.onDestruction` sets
`ipcOwner = false` and calls `root.reclaimIpc(root)`, which makes a
sibling `ipcOwner = true`; that sibling's `IpcHandler { enabled:
root.ipcOwner }` registers with an engine generation that is being torn
down. Quickshell 0.3.1 lacks a guard (upstream bug), but Seldon must work
with it.

**Do.**
- No synchronous hand-over in `Component.onDestruction`: only
  `ipcOwner = false`. A new owner is chosen through the existing paths
  (`onDrawnChanged`, `onBarChanged`, `Component.onCompleted`, each via
  `Qt.callLater`), or another trigger that cannot run during engine
  teardown.
- Prove that removing one instance at run time (a monitor unplugged, the
  widget removed from the bar) still yields exactly one owner and a
  working `quickshell ipc call jax.seldon.panel open`.
- Regression test in the harness: a shell with two bar widgets, ended by
  `quickshell kill` (IPC), then no new entry under the harness HOME's
  `.cache/quickshell/crashes/` and a clean exit status. It must run in its
  own runtime dir (WP-161).
- Correct the earlier attribution: `work/completed/WP-013/FINDINGS.md`
  and `memory/pitfalls.md` — an unsymbolised trace without a QML frame
  does not clear the plugin; symbolise first (debuginfod, gdb with
  `-iex 'set debuginfod enabled on'`). Mark WP-013's crash as unexplained.
- Release test (`docs/` release checklist): restart the shell via IPC with
  two bar widgets and check `~/.cache/quickshell/crashes` and
  `coredumpctl list quickshell` before and after.

**Acceptance.**
- The regression test fails on the current code and passes on the fix.
- `just check` green (WP-161 rules).
- Live on the dev host with two monitors, with the operator's go (it
  restarts the operator's shell): install the fixed plugin, run
  `omarchy restart shell` three times, no new crash report.
