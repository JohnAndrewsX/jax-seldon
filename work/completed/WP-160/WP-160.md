# WP-160 — A stale pacman db.lck hides an unfinished transaction

Ships in 0.2.x. Engine core (collector); stage 2 Fable.

Role: Engine Dev (Opus, high). Small.

**Observed** (WP-137 review 1, N2). After a power loss or a `kill -9` of
pacman, `/var/lib/pacman/db.lck` stays on disk. The pacman collector then
holds the open transaction back (ADR-0013 §5) until the user deletes the
lock, so neither its package rows nor the `unfinished` mark (ADR-0043)
appear. That is the case ADR-0043 calls the worst one.

**Do.**
- Treat a `db.lck` whose mtime is older than the current boot
  (`/proc/stat` `btime`) as stale: the transaction is emitted as
  `unfinished`. A lock from this boot keeps today's rule.
- Read only: never delete or touch the lock (AGENTS.md §6).
- Doctor names a stale lock and says how to remove it (text only).
- Update ADR-0013 §5's description in SPEC-ENGINE (no ADR change needed if
  the reviewer agrees it is a clarification; otherwise a short ADR).

**Acceptance.**
- Tests with a fake lock older and newer than a fake boot time.
- Idempotency: a later capture after the lock is removed adds nothing.
- `just check` green.
