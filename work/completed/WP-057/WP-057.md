# WP-057 — hook: case updates under the lock, patient lock wait, session-stop runs every step

Role: Engine Dev (Opus, high). Size: L. Wave: 1. Depends: WP-055.
Findings: **F-500 (High)**, F-502 (+ merged F-401), F-501, F-507, F-400.

## Goal

The agent hook never loses or duplicates a case update, waits long
enough for the lock, keeps the lock short, and `hook session-stop`
completes every step even when one fails.

- **F-500** — `record()` (hook.rs ~806) takes the state lock *before*
  reading `.seldon/active-case` and loading the case (`cases::find`); the
  case read-modify-write happens only under the lock, like every other
  case writer (log, event, drift, plan, agent, reconcile). Records that
  need no case may be filtered before the lock. `index --check` reports a
  case id present in two folders (today only `cases::find` notices,
  cases.rs ~167).
- **F-502 / F-401** — the index rebuild runs after the ledger/case write
  with the lock released (or outside the critical section);
  `LOCK_PATIENCE` (hook.rs:73, 2 s) raised to about 8 s, below Claude
  Code's hook timeout; `session_stop` runs every step past an earlier
  failure (no `?` at ~997/~1010) and reports the collected errors on
  stderr, exit 0.
- **F-501** — a journal day file without frontmatter is accepted: the
  next append prepends the block; `seldon log` does not leave a ledger
  entry without its journal line (order or rollback, say which); `plan
  done` and session-stop pass such a file.
- **F-507** — session-stop writes the STATUS.md views under the held
  lock before the commit, as SPEC-ENGINE §8 already states.
- **F-400** — the hook path skips the fast index rebuild above a ledger
  line threshold (or always — decide and say why) and lets the next
  `capture`/`status` catch up; SPEC §8's "under 5 ms" sentence gets the
  measured number.

## Outputs and acceptance

- Race test: a test holds the lock, changes the active case under it
  (status + one event), releases it while a hook waits → the case keeps
  both its change and the hook's event id; fails on the
  find-before-lock mutant. Repeat test: N rounds × 2 concurrent
  PreToolUse hooks → every ledger event id is in the case's `events:`.
- `index --check` flags a case id in two folders (test).
- A hook that waits while the lock is held 5 s records its event (fails
  with 2 s patience).
- session-stop with a broken journal file still captures, rebuilds the
  index and STATUS.md and commits; exit 0, errors on stderr.
- Frontmatter-less day file: `seldon log` exit 0, block prepended, ledger
  and journal both carry the entry; `plan done` exit 0.
- session-stop rewrites STATUS.md (test).
- F-400: above the threshold the hook leaves index.json unchanged and the
  next `status` brings it up to date (test); SPEC §8 budget text matches
  a measured release number (in the handover).
- `just check` 0; `just check-rss` 0 (the WP touches engine/src/index/).
