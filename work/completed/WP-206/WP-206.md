# WP-206 — counts from list lengths when the index is cut

0.2.x, plugin only. From the WP-204 review (2026-10-12, finding 2) and
ADR-0053 §5's list of counts the plugin takes from list lengths. Since
WP-204 the Work headers read "QUEUED · 50 / 450", but a group with no
listed row has no header at all: at ADR-0053 rung 21 the ACTIVE group
disappears while `summary.activeCases` is 40 (`sections/Work.qml`
~559; `workView` already returns "ACTIVE · 0 / 40"). `wipStatus` and
`anyCase` count list lengths the same way.

Role: Plugin Dev (Opus, medium). Reviewer: Opus.

**Do.** Work draws a group header when the summary counts cases the
list does not show, with one dim line under it that says the index
lists none of them and how to see them (`seldon case list`). `wipStatus`
and `anyCase` read the summary's counts where the index carries them.
Go through ADR-0053 §5's table of list-length counts and say for each
whether it now reads the summary or why it stays; no engine, schema or
fixture-contract change.

**Acceptance.** Model tests on a cut index (rung 21: active list empty,
`activeCases` 40) show the ACTIVE header and the line; `wipStatus` and
`anyCase` on that index; a whole index renders as before (headless
desk-view unchanged); `just check` green; evidence words in the
handover.

**Inputs.** `plugin/Model.js` (`workView`, `wipStatus`, `anyCase`),
`plugin/sections/Work.qml`; ADR-0053 §5; CONTRACT.md rule 4;
private `review-0.1.1/handovers/WP-204-review-1.md`.

Depends on: WP-204 merged into `next`.
