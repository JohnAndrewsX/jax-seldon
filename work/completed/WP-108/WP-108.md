# WP-108 — Hook headroom on curl lines with `-e`

Role: Engine Dev (Opus, high). Small; after WP-106 (redact.rs). From the
WP-106 stage-2 review (Q3).

## Goal

The 900-line hook timing row WP-097 added (`set -e; curl … -u … | sudo -E
bash && git commit -am x`, `just check-perf`, bound 5 ms, SPEC §1 budget)
measures 4.7–4.9 ms and missed once at 5.22 ms on a quiet host. Win back
time so the row's median is ≤ 4 ms; do not raise the bound.

## Inputs

engine/src/redact.rs (`cert-password` trigger `curl+-e`, compiled on
every curl line holding `-e`: `set -e`, `sudo -E`), engine/tests/hooks.rs
(`fast_enough_just_below_the_rebuild_threshold`, ignored, check-perf),
the WP-092 handover (the deferred detached-rebuild lever), the WP-097 and
WP-106 handovers and review packets (private folder).

## Outputs

Measure both levers and take the cheaper one that reaches the target:
(a) a bounded `cert-password` trigger (` -E`/`--cert`/`--proxy-cert`
literals rather than bare `-e`, keeping triggers literal text every match
contains); (b) the detached rebuild deferred in WP-092 (a design change:
then an ADR first — stop and say so). Interleaved A/B numbers under the
check lock in the handover; SPEC §7 cost sentence updated.

## Acceptance

`just check` and `just check-perf` 0; the row ≤ 4 ms median; mutants.
Review: stage 1 Opus, stage 2 Fable (redaction trigger / hook path).
