# WP-168 — Logbook writers refuse a linked folder

Ships in 0.2.x on `next`. From the WP-166 review (N1). Engine core;
stage 2 Fable.

Role: Engine Dev (Opus, high). Small.

**Observed.** `seldon decide` writes a new ADR through a `decisions/` that
is a symbolic link, to wherever the link points (the file is created with
O_EXCL, so nothing is overwritten, but it lands outside the logbook and
git reports "beyond a symbolic link"). WP-166 fixes `inbox/`; the other
folders the engine writes into need the same rule.

**Do.**
- One helper (as `triage::checked_dir`, WP-124): every logbook folder the
  engine creates a file in (`decisions/`, `cases/…`, `ledger/`, `inbox/`,
  `journal/`, `system/`, …) must be a real directory inside the logbook;
  a link or a non-directory is refused with exit 1 and a reason.
- List every writer (grep `create_dir`, `OpenOptions`, `write_new`) in the
  handover and show each uses the helper.

**Acceptance.** A test per folder with a link and with a file in its
place; mutants on the helper killed; `just check` green.
