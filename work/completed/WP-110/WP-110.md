# WP-110 — Plugin: quiet surfaces (ADR-0028 WP-B)

Role: Plugin Dev (Opus, high). Ships in 0.1.4. No contract change; reads
only `summary` and `drift`, no new engine call. Can run in parallel with
WP-109: it keys on `crisis`, `openDrift` and `summary.crisis`, which
exist today.

## Goal

The bar and panel stay quiet for everything but a crisis (ADR-0028 §4a,
§4b): the bar's `D` is the crisis count by default (hidden at 0), the
red strip only for crises with the new text, attention is a quiet
Changelog header line, labels follow `crisis` not `zone`.

## Inputs

decisions/ADR-0028-attention-by-consequence.md §4a/§4b/§7/§8 WP-B,
docs/SPEC-PLUGIN.md §4/§5, plugin/ (bar, panel, DriftSheet.qml ≈ 313/370,
Model.js ≈ 352/682, Today pictogram), the plugin manifest settings
(`wipLimit` as the pattern), tests/plugin harness, AGENTS.md §7 plugin
rules, fixtures/index.sample.json.

## Outputs

Plugin setting `driftInBar` (`crisis` default, `all`, `none`); bar count
and neutral tooltip ("Seldon — N active cases, N crisis, N changes
without a case, last capture …"); strip text "N changes that can affect
boot, login or the shell have no case"; drift-sheet labels keyed on
`crisis`; Changelog header line "N changes without a case" (no badge, no
tab colour); Today pictogram rule (crisis → urgent; active case →
accent; attention alone → nothing); drift-sheet order with an *Ask
agent* slot (the button lands in WP-095); SPEC-PLUGIN §4/§5; CHANGELOG.

## Acceptance

Harness cases: bar at `crisis|all|none`, strip only with a crisis, a
yellow-zone crisis labelled as crisis, header line, pictogram; `omarchy
plugin validate plugin/` and `qmllint -I "$OMARCHY_PATH/shell"` pass;
`just check` 0. Review: stage 1 Opus, stage 2 Fable (unsandboxed plugin).

built-in plugins' settings before choosing where `driftInBar` lives:
use the Omarchy shell's own plugin-settings mechanism (as `wipLimit`
does; `shell.json` hot-reloads), never a private file. Bar placement and
behaviour follow `omarchy bar` conventions.
