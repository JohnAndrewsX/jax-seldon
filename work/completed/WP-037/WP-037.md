# WP-037 — Overlay live findings: `periodView` fallback on open, harness creation order, heatmap probe docs, theme shots

## Goal
The Prime Radiant behaves in the live Omarchy shell as the headless
harness proves (no aggregation on open), the harness loads the overlay
the way the shell does so the mismatch cannot return, the heatmap probe
documentation hits a cell, and the three-theme live screenshots are
complete.

## Inputs
work/completed/WP-013/FINDINGS.md §5 and HANDOVER.md (live `call view`
→ `aggregations: {service: 736, overlay: 23}` on the first open; the
reviewer's mechanism: 23 = exactly one `Model.periodTable()` run — the
installed shell creates the overlay item and injects `service`
afterwards (`$OMARCHY_PATH/shell/shell.qml`, `if ("service" in item)
item.service = …`), so `periodData: Model.periodView(root.service ?
root.service.periods : null, root.period)` in plugin/Overlay.qml first
evaluates with `service === null` and `periodView`'s fallback calls
`periodTable(null)` once in Overlay.qml's own Model.js instance; the
harness passes `service` as a creation property, so it never sees it),
plugin/Overlay.qml, plugin/Model.js (`periodView`, `periodTable`,
`aggregationCount`, `heatmapLayout`), plugin/components/overlay/
{ChartCanvas,Heatmap}.qml, tests/plugin/harness/overlay.qml and
tests/plugin/overlay-view.sh (`fresh`, `firstFrame`), docs/SPEC-PLUGIN.md
§6, docs/TESTING.md, plugin/README.md (hover probe example),
work/completed/WP-013/live/ (Osaka Jade shots; Tokyo Night and
Catppuccin Latte missing), memory/omarchy-shell.md, memory/pitfalls.md.

## Outputs
- `Model.periodView` returns a memoised empty view when the table is
  null (built directly, never through `periodTable(null)`, so no
  aggregation counter moves); `periodData` re-evaluates once `service`
  is injected. Live `call view` after a fresh open reports
  `aggregations.overlay == 0` and every chart `paints == 1`.
- The harness creates the overlay the way the shell does: `createObject`
  without `service`, then assigns it; `overlay-view.sh` asserts
  `fresh … aggregations.overlay == 0` on that path (it must fail on the
  old code — show it in the handover).
- SPEC-PLUGIN §6 and TESTING get one sentence on the injection order
  (`service` arrives after creation; bindings must tolerate null without
  work).
- Heatmap probe docs: the grid is a height-bound square grid (by design,
  legend beside it), so a fixed fraction only hits a cell at 365 d/All on
  wide screens; the README/TESTING example uses `locate(index)` or a
  point computed from `heatmapLayout`. Optional, stated as a design
  decision in the handover: centre the grid in its slot.
- Live verification on the test host (unlocked): fresh open `call view`,
  `hover`, and the two missing theme screenshots (Tokyo Night,
  Catppuccin Latte) plus one Osaka Jade, using exactly the guard-allowed
  bare form `ssh <host> 'OMARCHY_PATH=/usr/share/omarchy omarchy theme
  set "<theme>"'` — orchestrator's explicit go — with `lock status`
  before each theme change and shot, exit status read in a separate ssh
  call, Osaka Jade restored the same way; results under
  work/active/WP-037/live/.

## Acceptance tests
- `just check` exit 0; the new harness path asserts `overlay == 0`.
- Live `call view` on the test host after a fresh open:
  `aggregations.overlay == 0`, every chart `paints == 1`.
- Three theme screenshots at the host's real scale, theme restored.
