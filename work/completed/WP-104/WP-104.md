# WP-104 — State reset after a crash: no false note; doctor's prediction

Role: Engine Dev (Opus, high). 0.1.5, after WP-099. From the WP-099
reviews (stage 1 B1/N4, stage 2 follow-up 1).

## Goal

A crash after a capture appended the first events of a source it
baselined without a note no longer makes the next capture record a state
reset for that source that lost nothing; doctor's prediction after a
crashed reset says what the next capture will really do.

## Inputs

engine/src/commands/capture.rs (`held_losses`, `pending_notes`),
engine/src/collectors/mod.rs (`Cursors.pendingNotes`), the WP-099
handover and both review packets (private folder: probes P1, P2),
docs/SPEC-ENGINE.md §3 (the limitation sentence WP-099 adds),
engine/src/commands/doctor.rs (`pending_reset` row).

## Outputs

- A sibling field in cursors.json (e.g. `pendingBaselines`: the sources
  the crashed capture baselined silently), saved with the mark; the next
  capture excludes them from `held_losses`. Do not reshape `pendingNotes`
  (it ships as a string list).
- doctor: when the marked note is already in the ledger, the row says
  the next capture warns, not "will record a state reset".
- Tests: probes P1 and P2 give no false note; a genuine loss still is
  recorded; old files without the field load. SPEC §3: the limitation
  sentence removed; CHANGELOG.

## Acceptance

`just check` 0; mutants. Review: stage 1 Opus, stage 2 Fable (engine core).
