# WP-086 — Seldon's own updates are not drift

Role: Engine Dev (Opus, high). 0.1.3 wave, starts when a worker is free.
Operator observation 2026-10-05: after `omarchy plugin update jax.seldon`
the panel asked to explain a `plugin-update jax.seldon 0.1.0 → 0.1.2` by
`system` as drift.

## Goal

A change that is Seldon updating itself (the plugin `jax.seldon` added,
updated, enabled or disabled; the engine replaced by `install.sh` or the
package) is recorded as Seldon's own change and never shown as drift,
the way the engine already attributes its own installs (WP-038) and the
theme hook its own writes.

## Inputs

engine/src/collectors/plugins.rs (events, the own-clone rule near line
319), engine/src/attribution.rs and the drift rules in docs/SPEC-ENGINE
§5 (own writes, rule 7 explained-own), work/completed/WP-038/HANDOVER.md
(self-attribution of the engine's installs), engine/src/commands/capture.rs
(`explainedOwn`), docs/CONCEPT.md (what drift means), fixtures/logbook and
the plugins collector tests in engine/tests/collectors.rs, plugin/README.md
States/Changelog wording if it names drift reasons.

## Outputs

- Rule: plugin events whose subject is the plugin's own id (`jax.seldon`,
  read from one constant shared with the engine's self-attribution) get
  `actor: seldon` (or the actor WP-038 uses) and are not drift; they still
  appear in the Changelog as events. Same for the engine's own package or
  install.sh upgrade if WP-038 does not cover it yet (check; say in the
  handover which cases were already covered).
- Tests: a `plugin-update jax.seldon` capture produces an event with the
  own actor and no drift item; a `plugin-update` of another plugin still
  is drift; idempotency unchanged. Mutant per claim.
- SPEC-ENGINE §5 sentence; CHANGELOG line; the index fixture only if a
  fixture test needs it (say why).

## Acceptance

`just check` 0; mutants in the handover.
