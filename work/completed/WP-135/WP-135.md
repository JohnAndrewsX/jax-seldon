# WP-135 — `seldon decide accept`: accept a decision in one click

Ships in 0.2.0 on the integration branch `next`: branch from `next`, merge
into `next`. Operator decision 2026-10-07 (E7). The WP-127 review pointed
out that this is a new write path, so it gets its own WP.

Role: Engine Dev with a small plugin part (Opus, high).

**Goal.** In the desk's Decisions section, *Accept* on a proposed decision
writes the acceptance through the engine. Today it only opens the ADR in
the editor (WP-123, Decision 2).

**Inputs.**
- AGENTS.md §3 (a new argv row in CONTRACT.md is a contract change: say
  which rule of ADR-0035 §6 covers it, or write the ADR).
- ADR-0034 §2, ADR-0035 §6.
- The existing `seldon decide` command.
- docs/SPEC-LOGBOOK.md (decision frontmatter).
- WP-123's Decisions section and its Accept button.

**Outputs.**
- `seldon decide accept <ADR-NNNN> [--actor A] [--json]`:
  - It sets `status: accepted` with the date.
  - It writes a ledger event: kind as the SPEC fits, actor human.
  - It refuses a decision that is not `proposed`.
  - It refuses an agent actor or an agent session. Accepting a decision
    is the user's act, the B2 pattern of WP-102 and WP-124.
  - Idempotent; autocommit; index rebuilt.
- A CONTRACT.md argv row.
- The plugin's Accept arms twice, then runs the fixed argv.
- SPEC, the guides en/de, CHANGELOG.

**Acceptance.**
- `just check` is green.
- Tests: accept, refuse (not proposed, agent actor, agent session),
  idempotent.
- The harness case for Accept checks the argv.

**Dependencies.** WP-123 is on `next`; WP-127 if both touch the Decisions
detail.
