# WP-164 — Boot configuration as hashed collector sources

Ships in 0.2.x on `next`. Operator decision 2026-10-08 (S8, from the
JARVIS-LNX-RAW study). AGENTS.md §6 is amended for it: hashes only.

Role: Engine Dev (Opus, high). Small.

**Goal.** A change to the boot configuration is visible in the record even
when no agent made it.

**Do.**
- The config collector hashes, content never read into an event:
  `/etc/mkinitcpio.conf`, `/etc/mkinitcpio.conf.d/*`, `/etc/mkinitcpio.d/*`,
  `/etc/default/limine`, `/etc/limine-entry-tool.conf`,
  `/etc/limine-entry-tool.d/*`, `/boot/limine*.conf` where present.
- Unreadable files get the stat hash (ADR-0037). **First measure** on the
  test host whether any of them is rewritten without a real change (the
  WP-131 lesson: cupsd rewrote its files on every print job); if one is,
  leave it out and say so.
- Class: per ADR-0028/ADR-0042 (boot files: a change outside a case is at
  least attention; say whether crisis applies).
- Tests: hash-only, stat hash, add/remove, idempotent; SPEC §2/§4, guide 06,
  CHANGELOG.

**Acceptance.** `just check` green; on the test host an edit of a drop-in
gives one event at the next capture and nothing else changes it.
