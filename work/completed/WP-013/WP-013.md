# WP-013 — Engine ↔ plugin integration test on a real logbook

## Goal
One script proves the whole chain on a real machine: `seldon init` →
`capture` → `index`/`status` → the shell's plugin reads the index and
shows it. Documented so the orchestrator can run it unattended before
every phase exit.

## Inputs
docs/PLAN.md (Phase 0/1 exits), docs/TESTING.md, docs/HERDR-SETUP.md §5,
docs/CONTRACT.md, work/completed/WP-{007,010,011,012}/HANDOVER.md (smoke
procedures, IPC targets `jax.seldon.service` / `jax.seldon.panel view`,
fake-engine harnesses), engine/ and plugin/ on main.

## Outputs
- `tests/integration/e2e.sh`: on the **test host** over ssh (alias from
  the orchestrator's git-ignored memory, never committed): build the musl
  engine on the dev host, copy it to `~/.local/bin` there, `seldon init
  --non-interactive --path ~/Seldon-e2e`, `seldon capture --all`,
  `seldon plan new/start`, `seldon log`, `seldon status`; rsync the plugin,
  validate, restart the shell; read `jax.seldon.service status` and
  `jax.seldon.panel view` (status `ok`, pill counts match `index.json`,
  Today shows the note, Changelog shows the capture events); QuickEntry
  through IPC/`wtype` writes a note that appears after the FileView
  refresh; then restore the test host (logbook, binary, index, config,
  plugin state as found). Exit 0/1 with a summary; idempotent.
- A dev-host variant that stops before the shell steps (`--engine-only`),
  with scratch XDG dirs, so it also runs here.
- `docs/TESTING.md`: an "Integration" section; `justfile`: `e2e` recipe
  (host-only, skipped under `SELDON_SKIP_HOST_CHECKS`).
- Findings as `work/active/WP-013/FINDINGS.md`: every mismatch between
  engine output and plugin display, with the exact command and the index
  excerpt.

## Acceptance tests
- `just e2e` exits 0 on the dev host (engine-only) and on the test host
  (full), with the summary printed and the hosts restored.
- The test runs twice in a row without manual cleanup.
- At least these assertions: pill text equals the index counts; `today`
  contains the logged note; the capture produced ≥ 1 pacman event on the
  test host; `state.status == "ok"` in the plugin after `status`;
  `quickshell log` clean of jax.seldon errors.

## Constraints
Read-only on both hosts except the Seldon paths the script creates and
removes (`~/Seldon-e2e`, `~/.local/bin/seldon`, `~/.local/state/seldon`,
`~/.config/seldon` — the guard allows the last one over ssh only) and the
plugin dev install. Never the dev host's real `~/.config` or state dirs.
Model opus, effort medium (ORCHESTRATION.md §12 QA row).
