# WP-136 — Plugin updates name their incoming commits

Ships in 0.2.0 on the integration branch `next` (branch from and merge into `next`). Operator decision 2026-10-07 after the comparison with the Omarchy plugin "What changed" (nejcc.what-changed, MIT). The idea is taken, not its code: write our own.

Role: Engine Dev with a small plugin part (Opus, high). Small. Order: W2, the first of four.

**Goal.** A `plugin-update` event of a git-installed plugin says what came
in: the subjects of the commits between the old and the new HEAD.

**Inputs.**
- WP-113's plugin collector (tree hash, `plugin-update`, rule 8).
- SPEC-ENGINE §4 and §7 (redaction).
- ADR-0025 (clip).
- The desk's event detail (WP-122).
- ADR-0038 if the index needs a field.

**Outputs.**
- The plugins collector reads, read-only, `git log --format=%s OLD..NEW`
  (or the reflog) of `~/.config/omarchy/plugins/<id>`. It runs `git` with
  a fixed argv and `-C`, with no hooks, no pager, no network, and
  `GIT_CONFIG_NOSYSTEM`, and is bounded in time and in count.
- At most 20 subjects, redacted and clipped, in `meta.commits`. Detail:
  `N commits: <first subject> …`.
- Install by clone, update by pull, and rollback by reset are named as
  such.
- The plugin shows the list in the event detail as plain text.
- Tests use a fixture plugin repo built in a temp HOME: update, rollback,
  non-git plugin (no list), a hostile subject (control characters, a
  secret), and a timeout.

**Acceptance.**
- `just check` is green.
- The capture-cost delta is measured.
- No network.
