# WP-035 — `seldon dossier`: generated fences in system/*.md and the pre-logbook package list

## Goal
The dossier (`system/*.md`) is written by the engine, not only read.
`seldon rebuild` can then list the explicit packages that predate the
logbook, which closes the one gap the WP-032 review found against the
definition of done in PROJECT.md ("a fresh Omarchy install can follow
outputs/REBUILD.md").

## Inputs
docs/SPEC-ENGINE.md §3 (`seldon dossier [--section …]`, unimplemented
until now) §4 §6, docs/SPEC-LOGBOOK.md §3 "Dossier" (fence rules, text
outside fences is user-owned), fixtures/logbook/system/*.md (the fence
names in use: `packages.summary`, `packages.history`, `services.enabled`,
`plugins.list`, `omarchy.summary`, `hardware.summary`, `deviations.table`),
engine/src/index/load.rs (`fences`, `fence_kv`, `fence_table`),
engine/src/index/views.rs (fence merge; the WP-032 review asks for one
shared `merge_fence(name, …)` with two callers), engine/src/rebuild/
(WP-032; §2 "explicit packages"), engine/src/collectors/{plugins,omarchy}.rs
(the CLI readers to reuse), work/completed/WP-032/HANDOVER.md (review
items 6 and 7), memory/rust-notes.md, memory/pitfalls.md.

## Outputs
- `seldon dossier [--section packages|services|omarchy|plugins|deviations|all] [--json]`:
  rewrites only the named fences in `system/*.md` (`all` by default),
  keeps everything outside the fences, writes atomically and only on
  change, autocommits `seldon: dossier`, no ledger write. Exit codes per
  SPEC-ENGINE §3 (3 not initialised, 4 lock held).
  - `packages.summary` (explicit/total/aur counts), `packages.history`
    (append today's row when counts changed), and a new
    `packages.explicit` fence: the sorted list of explicitly installed
    packages with repo/AUR origin, one line per package, each marked
    `since <date> [[C-…]]` when the ledger knows the install, otherwise
    `pre-logbook`. Data source: `pacman -Qqe`, `-Qqm`, `-Q` read-only
    queries (SPEC-ENGINE §4 gets one line: the dossier queries pacman
    read-only; no package manager is ever invoked with a mutating verb).
  - `services.enabled`: `systemctl list-unit-files --state=enabled` for
    user and system scope (read-only), case column from the ledger.
  - `plugins.list` and `omarchy.summary` from the existing collector
    readers; `hardware.summary` from `/proc`, `lscpu`-free (read files
    only: cpuinfo model, meminfo total, `/sys/class/dmi/id/product_name`
    when readable, root filesystem type from `/proc/mounts`).
  - `deviations.table`: rows for config events whose case is known (the
    SPEC already says so); existing rows and the user's reason text are
    kept, keyed by path.
- `seldon rebuild` §2 gains a "### Before the logbook" group listing the
  `pre-logbook` packages from the `packages.explicit` fence (as
  `omarchy pkg add …` lines, AUR separately), so the document is complete.
- `index/views.rs`: the shared `merge_fence` (review item 6).
- `init` runs `dossier` once after the first capture (behind the existing
  `--no-capture` switch); `capture` does not (ADR-0005 stays: the dossier
  refresh is explicit or via `status`? — no: only `init` and `dossier`;
  record the choice in the handover).
- Tests through `common::Env` with `SELDON_TEST_GUARD`: pacman and
  systemctl are shimmed by scripts on a test `PATH` (fixtures/logs/
  gets `pacman-Qqe.txt` etc.); fence rewrite keeps user text; idempotent
  second run writes nothing; golden REBUILD.md updated for the new group;
  `--json` shape `{files, sections, warnings}`.
- Docs: SPEC-ENGINE §3 line for `dossier`, §4 one line, SPEC-LOGBOOK §3
  fence list, docs/TESTING.md, CONTRACT.md only if a schema field changes
  (none expected).

## Acceptance tests
- `just check` exit 0.
- On the fixture logbook with shimmed queries: all seven fences written,
  user text outside fences byte-identical, second run "nothing changed".
- `seldon rebuild` golden contains the "Before the logbook" group with
  every `pre-logbook` package; the WP-032 trace test still passes.
- A real-host read-only run on the dev host (scratch logbook copy, XDG
  redirected) completes and lists this host's explicit packages; nothing
  under the real `~/.config` or `~/.local/state` is touched.

## Constraints
Read-only host queries only (AGENTS.md §6); never run a package manager
or `systemctl` with a mutating verb — the guard blocks it and a block is
reported, never worked around. No new crates. Keep to engine/src/
{commands/dossier.rs, dossier/, rebuild/, index/views.rs}, tests, docs.
