# WP-199 — init returns only when its git work is done

0.2.x. From the WP-193 handover (2026-10-10): a doctor test that removes
the logbook's `.git` right after `seldon init` flaked once under the full
parallel run ("something still wrote into `.git` while it was being
removed"); it passed alone 10/10.

Role: Engine Dev. Small. Reviewer: Opus.

**Do.** Find whether `init` (or its autocommit) leaves a `git` child
running after the command returns (spawned and not waited for, or a
detached `git gc --auto`/maintenance). If so, wait for every child before
returning, and pass `-c gc.auto=0 -c maintenance.auto=false` to the
engine's git calls so git never forks background work into the logbook.
If not, make the test robust (retry the removal) and say why. A test that
asserts no `git` process with the logbook as cwd survives `init`.

**Acceptance.** The doctor test passes 50/50 under `just check`'s
parallel load; `just check` green; evidence words in the handover.

**Inputs.** `engine/src/logbook/git.rs`, `engine/src/commands/init.rs`,
the doctor tests; WP-175 (the git gate before every call).
