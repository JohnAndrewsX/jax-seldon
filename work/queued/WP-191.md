# WP-191 — CI runs the plugin's checks, stage 2: Quickshell against a pinned Omarchy shell tree

0.2.y. Origin: study of Tom Ballard's Omarchy work (2026-10-09,
`jax-seldon-private/study-tcballard/`), operator decision E66 (stage 2,
with a small ADR). Ideas only, no code taken.

Role: QA / Scaffold (Opus, high for the harness port). Medium.
Reviewer: Opus; Fable stage 2 (the ADR and the test model). ADR: proposed
by this WP, accepted by the operator before the CI change merges.

**Problem.** After WP-190, CI runs the node tests and the validator but no
QML: `qmllint`, `check-tokens.py` and the offscreen Quickshell harnesses
(`tests/plugin/service-states.sh`, `desk-view.sh`, `bar-view.sh`,
`ipc-restart.sh`) need `$OMARCHY_PATH/shell` and Quickshell, so they run
only on the dev host. WP-183b's readability report is specified "in CI"
and cannot run there today.

**Goal.** CI runs the plugin's QML checks against a pinned copy of
Omarchy's shell tree, and that copy is defined as a mirror of the test
host's installed tree — never a second reference.

**Do.**
- **ADR (proposed), "A pinned Omarchy shell tree in CI":** the pin in
  `packaging/omarchy-pin` (WP-190) names the commit that matches the test
  host's installed Omarchy; CI uses it only to repeat checks the dev host
  already runs; where CI and the test host disagree, the test host wins
  and the pin is refreshed (AGENTS.md §1, "code is truth"); how the pin is
  refreshed after an `omarchy update` (with WP-194's notice); what CI
  never claims (layer-shell geometry, live IPC with the real shell,
  monitors).
- CI job (a separate job in `ci.yml`, so stage 1 stays fast): a sparse
  checkout of `shell/` at the pin (verify the path and that the tree is
  self-contained); install `quickshell` and `qt6-declarative` in the Arch
  container and print their versions to the log. If Quickshell is not in
  Arch's official repositories, the ADR names the source and how it is
  pinned; no AUR build in CI without that ADR line.
- Run with `OMARCHY_PATH=<checkout>`: `just qmllint` (including
  `check-tokens.py`) and the four harnesses, each process with its own
  `HOME` and its own 0700 `XDG_RUNTIME_DIR` removed afterwards (AGENTS.md
  §6). The harnesses' merge-base skip does not apply in CI (they always
  run).
- Omarchy's own QML text-format scan, if present at the pin (the study
  reports `test/shell.d/qml-text-format-scan.py`; verify the path), run on
  `plugin/`.
- `docs/TESTING.md`: "what CI runs" updated; the evidence word for these
  results is *CI*, never *test host* (AGENTS.md §5).

**Acceptance.** The four harnesses and qmllint green in CI with the
Quickshell and Qt versions in the log (CI); a mutant QML (a hard-coded
colour, a broken `Text` binding) turns CI red (CI); the dev-host gate is
unchanged (fixture, headless); the ADR accepted before merge.
