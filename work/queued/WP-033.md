# WP-033 — `seldon update-impact`: local migrations plus optional release notes, no network

## Goal
`outputs/UPDATE-IMPACT.md` tells the operator which of their deviations an
Omarchy update touches — from what is available on the machine, without
the engine ever using the network (AGENTS.md §7). Operator decision
2026-10-02: option C (local sources plus an optional notes file).

## Inputs
docs/PLAN.md WP-033 row (written for a git checkout; Omarchy 4 is a
package, `omarchy-version` reports e.g. `4.0.4-1`, `/usr/share/omarchy/
version` is unreliable), `$OMARCHY_PATH/migrations/*.sh` (timestamped
migration scripts, 106 on 4.0.4-1 — each names the paths it changes),
the pacman log (`omarchy` package upgrades, already captured as events),
fixtures/logbook/system/deviations.md (`deviations.table`),
engine/src/rebuild/ (document generation pattern: fence, only-on-change,
autocommit), engine/src/dossier/query.rs (read-only query pattern and
shims), docs/SPEC-ENGINE.md §3 (`update-impact` line), docs/SPEC-LOGBOOK.md
§3, memory/host.md.

## Outputs
- `seldon update-impact [--target VERSION] [--notes FILE] [--json]`:
  - **Local sources:** the migration scripts newer than the installed
    version's last migration (by timestamp; the installed version's
    migration set is recorded in the dossier `omarchy.summary` as
    `migrations: <count>/<newest>` on each dossier run), the paths and
    commands they mention (grep for `~/.config/...`, `$HOME/...`,
    `/etc/...`, `omarchy-*` helpers), and the package file list of the
    installed `omarchy` package (read-only query, shimmed in tests).
  - **Optional notes file:** `--notes FILE` with release notes the
    operator saved (Markdown or plain text); paths and package names in
    it are matched the same way. Absent → section says so.
  - **Matching:** every `deviations.table` row and every cased config
    path against the touched paths (exact, prefix and glob from the
    migration text); a hit lists the deviation, its case and the
    migration or note line that touches it; per-row verdict
    `touched | likely | clear`.
  - Output `outputs/UPDATE-IMPACT.md` (fence `update-impact`, text
    outside kept, atomic, only on change, autocommit `seldon:
    update-impact`; English headings, prose in the logbook language);
    sections: 1 installed vs target, 2 migrations considered, 3
    deviations touched, 4 notes matched, 5 how to proceed (`omarchy
    update`, then `seldon capture --all`, `seldon drift`).
  - `--json` → `{path, installed, target, migrations: {considered,
    newest}, deviations: {touched, likely, clear}, notes: {file, lines
    matched}|null, files, git, warnings}`.
- After the update: `seldon capture` already records the upgrade;
  `update-impact` run again reports what changed (same report, post-hoc
  wording).
- Tests via common::Env with shimmed queries and a fixture migrations
  dir under fixtures/logs/omarchy-migrations/; golden
  engine/tests/golden/UPDATE-IMPACT.md; docs: SPEC-ENGINE §3 line,
  TESTING.md, SPEC-LOGBOOK §3 outputs list.

## Acceptance tests
- `just check` exit 0; golden byte-identical on the fixture; second run
  "nothing changed".
- No network code path (grep for reqwest/ureq/curl: none); the engine
  never writes outside the logbook.

## Constraints
No new crates; read-only host access only; a guard block is reported,
never worked around. Scheduled after the AUR publication.

## Added 2026-10-07 (operator P2, from the study of the predecessor "Omar")

Two more read-only lists in the update-impact result:
- **Overrides that hide a changed Omarchy default.** For every file under
  the user's `~/.config` that has a counterpart under
  `$OMARCHY_PATH/config`, compare the default's hash before and after the
  update. Hashes only: the old default's hash comes from the dossier or
  the capture's evidence. List the user files whose default moved.
- **Completed cases to re-check.** These are cases whose area or touched
  paths the update changed, each with its verification lines from the
  case file. They are listed only; the engine never runs them.
