# WP-144 — Persistence and default-app paths JARVIS hit

Ships in 0.2.0 on the integration branch `next` (branch from and merge into `next`). Source: the study of the second predecessor "JARVIS" (private, in the orchestrator's notes; never in this repository). Operator decision 2026-10-07. (J1)

Role: Engine Dev (Opus, high). Small, but it needs an ADR amendment first.

**Goal.** Seldon sees the paths a real machine changed without anyone
noticing.

**Paths.**
- **Watched paths (attention):** `~/.zprofile`, `~/.zshenv`,
  `~/.zlogin`, `~/.config/mimeapps.list`,
  `~/.config/xdg-desktop-portal/`.
- **`alwaysRedPaths` (crisis):** `~/.local/share/dbus-1/services/` and
  the zsh login files (`~/.zprofile`, `~/.zshenv`, `~/.zlogin`), which
  run at login like `~/.profile`.

**How.**
- An ADR-0028 §4d amendment: a short ADR, `proposed`; the operator
  accepts it.
- The earlier-defaults upgrade mechanism (WP-109), so existing installs
  gain the paths at the next capture without noise.
- Tests for each path's class, and that the upgrade is silent.
- SPEC §2/§4, guide 06 en/de, CHANGELOG.

**Dependencies.** WP-113 on `next` (it changes the same default lists).
