# WP-225 — Omarchy-owned files on edge (B9, B10, B12, B13, B15)

A 0.4.x patch for 0.4.1. Found in the E92 edge survey (2026-10-14).

Role: dev (Opus). Reviewer: Opus.

**Problem.** Omarchy edge writes new files of its own that Seldon reads as
unexplained user changes: `~/.config/omarchy/language`,
`~/.config/uwsm/env.d/50-omarchy-language`, `~/.config/omarchy/defaults/*`
(B9), and the crash mutes `~/.local/state/omarchy/toggles/crash-ignore/<name>`
plus `toggles/crash-capture-off` (B10; `omarchy_copies()` maps them to a
path that never exists). Omarchy now links its own skills into
`.gemini/config/skills` (B15), which `SKILL_DIRS` lacks. `omarchy pkg add`
logs `pacman -S --noconfirm --needed -- pkgs` (B13), and the floating
terminal now prints "Failed! (code)" for a non-zero exit (B12).

**Do.** Classify the B9/B10 paths as Omarchy-owned routine changes with
attribution (`omarchy language`, `omarchy crash mute`); paths and mtimes
only, no hashes under `~/.config` (E41). Add `.gemini/config/skills` to
`SKILL_DIRS`. Add pacman.log fixtures with the `--` form. Update docs and
tests that expect "Done!" so "Failed! (code)" is described honestly.

**Acceptance.** A unit test per path (routine, attributed); a second
capture emits 0 events; the skills install test covers the new dir;
B13 fixtures parse; `flock /tmp/seldon-check.lock env SELDON_FULL_CHECK=1 just check`
green on the dev host (edge). Stay out of WP-224's files (the always-red
family in `config.rs`/`drift.rs`, `collectors/omarchy.rs`, the two QML ids,
the assumption ledger).

**Inputs.** AGENTS.md (§6 E41); private `audit-e92/01-edge-survey.md`
(B9, B10, B12, B13, B15); `engine/src/collectors/config.rs`,
`engine/src/commands/skills.rs` (or where `SKILL_DIRS` lives), `pkgcmd.rs`.
