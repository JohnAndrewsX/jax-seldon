# WP-200 — the engine keeps index.json under its budget

0.2.x. From the WP-126a review (2026-10-10, F4, Q-A): from 0.2.0 the
plugin refuses an `index.json` of 1 000 000 characters or more before
`JSON.parse` (E72; CONTRACT.md rule 5, < 1 MB) and shows "Index
unreadable" with *Build index*. The engine only warns above the budget
and still writes the file (`engine/src/index/build.rs`), so on a very
large logbook *Build index* writes the same oversized file and the desk
stays on the banner.

Role: Engine Dev (Opus, high). Reviewer: Opus, then Fable (contract).

**Do.** Decide with an ADR how the engine stays under the budget: which
lists are trimmed first and how the index says so (a field the plugin
already reads, or an optional contract-2 field per ADR-0035 §6 and
ADR-0051), so a released 0.2.0 plugin never sees an oversized index and
never counts fewer crises. Measure the largest section on the ×150
fixture and on a synthetic worst case. `seldon status` names the largest
section (already in 0.2.0's message).

**Acceptance.** A test builds a logbook whose untrimmed index would pass
1 MB and proves the written index stays under it, every crisis still
counted; the plugin's headless `index-oversized` case still passes;
`just check` green; evidence words in the handover.

**Inputs.** CONTRACT.md rule 5; `engine/src/index/build.rs`;
`plugin/Model.js` (the size check), `plugin/Service.qml`;
`jax-seldon-private/review-0.1.1/handovers/WP-126a-review-1.md` (F4);
ADR-0035, ADR-0051.
