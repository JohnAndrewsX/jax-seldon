# WP-159 — Secrets split by a zero-width character get past redaction

Ships in 0.2.x unless the reviewer of this WP finds it reachable from the
plugin before the 0.2.0 tag. Security; stage 2 Fable.

Role: Engine Dev (Opus, high). Small to medium.

**Observed** (WP-102b review 1, N5). A secret split by a zero-width or
other format character (`to<U+200B>ken=…`, `Bearer<U+200B> …`,
`ghp_0123<U+200B>4567…`) is not matched by the redaction patterns, so it
reaches the case file through `import task`, and an event body through
`seldon log`. WP-140 chose "a note keeps them" for invisible code points;
WP-143 strips them only in the commit subject.

**Do.**
- Decide with the reviewer, and write it in the handover, which of these
  holds engine-wide: (a) redaction matches on a copy with the
  `is_direction_or_format` characters removed and masks the original span;
  (b) those characters are removed before redaction everywhere user text is
  written; (c) both.
- Keep WP-140's promise that a note's visible text is unchanged where no
  secret is found.
- One shared helper used by `log`, `import task`, the closing summary and
  any other writer of free text.

**Acceptance.**
- Tests: each of the three examples above is masked in the event body, the
  case file and the commit subject.
- A text with a zero-width character and no secret is written unchanged
  (or as decided in the handover).
- `just check` green; mutants on the helper are killed.
