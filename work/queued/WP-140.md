# WP-140 — Redaction: PEM private keys and more invisible code points

Ships in 0.2.0 on the integration branch `next`: branch from `next`, merge
into `next`. Source: the stage-1 review and the Fable stage 2 of WP-127
(2026-10-07).

Role: Engine Dev (Opus, high). Small.

**Goal.**
1. A PEM private key block (`-----BEGIN … PRIVATE KEY-----` …
   `-----END … PRIVATE KEY-----`, including OPENSSH, RSA, EC and
   ENCRYPTED) is redacted whole, in every path through `Redactor`.
2. The invisible and format code points that can split a token from its
   rule are dropped before redaction, as U+200B already is. The list:
   - U+00AD, U+061C, U+180E;
   - U+2061–U+2064, U+206A–U+206F;
   - U+FFF9–U+FFFB;
   - U+E0000–U+E007F.

   This applies in `import::is_direction_or_format` and in the index
   texts' Cf drop.

3. A header value that starts with a double quote is redacted:
   `Authorization: "Bearer x"` and `x-api-key: "…"`. Today these leak, on
   the base too (WP-128 Fable stage 2).
4. Merged markers: a built-in match whose masked part is only markers is
   left as it is, so a second pass with a user pattern that eats a gap
   gives the same text (WP-128 decision 5).

5. Plain-argument secrets on privileged lines (WP-129 Fable stage 2):
   `nmcli … password|psk|wifi-sec.psk|802-1x.password X`,
   `echo u:pw | chpasswd`, `htpasswd -b`, `smbpasswd`,
   `usermod -p` / `useradd -p`, `cryptsetup` with a key on the line.
   Recommended route: a hook-local list in WP-129's `-S` style (the whole
   line becomes `<program> ‹redacted›`), no `redact.rs` change; plus §7
   rules where a general rule is cheap. **0.2.0 is tagged only with this
   WP merged** (operator to confirm, E17).

**Inputs.**
- docs/SPEC-ENGINE.md §7.
- `engine/src/redact.rs`, `engine/src/import/mod.rs`.
- ADR-0038 (the dropped set it names).
- CONTRACT.md.
- WP-128 (CRLF), if on `next`.

**Outputs.**
- The PEM rule, with LF and CRLF, and with the block cut by a clip.
- The extended set.
- Tests per code point.
- A redaction bench within budget.
- SPEC §7 and the ADR-0038/CONTRACT lists updated (a wording follow-up of
  an accepted ADR goes in as an amendment note).

**Acceptance.**
- `just check` is green.
- `just check-perf` redaction is within budget.
- A mutant per rule fails a test.
