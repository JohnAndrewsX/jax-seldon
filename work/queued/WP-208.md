# WP-208 — the plugin marks a transaction partial by its own rows

A 0.3.x patch, plugin only. From the WP-203 stage-2 review (2026-10-12, F2;
ADR-0054 §3). The 0.2.0 plugin infers that a pacman transaction is only
partly in the index when the transaction holds the list's last event
("newest 500"). Since WP-203 the 500 events are every listed drift
item's event plus the newest of the rest, so an old pinned event can
follow the boundary transaction and the detail reads "24 packages: 24
upgraded" for a transaction of 40.

Role: Plugin Dev (Opus, medium). Reviewer: Opus.

**Do.** `partial` holds when the transaction holds the oldest event that
is not a pinned leader, or its leader is older than that event, or the
rows it lists are fewer than the drift item's `members` count. Texts
that say "the newest 500 events" say "500 events". The exact rule is
drafted in `work/completed/WP-203/HANDOVER.md` (open question 4); follow
it or say why not. No engine, schema or fixture-contract change.

**Acceptance.** Model tests for the three cases (boundary transaction,
leader older than the oldest non-pinned event, rows < `members`) and an
untouched whole transaction; the 0.2.0 counter-example from the WP-203
review reads partial; headless desk-view unchanged; `just check` green;
evidence words in the handover.

**Inputs.** `plugin/Model.js` (`transactionDetail`, `groupMembers`);
CONTRACT.md rule 4; ADR-0054; private
`review-0.1.1/handovers/WP-203-stage2-fable.md` and
`gates/rv-203/probe-tx.js`.

Depends on: WP-203 merged into `next`.
