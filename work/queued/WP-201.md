# WP-201 — a crisis inside a triage proposal by key

0.2.x. From the WP-126c review (2026-10-11, item 4): since WP-126c the
triage proposal opens and applies by key (↑ from the first Changelog row,
Enter twice), but each crisis inside the proposal still has only its own
"Apply this crisis" button, so it needs a click. By key a crisis is
resolved from its own row (Link, Explain, Dismiss), where the user retypes
the resolution instead of accepting the agent's evidence.

Role: Plugin Dev (Opus, medium). Reviewer: Opus, then Fable (a write made
as the user).

**Do.** Inside an open proposal, ↓/↑ walk its crises; Enter twice applies
the one under the cursor with `seldon drift apply <proposal> --item <id>`
(the existing per-crisis path), one crisis at a time (ADR-0028 §3,
ADR-0036); the arm follows SPEC-PLUGIN §5.3 and disarms on any move or a
replaced proposal (the WP-126c F2 rule). The hint line names the keys.

**Acceptance.** model.test.js and a headless desk-view case apply one
crisis by key, the others stay; a replaced proposal never applies; the
case fails on the old code; `just check` green; evidence words in the
handover.

**Inputs.** `plugin/sections/Changelog.qml`,
`plugin/components/desk/TriageDetail.qml`, `plugin/Model.js`; SPEC-PLUGIN
§5.3; WP-124, WP-126c;
`jax-seldon-private/review-0.1.1/handovers/WP-126c-review-1.md`.

**Also (WP-126c review round 2).** A test for the A→B→A case: A armed,
B replaces it, B is discarded elsewhere before any key, A is current
again — the arm must not come back (`TriageDetail.qml` `onCurrentChanged`
handles it today; no test covers it).
