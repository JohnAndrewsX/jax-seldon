# WP-194 — What Seldon assumes about Omarchy, checked offline

0.2.x. Origin: study of Tom Ballard's Omarchy work (2026-10-09,
`jax-seldon-private/study-tcballard/`), operator decision E69 (offline
only, no cron, no network). Ideas only, no code taken.

Role: Plugin Dev (Opus). Small. Reviewer: Opus. No ADR.

**Problem.** The plugin builds on Omarchy internals that are not a public
API: `updateEntryInline` (behind a silent `typeof … === "function"` guard,
`plugin/Desk.qml:383-391`), `pickDrawnSlot`, `bar.moduleWidgets`, the
`shell` IPC table, the `shell.json` rules, the `qs.Ui` controls and
`Style` tokens (docs/SPEC-PLUGIN.md §8, `memory/omarchy-shell.md`). After an
`omarchy update` nothing tells the team which of these to re-measure; a
silent fallback is the likely failure.

**Goal.** About ten installed Omarchy files are listed with a hash and one
sentence each naming the Seldon line that relies on them; after an
`omarchy update` a check says which assumptions to re-measure. A notice in
`just check`, a gate only at release.

**Do.**
- `tests/omarchy/assumptions.json`: per entry the path relative to
  `$OMARCHY_PATH` (candidates: `shell/services/PluginShellApi.qml`,
  `shell/shell.qml`, `shell/Ui/PluginBarApi.qml`, `shell/Ui/BarWidget.qml`,
  `shell/plugins/bar/Bar.qml`, the `shell/Ui/` controls the plugin uses,
  `shell/Commons/` token files, `bin/omarchy-plugin-update`,
  `bin/omarchy-plugin-validate`, `shell/README.md` — confirm each by a
  `grep` of what the plugin really calls), its sha256, the Omarchy version
  it was measured on (`omarchy version`), and one sentence: "Seldon relies
  on … at `plugin/<file>:<line>`". No content copied from Omarchy.
- `scripts/check-omarchy-assumptions.sh` and `just check-upstream`: hash
  the installed files read-only; on a mismatch print each affected
  assumption and what to re-measure; exit 0 with a notice by default,
  exit 1 with `--gate`. Missing `$OMARCHY_PATH` (CI): "skipped", never
  "passed".
- `just check` runs it in notice mode on hosts with Omarchy; WP-190's pin
  file is compared with the installed validator's hash, and a difference
  is part of the notice ("CI validates with another validator").
- Release gate: WP-126 and WP-188 run it with `--gate` on the test host
  before the live check; a mismatch is re-measured and the ledger updated
  in the same commit (hash and sentence), never silenced. The result goes
  into the WP-192 record's `limitations` when anything stays open.
- `memory/omarchy-shell.md`: a dated "assumptions" header pointing to the
  file. `docs/TESTING.md`: one paragraph.
- Not in scope: a network check, a cron or weekly job, a check on push.

**Acceptance.** A changed file in a scratch copy of `$OMARCHY_PATH`
produces the notice naming the assumption, and `--gate` refuses (fixture);
the ledger matches the dev host's installed tree (desktop, read-only) and
the test host's (test host); a missing `$OMARCHY_PATH` prints "skipped"
(fixture, CI); `just check` green.

**Inputs.** AGENTS.md §1, §5, §6 (read-only); docs/SPEC-PLUGIN.md §8, §9;
`memory/omarchy-shell.md`; `plugin/Desk.qml`, `plugin/Service.qml`,
`plugin/BarWidget.qml`; `$OMARCHY_PATH/shell/` (read only);
`packaging/omarchy-pin` (WP-190); `justfile`; the omarchy skill
(`plugins.md`) and `omarchy commands --json` (`omarchy version`, `omarchy
plugin update`); the study: FINDINGS.md §1.4, §5.2 item 5, HANDOVER.md
(WP-191 draft), debate/judgement.md verdict 5 and "Where I overrule" item
3; Tom's pattern for reference only:
`build-omarchy-plugins/contracts/upstream-contracts.json`.

**Dependencies.** WP-190 (the pin file). Before WP-188's gate; usable by
WP-126 if it lands first, otherwise WP-126 records "not run".
