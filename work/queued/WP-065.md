# WP-065 — views and ledger: robust fences and per-line decoding

Role: Engine Dev (Opus, high). Size: M. Wave: 3. Depends: WP-062
(`ledger.rs`). Findings: F-130, F-131, F-132 (engine part; the doctor
line count is WP-070).

## Goal

User text can neither grow nor erase the generated views, and one bad
byte in a ledger month no longer stops `index`, `status` or `capture`.

- **F-130** — every value written into a fence (index/views.rs ~283-293,
  ~347-352, ~431-440) has `<!-- seldon:` neutralised (e.g. a zero-width
  break or an entity — choose one that renders the same in Obsidian).
- **F-131** — `write_status`/`merge_fence` (~371-405) use the existing
  `fence_damaged` check: a damaged or missing fence → skip with a
  warning, file unchanged; `\r\n` line ends are accepted.
- **F-132** — `ledger.rs` (~98-108) reads a month as bytes and decodes
  per line; an undecodable line is skipped and counted; `index/load.rs`
  (~82-91) passes the count on as a warning in `--json`/stderr. Expose
  the count so WP-070 can report it in `doctor`.
