# WP-184 — Contract 3: one bump for every 0.3 field

0.3. From the prototype 0.3 debate
(`jax-seldon-private/prototype-0.3/debate-2026-10-09/`, SYNTHESIS.md §3
NEW-9; item C9(b), B6's fields); operator decisions E55 (forward
compatibility first, WP-176), E57 (crashes never colour the bar), E42.

Role: Engine + Plugin Dev (Opus, high). Medium schema/fixtures/validator,
medium engine, medium plugin. Reviewer: Opus; Fable stage 2 (contract).
ADR: "Contract 3" (Fable writes, next free ADR number; the operator
accepts) — the bump, the field list with the v2-readability
justification per field, the 0.3 pre-tag window, the lockstep release.
It cites the crashes ADR (WP-185), the reports ADR (WP-186) and the
recipes ADR (E10).

**Goal.** One `contractVersion` bump 2 → 3 that carries every 0.3 field;
engine and plugin at 3 in one merge; a released 0.2.0 plugin keeps
reading through `contractReadableFrom` (WP-176).

**Do.**
- `schema/`: source/collector `journal`; event kind `crash`; timeline
  kind `crash` (never `crisis`); `crashes[]` (one row per executable,
  WP-185); `reports[]` mirroring `decisions[]` (no body or history in the
  index, WP-186); a `recipe` pointer like `triage` (E10); folded
  `resolvedAt`/`resolvedBy` on dismissed drift (B6, WP-180); the
  `diagnosis` pointer of WP-149 and the fields of WP-145 and WP-165 if
  they missed the contract-2 window; a field for "this machine has no
  snapper" that replaces the plugin's match on the collector message
  `snapper is not installed` (CONTRACT.md rule 10, from WP-119).
  Case-style names (`filed`, `closed`,
  `case`, `report`). A structured `correlation {eventId, kind, subject,
  minutesBefore}` — no prose (SYNTHESIS §7.11).
- The ADR lists per field why a v2 reader does not misread it; only then
  does the engine write `contractReadableFrom: 2`. A field a v2 plugin
  keys on and would misread forces `readableFrom: 3`, said in the ADR.
- `fixtures/index.sample.json` renders every new surface;
  `scripts/validate-fixtures.py` and the reference derive follow;
  docs/CONTRACT.md; `engineMin` names 0.3.0; the 0.3 pre-tag window as
  ADR-0035 §6.
- Plugin 0.3 reads v2 and v3 indexes (the v2 fixture stays as a test).

**Acceptance.** The fixture validates and renders every new surface
(`desk-view.sh`); `seldon index --check` passes; plugin tests read a v2
and a v3 index; the 0.2.0 plugin's model test reads the v3 fixture with
status ok and the crisis colour (WP-176's tolerance test, re-run); engine
writes `readableFrom: 2` with the ADR's justification cited in the code
comment; fixture edits serialised with WP-185 and WP-186 (the fixture
drift lesson); `just check` green.

**Inputs.** AGENTS.md §3; docs/CONTRACT.md; `schema/*.json`; `fixtures/`;
`scripts/validate-fixtures.py`; ADR-0035, ADR-0038, WP-176's ADR;
SYNTHESIS §1 C9, B6, §4 items 5–7, §7 items 11, 12; the G3 papers
(`G3-devil.md` C9 section); FEEDBACK 5, 13, 37; WP-145, WP-149, WP-165.

**Dependencies.** WP-176 in 0.2.0. The crashes ADR (WP-185), the reports
ADR (WP-186) and the recipes ADR accepted before this ADR. Before WP-185's
and WP-186's builds. WP-187 can start in parallel (no contract).
