# WP-004 — Collectors: pacman, snapper, omarchy

## Goal
The three system-level collectors produce ledger events idempotently from
real logs and commands, with persistent cursors and redaction.

## Inputs
docs/SPEC-ENGINE.md §4 §5 §7, docs/CONTRACT.md, schema/event.schema.json,
fixtures/logs/ (pacman.log with rotation and malformed lines, snapper.json),
memory/host.md (§ "Where the kit's assumptions differ": omarchy is a
package install, `omarchy-version`, snapper permissions).

## Outputs
- `engine/src/collectors/{mod,pacman,snapper,omarchy}.rs` with `fn collect(ctx) -> Vec<Event>` and cursors in `~/.local/state/seldon/cursors.json`.
- pacman: byte offset + inode cursor, rotation restart with dedupe by `(ts, kind, subject, version)`, transaction grouping (`txId`), `meta.command` from the `[PACMAN] Running` line, `explicit` vs dependency.
- snapper: `snapper --jsonout list` → `snapshot` events; pre/post pairs via `meta.pairOf`; graceful degradation when the command fails with "No permissions" (collector `ok: false`, message with the fix).
- omarchy: version from `omarchy-version` (fallback `pacman -Q omarchy`); change → `update` event with `from`/`to`. No git-based detection (not a checkout).
- `engine/src/redact.rs` — SPEC-ENGINE §7 rules + user patterns; applied to `meta.command` and `detail`.
- ULID ids, RFC 3339 timestamps with offset.

## Acceptance tests
- Fixture logs → expected events (golden files under `engine/tests/golden/`).
- Second run on the same fixtures yields 0 events (`idempotency::` tests).
- Rotation handled (fixture with a rotated pacman.log).
- `redaction::` tests pass for every pattern in SPEC-ENGINE §7.
- Every emitted event validates against `schema/event.schema.json` (jsonschema in tests).

## Constraints
Read-only on the host. Never run `snapper` with sudo. Table-driven pacman
parser so new log edge cases become fixture rows, not code branches.
