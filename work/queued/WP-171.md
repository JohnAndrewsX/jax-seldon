# WP-171 — Logbook files that are symbolic links

0.2.x; engine core, security; stage 2 Fable; likely a short ADR (SPEC-ENGINE
§2 allows following a file link today). From the WP-168 review (N1, N3).

**Observed.** A file link inside the logbook (a journal day, `STATUS.md`, a
case file, `ledger/*.jsonl`, a view) is followed: `seldon log` rewrote the
link's target outside the logbook (frontmatter, old text, entry). WP-168
refuses linked folders; files are the same escape class and worse (an
existing file outside is rewritten).

**Before 0.2.0** (Fable, WP-168 stage 2): one rule for folders and files,
one Breaking entry, and the `doctor` row makes WP-168's refusal
discoverable. Merge order: WP-168 → WP-166 → WP-171.

Mechanism to change: `sys::write_atomic_at` resolves the final link on
purpose (`MAX_LINKS`), SPEC §2 "the link stays and its target is
replaced".

**Do.**
- Decide (ADR): refuse a file link at every logbook write (append and
  replace), or replace the link with a real file and say so. Recommended:
  refuse with exit 1, like WP-168's folders.
- `doctor` gets a layout row that names linked folders and files (WP-168
  N3), so the user learns before a write is refused.

- The ADR records the accepted residual for WP-168 and this WP: "The check
  is lstat-then-create without O_NOFOLLOW; a process with write access to
  the logbook can swap a folder for a link between the two. Accepted: such
  a process can edit the logbook directly."

**Acceptance.** A test per writer with a file link; mutants killed; `just
check` green.
