# WP-154 — Shared rules for every git call of the engine

Ships in 0.2.0 on the integration branch `next`: branch from `next`, merge
into `next`. Source: the Fable stage 2 of WP-136 (2026-10-07).

Role: Engine Dev (Opus, high). Small.

**Goal.** What WP-136 learned about a hostile clone becomes a rule for
every git call, without breaking the logbook's own git. The logbook is the
user's repository: their config, hooks, signing and terminal stay in
effect for commits.

**Rules.**
1. **Cap the output of every `Run` of git.** Every `run_*` in `sys.rs`
   takes a cap. git callers default to 1 MiB. `usize::MAX` stays only
   where a caller needs the whole output (the pacman list, dossier
   queries), named at the call.
2. **Read-only git queries never reach the network.** This covers
   `query`, `head`, `is_dirty`, `branches`, `check_toplevel` and
   `version`. They get `GIT_ALLOW_PROTOCOL=none`, `GIT_NO_LAZY_FETCH=1`,
   and `--no-lazy-fetch` where git ≥ 2.44 takes it. Commit and push paths
   keep transport.
3. **Pin every "refused" claim with a byte-level test.** Text scans of
   formats git parses (config, gitdir files) list the parser's edge
   cases: BOM, CRLF, `\` continuation.

**Acceptance.**
- Tests: a 100 MB stderr from a stub git is capped.
- A logbook that is a partial clone does not fetch during
  `seldon status`.
- Commits still sign and run hooks as configured.
- `just check` is green.
