# WP-131 — Printer configuration as a hashed collector source

> **Parked 2026-10-08 (operator E30).** Built on branch
> `wp/131-printer-hashes` (71f17d5d, handover there), not merged. Live
> evidence on the dev host: cupsd rewrites `/etc/cups/printers.conf` and
> every PPD (with a fresh `.ppd.O`) on each print job, and the user cannot
> read them (0600 / 0640 root:cups), so the stat hash reports every printed
> page as a printer change. A fix would need a new, user-readable source
> (the CUPS client's printer list), which is not worth it for printers. The
> AGENTS.md §6 permission is withdrawn. WP-129 covers an agent's privileged
> printer commands.

Ships in 0.2.0 on the integration branch `next`: branch from `next`, merge
into `next`.
- Operator decision 2026-10-07 (E14 b): "ja, aber nach a)", i.e. after
  WP-129.
- AGENTS.md §6 is amended for it: hashes only, the same way as for
  `pacman.conf` (WP-114).

Role: Engine Dev (Opus, high). Small.

**Goal.** A printer added, changed or removed is visible in the record
even when no agent did it (GUI, `lpadmin` by hand, the CUPS web page).

**Inputs.**
- AGENTS.md §6 as amended.
- ADR-0028 and ADR-0037, if accepted (hash-only collectors, the cut-off
  and stat-hash rules).
- WP-113's config collector (`collectors/config.rs`).
- WP-114's `/etc/pacman.conf` hashing.
- SPEC-ENGINE §2/§4/§7.

**Outputs.**
- The config collector hashes these, **content never read into an event**:
  - `/etc/cups/printers.conf`, `/etc/cups/classes.conf`,
    `/etc/cups/ppd/*`;
  - `~/.cups/lpoptions` (the user's default printer).

  Printer URIs can hold credentials (smb, ipp with userinfo).
- An unreadable file (`printers.conf` is root-owned 0600 on Arch) gets
  the stat hash, size and mtime/ctime, as in ADR-0037. Say honestly in
  SPEC what that does and does not see.
- Events: `config-change|add|remove` with subject the path.
- Class **attention**. Say whether a printer change made by an open case
  is auto-explained.
- Tests: hash-only, unreadable `printers.conf` (stat), add/remove,
  idempotent.
- SPEC §2/§4, guide 06 en/de, CHANGELOG.

**Acceptance.**
- `just check` is green.
- Live on the test host: the second network printer added by the user
  through the GUI or `lpadmin` → one event at the next capture.
- Removed again → one event.
- No printer URI in the ledger.

**Dependencies.** WP-129 is merged into `next`.
