# WP-181 — Desk key registry, the `?` overlay, Esc layers

Stage 1 0.2.x (plugin only); stage 2 (command palette) 0.3. From the
prototype 0.3 debate (`jax-seldon-private/prototype-0.3/debate-2026-10-09/`,
SYNTHESIS.md §3 NEW-6; item B1 and the Esc finding); operator decisions
E6 (Enter never launches an agent), E48–E63.

Role: Plugin Dev (Opus). Medium plugin, small docs. Reviewer: Opus. No
ADR (SPEC-PLUGIN §5.3 rewrite, KEYBINDINGS.md).

**Problem.** Keys live in `Desk.key` (`plugin/Desk.qml`), the footer and
SPEC §5.3 separately, so they drift. Digits are dispatched by
`deskSectionForKey` *before* `textKey`, and the Graph owns `0` for fit
(`sections/Graph.qml`): a section on `0` would steal it silently. Esc
while an action is armed closes the desk (the Esc chain in `Desk.qml`
knows section back → search → stacked detail → dismiss; "armed" is not a
layer). Harmless — it disarms — but wrong.

**Do — stage 1 (0.2.x).**
- `Model.KEYS`: one registry `{key, scope, modes, when, action, label}`.
  It drives `Desk.key`, a generated footer, a `?` overlay that lists the
  keys of the current scope, and `g`/`G` (first/last row).
- Esc gets an "armed" layer first: Esc on an armed action disarms and the
  desk stays open.
- `y` copies the selected item's **id only** (ADR-0036: never logbook text
  into the clipboard-for-prompts path).
- Digits belong to the registry: `0` stays the Graph's fit; the 0.3
  sections (Crashes, Reports) take their digits from the registry, not
  from the prototype (SYNTHESIS §7.8).
- SPEC-PLUGIN §5.3 is generated from or checked against the registry;
  docs/KEYBINDINGS.md follows.

**Do — stage 2 (0.3, after WP-187).** The command palette (Ctrl+K or
`:`) lists the selected item's actions with their keys; its rows **arm
like keys** (no click bypasses the arm, unlike the prototype's
`keys.js`); it never offers a mode switch (ADR-0045 §8, A2); E6 holds.

**Acceptance.** Keys unique per scope — the test fails on a second `0`;
every SPEC §5.3 row is in the registry and vice versa; every fixture
`ActionBar` id is reachable by a key; Esc on an armed action disarms and
the desk stays; the harness (`desk-view.sh`) proves each existing key
still does what it did; `just check` green (private HOME and
XDG_RUNTIME_DIR). Stage 2: palette rows arm; no mode switch in the list.

**Inputs.** `plugin/Desk.qml`, `plugin/Model.js`, `plugin/sections/*.qml`,
`plugin/components/desk/ActionBar.qml`, `Arm.qml`; docs/SPEC-PLUGIN.md
§5.3, docs/KEYBINDINGS.md; ADR-0034, ADR-0036, ADR-0045 §8; WP-173 (a
held key never confirms); SYNTHESIS §0 (key `0`, Esc), §1 B1, §7 items
4, 8, 9; the G2 papers; FEEDBACK 45; the prototype's `js/keys.js` (what
not to copy); WP-183a's skill; `$OMARCHY_PATH/shell/Ui/PanelKeyCatcher.qml`.

**Dependencies.** None for stage 1; before WP-163 (its preset key) or with
it. Stage 2 after WP-187.
