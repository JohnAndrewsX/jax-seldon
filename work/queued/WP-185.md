# WP-185 — Crashes in the record (E28 stages 2–3)

0.3. From the prototype 0.3 debate
(`jax-seldon-private/prototype-0.3/debate-2026-10-09/`, SYNTHESIS.md §3
NEW-10; items C7, C8); operator decisions E27 (journal metadata only),
E28 (stages 2–3 in 0.3 with an ADR), E57 (no bar colour for a crash, also
shell/Hyprland/hyprlock), E61 (the inbox guards against mistakes).

Role: Engine + Plugin Dev (Opus, high). Medium engine, medium plugin.
Reviewer: Opus; Fable stage 2 (new collector, journal read, redaction).
ADR: "Crashes in the record" (Fable writes, next free ADR number; the
operator accepts): collector `journal`, one row per executable, derived
status, "again", `ignore`/`unignore`, structured correlation, **no bar
colour** (records E57), the EASY §6 row, the `crash-capture-off` note.

**Goal.** Crashes are in the record, read from the journal, with
Omarchy's own identity rule, without a second alarm beside Omarchy's toast.

**Do.**
- **Collector `journal`** (source name `journal`, never `coredump`):
  the user's own systemd-coredump entries (`_UID` = own uid,
  `MESSAGE_ID=fc2e22bc6ee647b6b90729ab34a250b1`): `COREDUMP_COMM`,
  `COREDUMP_EXE`, `COREDUMP_SIGNAL_NAME`, `COREDUMP_PID`, timestamp. Never
  `COREDUMP_CMDLINE`, `COREDUMP_ENVIRON` or the core. The journal cursor is
  the idempotency key. The read path follows Omarchy's
  (`$OMARCHY_PATH/bin/omarchy-crash-watch`: `journalctl -o json` with a
  fixed argv, a timeout, no shell); redaction (`~`, SPEC-ENGINE §7) before
  the event is written. Event kind `crash`, timeline kind `crash`.
- **One row per executable** (Omarchy's key: the executable's basename,
  since `comm` is truncated to 15 characters); id = the first crash
  event's full ULID (not `cr-` + 8 characters). Status derived at build:
  `new | analysed | in-case | fixed | again | ignored`. `again` keeps the
  earlier case id or ignore reason visible ("ignored 3 Oct: '<reason>' ·
  crashed again 2×"). Never "regression" (no core, no identity proof).
- **Commands:** `seldon crash case|ignore|unignore|analysis … --json`
  (CONTRACT rows, fixtures); `ignore` ships with `unignore`. The analysis
  has one home: the inbox file of WP-166 (`seldon inbox add`).
- **Correlation:** structured `{eventId, kind, subject, minutesBefore}`
  (WP-184), the desk words it.
- **Bar (E57):** crashes never change the pill's colour or count;
  "crashed again after a case closed it" is a quiet attention row in
  Needs you (joins `Model.needs`, WP-179, with a safety-equality test); at
  most a tooltip line. Revisit after the live week.
- **Desk:** a Crashes section (its digit from WP-181's registry); the EASY
  §6 row (ADR-0045); a note when Omarchy's crash capture is off
  (`omarchy-toggle-crash-capture` stops only the watcher; systemd-coredump
  keeps journaling).

**Acceptance.** The collector run twice adds no event; `~` redacted;
CMDLINE/ENVIRON never read (test with a crafted entry); the pill is
byte-identical with a crash in the fixture; "again" wording tests;
`unignore` restores the derived status; theme check in 3 themes; the live
check on the test host with a provoked crash (orchestrator); `just check`
green (private HOME and XDG_RUNTIME_DIR for every child).
