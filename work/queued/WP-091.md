# WP-091 — Snapper access changes are recorded as notes

Role: Engine Dev (Opus, high). 0.1.4 wave 2, depends on WP-088
(capture.rs). Files: engine/src/commands/capture.rs, engine/src/
collectors/snapper.rs if needed, docs/SPEC-ENGINE.md §4.

## Goal

When the snapper collector changes between degraded and ok across two
captures (the user granted or removed read access, ADR-0026), the ledger
gets an observation note, so the change is visible in the history.

## Inputs

decisions/ADR-0026-snapper-read-grant.md (Seldon never runs the grant;
it is the user's command), the state-reset note from WP-081 (precedent
for a seldon note), engine/src/commands/capture.rs (cursors before the
capture hold the previous state), docs/SPEC-ENGINE.md §4 snapper.

## Outputs

- Note with existing values only: `source: seldon`, `kind: note`, actor
  `system`, subject `snapper`; both directions (degraded→ok, ok→degraded
  e.g. after a SYNC_ACL rewrite removed the grant). Not an own change.
- Tests: both transitions, no note when unchanged, idempotent, first run
  ever records no transition. Mutants.
- SPEC §4 paragraph; CHANGELOG line. No schema change.

## Acceptance

`just check` 0; mutants. Review: stage 1 Opus.
