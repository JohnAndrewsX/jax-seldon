# WP-087 — Redaction: quote-aware curl context and repeated options

Role: Engine Dev (Opus, high). 0.1.4 wave 1. Module: engine/src/redact.rs
only (plus its tests). Follow-up from the WP-084 review.

## Goal

The curl-style rules (curl-user, proxy-option, proxy-userinfo,
cookie-option, and the `-p` password rules that share the same context
idiom) mask every credential on a command line: a `&`, `;` or `|` inside
quotes no longer ends the command context, and an option given twice
(`-u a:b … -u c:d`, `-b x … -b y`) is masked both times.

## Inputs

engine/src/redact.rs (the shared `[^\n;&|]*?` context idiom, the joined
triggers from WP-084), docs/SPEC-ENGINE.md §7, work/completed/WP-084/
HANDOVER.md (timings, perf rows), the redaction tests and the hook perf
case in engine/tests/.

## Outputs

- One quote-aware context fragment, defined once and reused by every rule
  that uses the idiom today (do not fork per rule).
- Repeated options: the second occurrence is found by scanning on from
  the previous match, not by loosening the anchor to the command word.
  Name the mechanism in a code comment.
- Tests: quoted separators (`'a&b'`, `"x;y"`) keep the context; repeated
  `-u`, `-U`, `-b`, `--proxy-user` are all masked; an unquoted `;` still
  ends it (no over-masking of the next command); prose rows stay clear.
  Mutant per claim.
- SPEC-ENGINE §7 sentence; CHANGELOG line (neutral wording).

## Constraints

The WP-084 timings are acceptance tests: 16 KB curl line ≤ 0.13/0.53 ms
order of magnitude, hook curl case < 5 ms. A quote alternation inside a
lazy repetition can regress them — measure before and after, same
machine, and put both numbers in the handover. No new crates.

## Acceptance

`just check` 0; timings before/after in the handover; mutants listed.
Review: stage 1 Opus, stage 2 Fable (security).
