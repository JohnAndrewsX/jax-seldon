change of the repository set or `SigLevel` is a crisis.

## Live case (orchestrator, 2026-10-09, fresh test host)

`omarchy channel set rc` (via `omarchy-refresh-pacman rc`) rewrote
`/etc/pacman.conf` (`[omarchy] Server = https://pkgs.omarchy.org/rc/$arch`)
and `/etc/pacman.d/mirrorlist` (stable-mirror → rc-mirror for core,
extra and multilib; the old one kept as `mirrorlist.bak`), then ran
`pacman -Syyuu` (a kernel upgrade) before `omarchy update` took its
snapshot. Seldon 0.1.4+next recorded the upgrade, the keyring
reinstalls and the update's two snapshots, but not the channel switch.
Two consequences for this WP: the scope `/etc/pacman.d/*.conf` misses
`mirrorlist` (no `.conf`), which is where the channel moves every Arch
repository; and a channel switch done through Omarchy's own command
should read as one explained change (owner: `omarchy channel set`), not
as a crisis — decide in the ADR whether a repository change inside an
Omarchy channel switch is attention, and how Seldon tells it apart
(e.g. the server hosts `*.omarchy.org`).
