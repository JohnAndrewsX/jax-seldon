# WP-180 — Case and drift memory lines: what the agent may do, what changed, what was dismissed

Part 1 0.2.x (plugin only); part 2 0.2.y (a CONTRACT row). From the
prototype 0.3 debate (`jax-seldon-private/prototype-0.3/debate-2026-10-09/`,
SYNTHESIS.md §3 NEW-5; items B5, B6); operator decisions E42, E48–E63.

Role: Plugin Dev (Opus), Engine Dev for the part-2 fixture. Small + small.
Reviewer: Opus; Fable short on part 2 (contract row). No ADR (see the
open question below).

**Problem.** The case detail's R3 line ("every step that can break boot
needs your go", `Model.js`) claims a guard that is off by default
(WP-134). A dismissed drift that comes back says nothing about the earlier
reason. "What changed" on a case is one flat list.

**Do — part 1 (0.2.x).**
- **R3 line (B5).** "Seldon's skill tells your agent to ask before each
  step that can break boot or login; Seldon does not enforce it." It
  changes with WP-134's `guard = ask` (WP-134 carries that sentence).
- **"What changed · N" (B5)** grouped **by source**: Packages / Files /
  Omarchy / Commands / Snapshots; the actor per row; "+N older" kept;
  never due. **No** Boot/Services group (that would be a second
  classifier beside `class.rs`).
- **Dismiss (B6).** The Dismiss form says: "It shows up again as new if
  <subject> changes again." The **detail** (never the row) of a new drift
  with the same kind and subject says: "An earlier change to <subject>
  (<its date>) was dismissed: '<reason>'"; on a crisis it adds "This is a
  new change; that reason does not cover it." No `↺`. Only the earlier
  event's date is cited: the index has no `resolvedAt`/`resolvedBy`
  (SYNTHESIS §7.15; the fields go to WP-184).

**Do — part 2 (0.2.y).**
- **Treat as R3 (B5).** A `plan set <ID> --risk R3 --json` row in
  docs/CONTRACT.md with a fixture (E42: no bump); the action shows on
  cases without an open agent session only, one way (no "Treat as R2").

**Acceptance.** `model.test.js` grouping tests incl. "+N older"; the
dismissed-before line appears in the detail and never in a row; the crisis
caveat; the `plan set --json` fixture validates; *Treat as R3* hidden while
an agent session is open; `just check` green.

**Settled by the orchestrator (2026-10-09).** E42 is the newer and the
general rule: a command the plugin runs is contract through an ADR, a
schema *or* a CONTRACT.md row, fixtures and both sides in one PR. A new
`plan set --risk` row therefore needs a CONTRACT.md row and fixtures, no
ADR — unless the reviewer finds a field a released plugin would misread.
