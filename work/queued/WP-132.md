# WP-132 — Guard: Omarchy routes by a read-only allow-list

Role: Engine Dev (Opus, high). Operator decision 2026-10-07 (E2), after
the WP-130 Fable stage 2 recommended it. Targets `main` (the dev-host
guard, not the product).

## Goal

Today the guard blocks a *list* of Omarchy routes that change the system.
A new changing route in an Omarchy update would pass. Invert it: only
read-only routes pass (`omarchy commands --json` is the source of truth
for the route set; `help`, `--help`, `list`, `show`, `status`, `version`,
`commands`, `plugin validate|list`, `agent usage` …), every other
`omarchy …` route and `omarchy-*` binary fails closed unless the test
host gate applies.

## Inputs

`scripts/guard.py`, `scripts/guard-test.sh`, `work/completed/WP-130/`
(TABLE.md, Known limits), `omarchy commands --json`, AGENTS.md §6.

## Outputs and acceptance

- The allow-list as data in `scripts/guard.py`, each entry with the reason.
- Table rows: every read-only route used in this repo's docs and scripts
  passes; a made-up `omarchy foo bar` and an unknown `omarchy-*` binary
  block; all WP-130 rows stay green.
- A check that lists routes from `omarchy commands --json` absent from the
  allow-list (information, not a failure).
- `just check-guard` and `just check` green; the operator sees the new
  table rows before the merge.
