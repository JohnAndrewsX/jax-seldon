# WP-224 — Omarchy edge compatibility (Qt 6.12, edge package names, moved shell docs)

A 0.4.x patch. Found in the E92 edge survey (2026-10-14) on a dev host
switched to Omarchy's edge channel ("Quattro RS 4.5" preview).

Role: dev (Opus). Reviewer: Opus.

**Problem.**

1. Qt 6.12's `qmllint` (it arrives with edge) flags `id: form` in
   `plugin/…/EventDetail.qml` and `id: top` in `plugin/…/ListColumn.qml`
   (ids that shadow a property or type). `just qmllint` and so `just check`
   are red on an edge host, against the stable tree too.
2. Edge ships `omarchy-dev`, `omarchy-settings-dev` and the kernel
   `linux-omarchy-bore`. The engine's always-red package list
   (`engine/src/config.rs`, `engine/src/drift.rs`) names only `omarchy`,
   `omarchy-settings` and `linux-omarchy`, so an edge update is not red;
   the `pacman -Q omarchy` fallback and the Omarchy collector's attribution
   miss `omarchy-dev`. A channel switch reads as "removed omarchy" plus
   "installed omarchy-dev" with a version drop (4.0.4 → 4.0.0.rNNNN).
3. `shell/README.md` is now a short index; the plugin contract moved to
   `docs/omarchy-shell.md` in Omarchy's git repo (not installed).
   `Ui/Button` labels now shrink and elide when the button is narrower
   than its label. Two Omarchy-assumption ledger rows (`shell-readme-contract`,
   `button-focusable`) no longer hold.

**Do.**

1. Rename the two ids (and every reference) so Qt 6.12 qmllint passes;
   keep Qt 6.11 green too.
2. Treat the channel packages as one family: `omarchy` / `omarchy-dev`,
   `omarchy-settings` / `omarchy-settings-dev`, and any `linux-omarchy*`
   kernel variant are always red; the fallback and attribution accept
   either name. A channel switch (remove one family member, install the
   other in the same transaction) is reported as one Omarchy channel
   change, not as a removal plus an unrelated install; the version drop
   is not an error. Check how the existing drift/transaction code groups
   it before adding anything; prefer the smallest change.
3. Update the two ledger rows in `scripts/check-omarchy-assumptions.sh`'s
   ledger (and docs that cite `shell/README.md` as the contract) to the new
   truth; keep the pin on stable (ADR-0055).

**Acceptance.** `flock /tmp/seldon-check.lock env SELDON_FULL_CHECK=1 just check`
green on the dev host (edge, Qt 6.12). Engine tests: rows for `omarchy-dev`,
`omarchy-settings-dev`, `linux-omarchy-bore` red; a channel-switch
transaction fixture produces one channel-change event; mutants that drop
the `-dev` names are killed. `just check-upstream` exit 0 with the two rows
updated. Plugin headless tests run on the test host against an edge tree
are a follow-up, not this WP (say "not run" for them).

**Inputs.** AGENTS.md; private `audit-e92/01-edge-survey.md` (the edge
survey, read §1–§3); `engine/src/config.rs`, `engine/src/drift.rs`, the
Omarchy collector; `scripts/check-omarchy-assumptions.sh`; ADR-0055.
