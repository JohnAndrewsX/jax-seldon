# WP-066 — frontmatter: hand-edited lists, BOM and fence spaces survive a save

Role: Engine Dev (Opus, high). Size: M. Wave: 3. Depends: WP-057
(journal frontmatter handling lands first). Findings: F-533, F-535.

## Goal

Saving a case never corrupts valid hand-edited frontmatter, and files
written by other editors parse.

- **F-533** — the frontmatter writer (frontmatter.rs ~179-187,
  ~231-265; model/mod.rs ~87-97) attaches comments and blank lines to the
  open list entry, accepts quoted keys, and re-parses its own output
  before writing; output that would not parse is refused with an error
  and the file stays unchanged.
- **F-535** — a leading UTF-8 BOM is accepted (and kept on render), and a
  closing `---` followed by spaces or tabs is accepted
  (`Document::parse` ~47-67, `fence_len` ~95-106).
