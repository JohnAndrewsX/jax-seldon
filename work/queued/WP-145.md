# WP-145 — Follow-ups with a trigger on any case

Ships in 0.2.x. Source: the study of the second predecessor "JARVIS" (private, in the orchestrator's notes; never in this repository). Operator decision 2026-10-07. (J2)

Role: Engine Dev with a plugin part (Opus, high). ADR first.

**Goal.** Deferred checks stop living in a hand-kept list or a private
timer. Any case, also a completed one, can carry a follow-up: a text plus
a trigger. Triggers:
- a date;
- the next login or reboot;
- after the next system update;
- a device attached (by name);
- after N days of use.

A due follow-up shows at session start (for agents, as an id only) and in
the desk's Today section. Done or dismissed is recorded.

**How.**
- An ADR (contract: an optional field under ADR-0035 §6 before the 0.2.0
  tag, or contract 3 after it).
- `plan followup <ID> --when … -- <text>`.
- The capture evaluates the triggers it can see: date, boot id, an
  update in `pacman.log`, a device in udev or the dossier.
- Tests per trigger.
