# WP-010 — Plugin skeleton: manifest, Service.qml, BarWidget.qml, states

## Goal
A plugin that loads in the shell, reads the fixture index, shows the pill
with real counts, and renders a useful state when the engine or the index
is missing. Everything later in Phase 1-3 builds on this file set.

## Inputs
docs/SPEC-PLUGIN.md §1-§4 §7-§9, docs/CONTRACT.md, schema/index.schema.json,
fixtures/index.sample.json (WP-002), plugin/ stubs (WP-001),
memory/omarchy-shell.md (incl. the WP-001 findings on summon/toggle routing),
built-in plugins under `$OMARCHY_PATH/shell/plugins/` (clock, agents, media).

## Outputs
- `plugin/manifest.json` final for Phase 1 (kinds, entry points, `seldon`
  block, `barWidget` metadata and settings schema).
- `plugin/Service.qml`: `FileView` on the index path with `watchChanges`,
  JSON parse with try/catch, `contractVersion` check, `index` property,
  state machine `ok | engineMissing | notInitialised | indexMissing |
  indexStale | contractMismatch`, engine detection via `seldon --version`,
  capture/status timer with `busy` serialisation, `run(args)` with fixed
  argument arrays only, `SELDON_INDEX` override for development.
- `plugin/BarWidget.qml`: `WidgetButton` pill `⟡ A · D` with the colour
  rules of SPEC-PLUGIN §4, tooltip, left/middle/right click wiring (Panel
  and Overlay may still be stubs).
- `plugin/components/Banner.qml`: one banner per non-ok state, each with
  its one-click fix (AGENTS.md §7).
- `plugin/Model.js`: pure helpers used by the pill and banners.
- `docs/TESTING.md`: how to smoke-load the plugin with the fixture index
  on the dev host and on the test host.

## Acceptance tests
- `omarchy plugin validate plugin/` and `just qmllint` pass.
- With `SELDON_INDEX=fixtures/index.sample.json` the pill shows the counts
  derived from the fixture (active cases, open drift).
- All five non-ok banner states render (forced via a dev override or by
  manipulating the index path), each with its fix action.
- Engine-missing detection works with `PATH` manipulated so that `seldon`
  is not found.
- Smoke load on the test host (copy per docs/HERDR-SETUP.md §5) shows no
  QML errors in `qs log`.

## Constraints
Never block the shell thread. Only fixed command argument lists. qs.Ui
components and Style/Color tokens only. No symlinks, no `omarchy.*` ids.
Resolve the open question in memory/omarchy-shell.md on IPC routing
(`shell toggle` hits the overlay, not the bar widget) and record the answer
there; if it needs a SPEC-PLUGIN §8 change, say so in the handover.
