# WP-102 — Import Markdown task files as cases

Role: Engine Dev (Opus, high). After WP-101 (`--start --agent` reuses
`agent start --new` internals). ADR-0027 §7. No contract change.

## Goal

A task the user wrote as a Markdown file in a project folder (and
perhaps already handed to an agent) becomes a Seldon case with one
command, without copying text by hand and without touching the file.

## Inputs

ADR-0027 §7, engine/src/commands/import.rs (`ImportSource`, marker and
report pattern of the vault import, WP-043), engine/src/commands/plan.rs
(`plan new` internals), docs/SPEC-ENGINE.md §3 (`import`), SPEC-LOGBOOK
§3 (imported cases, tags), docs/user/{en,de}/09, redaction rules
(SPEC-ENGINE §7: the body is logbook text, redact like a note).

## Outputs

- `seldon import task <FILE|DIR>… [--area A] [--zone Z] [--risk R]
  [--recursive] [--start [--agent]] [--dry-run] [--json]`: title from the
  first `# ` heading (else the file name without extension), Intent from
  the body (the heading removed), defaults yellow/R1/normal, Log line
  `imported from <~path>`, tag `imported`; a directory imports its `*.md`
  files (sorted; `--recursive` descends); `--start` starts each case,
  `--start --agent` also launches the agent on the *first* one only
  (one active session per user); applies by default, `--dry-run` lists
  what would be created.
- Idempotent: `.seldon/imports/tasks.json` keys `~`-path → {hash, case};
  same path and hash → `created: 0`, exit 0; same path, new hash → a new
  case whose Log names the earlier one; the source file is never read
  for writing, never moved. Paths outside the home directory are
  imported with the path redacted in the Log line.
- Report in `--json` (`{created: [ids], skipped: [{path, reason}],
  started, launched}`); autocommit `seldon: import task`.
- SPEC-ENGINE §3, SPEC-LOGBOOK §3 (`imported` tag), guide 09 en/de
  (section "Task files"), guide 05, CHANGELOG. Panel: none in this WP
  (CLI only; a panel "Import…" file picker is a later decision).

## Acceptance

`just check` 0; tests: heading/no heading, directory, recursive,
idempotency on re-run, changed file, `--dry-run` writes nothing, `--start`
and `--start --agent` with a stubbed launcher, redaction of a body
containing a token, exit 1 on a non-Markdown path; mutants. Review:
stage 1 Opus.


## 0.2.0 form (operator, 2026-10-06: no 0.1.5; built on `next`)

**WP-102 — import Markdown task files as cases** (Engine, then Plugin,
Opus high; 102a wave 1, 102b wave 3 after WP-122). Engine: `seldon import
task <path>… [--area <slug>] [--dry-run] --json` reads `- [ ]` / `- [x]`
items and `#` sections of the named Markdown files (the user's own task
files, never the logbook), one queued case per open item (title ≤ 72
chars from the item, Intent = the item and its indented lines,
`source: <file>#<line>` in the frontmatter, tag `imported`), completed
cases for `- [x]` items only with `--include-done`; idempotent (a second
run finds the `source` and creates nothing; `--json` says `skipped`);
dry run lists what would be created; redaction §7 applies to the text.
Desk: **Import tasks…** in the Work list head opens an inline form (path
field with the engine's path validation, area, "dry run" result list),
then one click imports; fixed argv `seldon import task <path> --json`,
the path one argument, never interpolated; an imported case's detail
shows "imported from <file>". Acceptance: engine tests (parsing, title
rule, idempotency twice, dry run writes nothing, a path outside `$HOME`
or inside the logbook is refused exit 1, redaction mutant); CONTRACT.md
argv line; harness cases (dry run, import, second import reports
skipped, refusal shown); `just check` 0; live check on the test host
with a ten-item task file. Review: stage 1 Opus, stage 2 Fable (file
path from a text field, unsandboxed plugin).
