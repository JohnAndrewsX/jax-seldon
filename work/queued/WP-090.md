# WP-090 — Plugin: stale code after an update; harness record order

Role: Plugin Dev (Opus, high). 0.1.4 wave 1. Files: plugin/,
tests/plugin/service-states.sh (and harness), packaging/set-version.sh
and expected-files.txt only if a version constant is added,
docs/user/{en,de}/11-update-and-uninstall.md, README.md and
plugin/README.md update sections.

## Goal

(a) After `omarchy plugin update jax.seldon` the bar keeps running the
old plugin code until the shell restarts (seen on the test host with
0.1.3). Users are told so, and if feasible the panel shows it. (b) The
snapper-degraded harness case no longer flakes on the order of its
fix-command records (wl-copy vs terminal).

## Inputs

$OMARCHY_PATH/shell (plugin loading, rescan — check whether a rescan is
meant to reload an already loaded plugin and say what you found),
plugin/manifest.json, plugin/Service.qml, plugin/Model.js, packaging/
set-version.sh, tests/plugin/service-states.sh (~line 260), docs/user
guide 11 en/de, memory/omarchy-shell.md, docs/SPEC-PLUGIN.md.

## Outputs

- Docs: guide 11 en/de and both READMEs: restart the shell
  (`omarchy-restart-shell`) after a plugin update, unless the shell
  check shows the update is meant to reload.
- If feasible: a version constant in the loaded code (set by
  set-version.sh, listed where expected-files needs it) compared with
  `manifest.json` on disk; when they differ the panel shows a neutral
  hint with one fixed action, argv `["omarchy-restart-shell"]`, no
  arguments, no shell string. Reading the plugin's own manifest is not
  Seldon data: AGENTS.md §3 applies to the logbook and index (state this
  in the handover). Harness case for both states. If not feasible, say
  why and ship the docs part.
- Harness: the snapper-degraded record assertion is order-independent.
- CHANGELOG line; SPEC-PLUGIN sentence if a state is added.

## Acceptance

`just check` 0, `omarchy plugin validate plugin/`, qmllint clean;
mutants for the hint; harness run 3× green. Review: stage 1 Opus is the
last gate (plugin UI); live check on the test host by the orchestrator.
