# WP-008 — Reconciliation and `drift` commands

## Goal
Events that match no case become drift; drift can be resolved, and the
resolution survives index rebuilds.

## Inputs
docs/SPEC-ENGINE.md §5, decisions/ADR-0008-drift-first-class.md,
docs/CONCEPT.md (Drift and Crisis), schema/event.schema.json
(`resolution`, `refersTo`), fixtures/logbook/ (the three drift rows).

## Outputs
- `engine/src/reconcile.rs` — the four rules of SPEC-ENGINE §5: agent + active-case link, pacman dependency auto-link, affected-paths/steps proposal (`proposedCase`), otherwise drift; red zone → `crisis: true`.
- `seldon drift [--crisis-only]`, `seldon drift link <EVENT> <CASE>`, `seldon drift explain <EVENT> "<intent>" [--zone --risk --area]` (creates a retroactive case), `seldon drift dismiss <EVENT> --reason TEXT` — each appends a `resolution` event; the original line is never edited.
- Case files get the linked event ids in `events:`; `proposedEvents` in the index.
- Zone classification table (packages, `/etc`, units, systemd user units → red; `~/.config` → yellow; logbook → green) in one module with tests.

## Acceptance tests
- Fixtures produce exactly the three expected drift rows (two crisis, one with `proposedCase`).
- link/explain/dismiss append resolution events and the rows disappear on rebuild.
- Dependency auto-link works (pacman transaction fixture).
- Resolution events validate (`refersTo` + `resolution` required by the schema's `allOf`).

## Constraints
Ids are validated by regex before use. `explain` reuses the WP-006 case
creation path; no second template.
