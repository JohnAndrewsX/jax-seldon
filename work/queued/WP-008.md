# WP-008 — Reconciliation and `drift` commands

## Goal
Events that match no case become drift; drift can be resolved, and the
resolution survives index rebuilds.

## Inputs
docs/SPEC-ENGINE.md §5, decisions/ADR-0008-drift-first-class.md,
docs/CONCEPT.md (Drift and Crisis), schema/event.schema.json
(`resolution`, `refersTo`), fixtures/logbook/ (the three drift rows).

## Outputs
- `engine/src/reconcile.rs` — the four rules of SPEC-ENGINE §5: agent + active-case link, pacman dependency auto-link, affected-paths/steps proposal (`proposedCase`), otherwise drift; red zone → `crisis: true`.
- `seldon drift [--crisis-only]`, `seldon drift link <EVENT> <CASE>`, `seldon drift explain <EVENT> "<intent>" [--zone --risk --area]` (creates a retroactive case), `seldon drift dismiss <EVENT> --reason TEXT` — each appends a `resolution` event; the original line is never edited.
- Case files get the linked event ids in `events:`; `proposedEvents` in the index.
- Zone classification table (packages, `/etc`, units, systemd user units → red; `~/.config` → yellow; logbook → green) in one module with tests.

## Orchestrator notes (2026-10-01)
- Drift is already *derived* by the WP-007 index builder (`engine/src/index/`:
  grouping per txId, leader, computed zone, routine class via
  `pkgcmd::is_plain_full_upgrade`, proposals per ADR-0015, the 200-item
  cap of ADR-0020). Do not re-implement it: `reconcile.rs` provides the
  *commands* and the engine-time rules that write to the ledger and the
  case files, and reuses the index's drift model for `seldon drift`.
- Rules per SPEC-ENGINE §5 (amended) and ADR-0013/0015/0017: rule 1 link
  by active case (hook-written events already carry the case; collector
  events reach it through the attribution pass of WP-009); rule 2
  dependency auto-link; rule 3 proposal; rule 4 drift eligibility; rule 5
  grouping; rule 6 crisis.
- Commands exactly per CONTRACT.md: `drift [--crisis-only] [--json]`,
  `drift link <id> <case> [--only]`, `drift explain <id> [--only] -- <intent>
  [--zone --risk --area]` (creates a retroactive case via WP-006's case
  store), `drift dismiss <id> [--only] -- <reason>`, `drift show <id> --json`
  (full member list of a group). A command on a group member resolves every
  open member in ONE ledger write (one `resolution` line per member, same
  ts/actor/detail/case, `meta.txId`; ADR-0013 §4); `--only` resolves the
  named event alone; re-running finds zero open members and writes nothing.
- Case files: `link`/`explain` add the event ids to the case's `events:`
  (ADR-0012 §10); also add collector events that the attribution pass
  attributed at capture time (WP-009 left this to reconciliation) — one
  pass in `capture` after the append.
- Zone table lives in `model::event::zone_for` (ADR-0014 §2, ADR-0019);
  do not duplicate it — extend its tests if a case is missing.
- **Engine bug to fix here** (found live by WP-012): `commands/open.rs`
  no-tty path runs `omarchy-launch-editor <path>` through `sys::run` with
  a 10 s timeout and kills it — nvim dies after 10 s. Fix: spawn detached
  (`stdin/stdout/stderr = Stdio::null()`, own process group, no wait);
  `NotFound` → the existing message; one `try_wait` after ~200 ms, a
  non-zero exit → "`<program>` exited with N" (exit 1); otherwise report
  `{"launched": true, "program": …}` and exit 0. `Stdio::null()` is
  mandatory (an inherited pipe would stall the plugin's queue). Test with
  a stub launcher that sleeps.
- Module ownership: `engine/src/reconcile.rs`, `engine/src/commands/drift.rs`,
  `commands/open.rs` (the fix only), `engine/tests/drift.rs`; WP-009's
  final merge may land in parallel — rebase when told.
- Every writing command calls `index::rebuild_if_initialised` (CONTRACT
  rule 2). Tests through `common::Env` only.

## Acceptance tests
- Fixtures produce exactly the four expected drift items (two crises, one with `proposedCase`, one yellow group `members: 3`) — the WP-007 golden covers derivation; here: `seldon drift --json` on a fixture copy lists them.
- link/explain/dismiss append resolution events and the rows disappear on rebuild.
- Dependency auto-link works (pacman transaction fixture).
- Resolution events validate (`refersTo` + `resolution` required by the schema's `allOf`).

## Constraints
Ids are validated by regex before use. `explain` reuses the WP-006 case
creation path; no second template.
