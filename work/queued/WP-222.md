# WP-222 — the runtime-dir guard tells a foreign Quickshell from a leftover

A 0.4.x patch (tests only). Found in the WP-191 review (N5) and in
WP-221's full check (2026-10-13).

Role: QA (Opus). Reviewer: Opus.

**Problem.** `real_runtime_check` in `tests/plugin/real-home-guard.sh`
fails on any new entry under the real runtime dir's `quickshell/by-id`
that no running process holds. Another program's short-lived Quickshell
instance leaves such entries too: on the dev host a file-chooser portal
(D-Bus activated, `qs -p /usr/share/<other>/…/shell.qml`) started during
desk-view runs, and the gate failed although every plugin assertion
passed. A user with such a program would see the same false alarm.

**Do.** Classify a new, unheld entry by what the instance ran: read the
entry's instance metadata (Quickshell writes it next to `ipc.sock`; verify
which file names the config path and how, against the installed
Quickshell) and count it as a leftover only when its config is one of
the harnesses' trees or the plugin's; report a foreign instance as `ok`
with a note naming its config path. Read only the metadata the decision
needs; never the logs. If the metadata cannot tell, fail as today.

**Acceptance.** `real-home-guard.test.sh` gains rows: a foreign entry
(config outside the harness trees) passes with the note; a harness
entry left behind fails; an entry without readable metadata fails; a
mutant that treats every entry as foreign is killed. `just check` green.

**Inputs.** `tests/plugin/real-home-guard.sh`, `real-home-guard.test.sh`;
AGENTS.md §6 (test harnesses never write into the user's live session);
work/completed/WP-161, WP-212; the private WP-191 review packet (N5).
