# WP-204 — the Work column headers show the whole count

0.2.x, plugin only. From the WP-200 Fable review (2026-10-11, follow-up
c). From ADR-0053 rung 3 on, and past rule 4's caps today, the index
lists fewer queued or active cases than exist. The Work column headers
count the list (`Model.workColumns`), so they read "QUEUED 50" on a
logbook with 450 queued cases.

Role: Plugin Dev (Opus, high). Reviewer: Opus (plugin only, no contract
change).

**Do.** `Model.workColumns` takes each column's total from
`summary.queuedCases` / `summary.activeCases`, which the index already
carries, and the header reads "QUEUED 50 / 450" when the list is
shorter, exactly as it does under the agent filter today; unchanged
when the list is whole. No engine or schema change.

**Acceptance.** A model test with a short list and a larger summary
count shows "50 / 450"; a whole list shows the plain count; the
headless desk view case still passes; `just check` green; evidence
words in the handover.

**Inputs.** `plugin/Model.js` (`workColumns`), `plugin/Desk.qml`,
`plugin/tests/model.test.js`; CONTRACT.md rule 4; ADR-0053 §5.

Depends on: WP-200 merged into `next`.
