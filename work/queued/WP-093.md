# WP-093 — Redaction: e-mail addresses in event subjects and texts

Role: Engine Dev (Opus, high). 0.1.4 wave 2, depends on WP-087
(engine/src/redact.rs). Must ship in the same release as WP-089.
Raised by the WP-089 worker: with `~/.local/share/applications` watched,
a desktop entry's file name becomes an event subject, and user-named web
apps can carry an e-mail address in that name (seen on a real host). The
redaction rules (SPEC-ENGINE §7) have no e-mail rule.

## Goal

An e-mail address in any text the engine writes (event subjects and
texts, cases, journal lines from collectors and hooks) is masked before
the write, like the other redaction rules.

## Inputs

engine/src/redact.rs (rule table, ASCII boundaries, the url-userinfo
rule), docs/SPEC-ENGINE.md §7, work/completed/WP-062, WP-084 and WP-087
handovers (perf rows, disjointness test), engine/src/collectors/config.rs
(subjects of config events).

## Outputs

- A rule `email` that masks the local part (keep the domain, or mask
  both — decide and say why in the handover; the subject must stay
  recognisable enough for a user to find the file).
- Not masked: SSH remotes `git@host:owner/repo` and `user@host` without a
  dot-TLD domain (the url-userinfo rule covers URLs); package versions
  and `@` in npm scopes (`@scope/pkg`). Tests for each.
- The disjointness test and the perf rows still pass (16 KB line,
  hook case).
- SPEC §7 row; guide 06 en/de sentence that file names under watched
  paths become subjects and how `skipPaths` keeps one out; CHANGELOG.

## Acceptance

`just check` 0; mutants listed; timings in the handover. Review: stage 1
Opus, stage 2 Fable (privacy).
