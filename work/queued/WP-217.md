# WP-217 — replace the YAML parser before the RUSTSEC-2024-0449 acceptance expires

0.3.x (a patch: no surface changes). The 0.3.0 release build failed its
`cargo audit` gate on RUSTSEC-2024-0449 (`unsafe-libyaml` 0.2.11,
unmaintained) via `serde_yaml` 0.9.34, which is itself deprecated
upstream. The orchestrator accepted the advisory in
`packaging/audit-ignore.txt` until **2027-01-31** on Fable's advice
(private `review-0.1.1/handovers/release-030-audit-fable.md`): an
unmaintained notice, not a vulnerability; the engine parses only local
YAML the user controls. AGENTS.md §7 has said "swap before packaging"
since 0.1.0.

Role: Engine Dev (Opus, high). Reviewer: Opus, then Fable (security:
the parser reads logbook front matter, config and imported task files).

**Do.** Choose a maintained YAML parser that does not depend on
`unsafe-libyaml` (check `serde_yaml_ng`'s current dependency first; the
alternatives may be outside AGENTS.md §7's crate list — then the WP
brings a one-line justification for the operator and the reviewer).
Swap all call sites (about 29 in `engine/src`) with byte-identical
results on every fixture and on the ×150 scaled logbook (a differential
test old vs new parser over all fixture front matter); remove the
`audit-ignore.txt` line; `cargo audit` clean without it.

**Acceptance.** The differential test passes on every fixture; `cargo
audit` clean with no ignore line; `just check` green; the release
dry run's audit step green; evidence words in the handover.

**Inputs.** `engine/Cargo.toml`, `engine/src` (grep `serde_yaml`),
`packaging/audit-ignore.txt`, CONTRIBUTING.md "Dependency advisories",
AGENTS.md §7.

## Operator decision 2026-10-13 (E90): re-scoped to `serde-saphyr`

Stage 1 (branch `wp/217-yaml-parser`, handover there) compared the
candidates. A God's/Devil's advocate debate (Fable, private notes) found
that `yaml_serde` only removes the notice: it is the same c2rust parser
(`libyaml-rs`, ~220 `unsafe` sites) under a fork with a single crates.io
owner, so the swap would bring no safety, speed or durability gain. The
operator keeps the ignore line until 2027-01-31 and swaps only for a real
gain in safety, speed or durability.

`serde-saphyr` (pure safe Rust, YAML 1.2, actively maintained) is the
candidate that could bring one. This WP is now:

- **Measure first.** Parse time and allocations against `serde_yaml` on
  every fixture and on the ×150 scaled logbook (the `index` and `capture`
  paths), the binary size of the static musl build, and `cargo audit`.
- **Prove the bytes.** The engine has no `Value` type from saphyr: add a
  small one of its own (order kept) or justify `serde_json::Value` with
  `preserve_order`, rebuild the writer's plain-safe check, and show with
  the differential test that every logbook byte and every error text the
  user sees stays the same, or list each difference for the operator.
- **Then the operator's §7 go** with the measurements in hand (a one-line
  justification), and the swap. Reviewer: Opus, then Fable (security).

Not started before 0.3.x patches with higher priority; due well before
2027-01-31. In December the orchestrator checks once whether a better
option has appeared, such as a team-owned `libyaml-rs` or a second release.
