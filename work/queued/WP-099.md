# WP-099 — Crash-proof seldon notes (state reset and snapper access)

Role: Engine Dev (Opus, high). 0.1.5 (or late 0.1.4 if a slot is free),
after WP-091. From the WP-091 stage-2 review.

## Goal

A crash between the ledger append and the `cursors.json` save no longer
repeats the `state-reset` note or the snapper access note on the next
capture; the SPEC limitation sentence WP-091 adds is removed again.

## Inputs

engine/src/commands/capture.rs (append ≈ 174, save ≈ 177, `state_reset`,
`access_change`), docs/SPEC-ENGINE.md §3/§4 (the limitation sentence),
the test `a_crash_before_the_cursor_save_does_not_duplicate`, the WP-091
review packets (private folder; the stage-1 crash probe).

## Outputs

- Dedup keyed on the note's identity, not its detail (the state-reset
  detail carries the capture time): `source: seldon`, `kind: note`,
  subject / `meta.sources`, dated at or after the old `lastRun` (or the
  reset's binding) — skip writing when such a note exists.
- Two crash tests (one per note), mutants.
- SPEC: limitation sentence removed; one sentence that §7 redaction does
  not apply to seldon notes (they embed collector messages, already in
  `index.json`).

## Acceptance

`just check` 0; mutants. Review: stage 1 Opus, stage 2 Fable (engine
core).
