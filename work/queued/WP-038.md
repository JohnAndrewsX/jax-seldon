# WP-038 — Engine attributes its own installs; Phase 0 exit procedure refreshed

## Goal
Files the engine writes outside the logbook (the theme hook script, the
Claude Code / Omarchy-Agent harness settings) never appear as open drift,
and the operator procedure matches the shipped wizard.

## Inputs
work/completed/PHASE-0-EXIT-transcript.md (findings F1, F2),
engine/src/commands/init.rs (theme hook and harness installs),
engine/src/collectors/config.rs (config events, attribution pass),
decisions/ADR-0017 ADR-0019 ADR-0021, docs/SPEC-ENGINE.md §4 §5 §8 §9,
work/PHASE-0-EXIT.md, docs/TESTING.md.

## Outputs
- When `init` (or `hook install`) writes a file under a watched config
  path, the next config event for that path is attributed to actor
  `seldon` with an automatic explanation ("installed by seldon init
  --theme-hook") — either by recording the write in the manifest with an
  owner marker, or by a resolution event written at install time. No
  open drift, no crisis; the event stays in the ledger. Rule 7 in
  SPEC-ENGINE §5; test: init with the theme hook, capture, drift empty.
- `work/PHASE-0-EXIT.md` rewritten to the current wizard (no separate
  `hook install`, first capture/baseline/dossier inside `init`, Lua
  config paths on Omarchy 4), kept as the reference for a fresh install.
- docs/TESTING.md gains the "fresh machine" smoke list from the transcript.

## Acceptance tests
- `just check` exit 0; the new test proves zero drift after `init
  --theme-hook` + `capture`.
- The procedure file runs top to bottom on a fresh user without edits.

## Constraints
No new crates; tests through common::Env with SELDON_TEST_GUARD; never run
against a real logbook.
