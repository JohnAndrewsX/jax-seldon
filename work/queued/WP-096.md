# WP-096 — Default actor and attended marker for launched agents (revised for ADR-0027)

Role: Engine Dev (Opus, high). Independent of WP-100 (different files;
may run in parallel); before WP-101's close path. No contract change:
`actor` already allows `agent:[a-z0-9-]+` (schema/event.schema.json
$defs.actor).

## Goal

A write by an agent that Seldon launched is recorded as that agent even
when it forgets `--actor` — so an agent close (ADR-0027 §5) is never
recorded as human — and the launched session can tell it is attended
(ADR-0027 §2d) without probing.

## Inputs

engine/src/commands/agent.rs (launch), plan.rs, log.rs, drift.rs,
decide.rs, event.rs (`--actor` handling), schema/event.schema.json
(actor pattern), docs/SPEC-ENGINE.md §3 and §8, ADR-0027 §2d and §5.

## Outputs

- `seldon agent start` (and WP-101's `--new`, WP-095's `ask`, whichever
  merges first) sets `SELDON_ACTOR=agent:<launcher-name>` (normalised to
  the schema pattern; refuse or map anything else, tests) and
  `SELDON_ATTENDED=1` in the launched process.
- `plan`, `log`, `drift`, `decide`, `event`, `hook generic` use
  `SELDON_ACTOR` when `--actor` is absent; explicit `--actor` wins; an
  invalid value is exit 1 naming the allowed form.
- `SELDON_ATTENDED` is read by nothing in the engine (it is the agent's
  signal; the skill and `AGENTS.md` v2 define its meaning); the engine
  only sets it and documents it in SPEC-ENGINE §8.
- `plan done` by an agent actor: the refusal without a Result is
  WP-101's; this WP only makes the actor reliable and records it.
- SPEC-ENGINE §3/§8, guide 04/05 en/de, CHANGELOG.

## Acceptance

`just check` 0; tests for env default, explicit override, invalid value,
both variables set by launch (stubbed launcher), `hook generic` actor
from env; mutants. Review: stage 1 Opus.
