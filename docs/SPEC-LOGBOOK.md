# SPEC-LOGBOOK.md — The logbook on disk

Normative. Version 1. Everything here must be readable without Seldon and
must open as an Obsidian vault.

## 1. Location and identity

- Default path `~/Seldon`; any path is allowed. Stored in
  `~/.config/seldon/config.toml` (`logbook = "/home/user/Seldon"`).
- The root contains `.seldon/logbook.toml` with `schemaVersion = 1`,
  `created`, `machineId` (hostname + random suffix), `language`.
- The root is a git repository. The engine commits with `seldon: <summary>`
  when `git.autocommit = true` (default).

## 2. Layout

```
Seldon/
├── AGENTS.md                 rules for every agent (template, user-editable)
├── PROJECT.md                what this machine is for; frontmatter: language, machineId
├── STATUS.md                 GENERATED by `seldon status`
├── DECISIONS.md              index of decisions/ (generated section + free text)
├── inbox/                    anything not yet triaged: ideas, findings, drift notes
├── journal/YYYY/YYYY-MM-DD.md   daily notes, written
├── ledger/YYYY-MM.jsonl      events, append-only, machine source (ADR-0003)
├── ledger/YYYY-MM.md         GENERATED human view of the month
├── decisions/ADR-NNNN-slug.md
├── work/queued/ work/active/ work/completed/   cases C-YYYY-NNN-slug.md
├── work/<case-id>/           optional workpieces (scripts, diffs) for a case
├── areas/<area>/README.md    long-lived sections: hyprland, themes, packages, dev-env, plugins, …
├── areas/<area>/AGENTS.md    optional local rules for that area
├── system/                   dossier: hardware.md packages.md deviations.md services.md omarchy.md plugins.md
├── memory/                   agent knowledge: lessons.md, omarchy.md, <topic>.md
├── resources/                references, links, downloaded docs
├── outputs/                  generated deliverables: REBUILD.md, UPDATE-IMPACT.md, reports
├── archive/                  retired material
├── .seldon/                  logbook.toml, active-case, templates/ (engine-managed)
├── .claude/ .codex/          optional agent harnesses (installed by wizard)
├── .obsidian/                optional, created only if the wizard is told to
└── .gitignore                .obsidian/workspace*, .seldon/active-case
```

File and folder names: lowercase, hyphens, English. Prose: user's language.

## 3. Frontmatter conventions

All YAML keys are English, enum values are English, free text may be any
language. Dates `YYYY-MM-DD`, timestamps RFC 3339 with offset.

### Case (`work/*/C-YYYY-NNN-slug.md`)

Folder by status: `queued` → `work/queued/`, `active` and `verification`
→ `work/active/`, `completed` and `dropped` → `work/completed/`
(ADR-0012 §9). Transitions are engine-enforced: `queued → active →
verification → completed`, and `queued | active | verification → dropped`;
`completed` and `dropped` are terminal (corrections are new events,
ADR-0003). The Log line words (`created`, `started`, `verification`,
`completed`, `dropped: <reason>`) are English in every logbook language;
journal stubs written by the engine follow the logbook language. The
engine's autocommit stages the whole work tree (`git add -A`), so edits
made in an editor since the last command are committed under that
command's message: the logbook's history is its backup.

```yaml
---
id: C-2026-004
type: case
title: "Zed als zweiten Editor installieren"
status: active            # queued | active | verification | completed | dropped
zone: red                 # green | yellow | red
risk: R2                  # R0 | R1 | R2 | R3
priority: normal          # high | normal | low
area: dev-env             # must exist under areas/ (engine creates on first use)
created: 2026-10-01
started: 2026-10-01
closed:
snapshotBefore: 112       # snapper number, set by `seldon plan start`
agents: [agent:claude-code]
events: [01J9…, 01J9…]    # ledger event ids, maintained by engine
tags: []
---
# C-2026-004 — Zed als zweiten Editor installieren

## Intent
## Plan
- Goal:
- Steps:
- Affected paths:
- Rollback:
- Verification:
## Log
<!-- append-only; engine and agents add dated lines -->
- 2026-10-01 10:12 · created (zone red, risk R2) · human
## Result
```

Status transitions (engine enforced): `queued → active → verification →
completed`, `* → dropped`. Moving between folders is done by the engine
only. The *Log* section is append-only.

### Journal (`journal/YYYY/YYYY-MM-DD.md`)

```yaml
---
type: journal
date: 2026-10-01
cases: [C-2026-004]
---
## 10:40 · agent:claude-code · C-2026-004
Zed installiert, Keybindings nach Omarchy-Defaults gesetzt. Gelernt: …
## 18:05 · human
…
```

Entries are appended as `## HH:MM · actor · case?` headings. Never rewritten.

### Decision (`decisions/ADR-NNNN-slug.md`)

Frontmatter `id, type: decision, title, status (proposed|accepted|superseded),
date, supersedes, cases`. Body: Context / Decision / Consequences.

### Area (`areas/<area>/README.md`)

Frontmatter `type: area, name, description`. Body free. Optional
`areas/<area>/AGENTS.md` with local rules; the engine lists these in the
index so agents can find them.

### Dossier (`system/*.md`)

Generated sections are fenced:

```
<!-- seldon:begin packages.explicit -->
…
<!-- seldon:end -->
```

Text outside fences is user-owned and preserved. `deviations.md` has one
row per deviation: path, reason, date, case. The engine adds rows for
config events whose case is known; the user fills the reason.

### Memory (`memory/*.md`)

Free Markdown, frontmatter `type: memory, topic, updated`. Agents append.
`memory/lessons.md` is the one file every agent reads at session start.

## 4. Ledger line (`ledger/YYYY-MM.jsonl`)

One JSON object per line, validated against `schema/event.schema.json`.
Never edited; corrections are new events (`kind: resolution`,
`kind: correction`). Month files roll over by event timestamp.

## 5. Generated view (`ledger/YYYY-MM.md`)

```
<!-- generated by seldon; do not edit -->
# Ledger 2026-10

## 2026-10-01
- 09:14 pacman · upgrade `hyprland` 0.52.1 → 0.53.0 · case C-2026-003
- 10:12 pacman · install `zed` 0.198.4 · case C-2026-004 · agent:claude-code
- 14:02 pacman · install `ollama` 0.6.1 · **drift** · agent:codex
- 14:30 snapper · snapshot 113 "pre: ollama"
```

Wikilinks `[[C-2026-004]]` are used for cases so Obsidian's graph works.

## 6. Obsidian

The wizard can create `.obsidian/` with: daily notes folder `journal/`,
excluded folders `.seldon .claude .codex` and the case workpieces
`work/C-*/` (regex filter `/^work\/C-/`; never `work/*/`, which would hide
every case), and no community plugin
requirements. Dataview or Bases are the user's choice; Seldon's generated
Markdown must read well without them.

## 7. Portability rules

- No absolute paths inside the logbook except in the dossier.
- No code except under `work/<case-id>/` and `outputs/`.
- Everything the engine generates can be regenerated from Markdown + JSONL.
- Deleting `.seldon/` loses nothing but the active-case marker.
