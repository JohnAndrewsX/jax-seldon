# The logbook

This page walks through the logbook folder: what each folder and file
holds, which parts the engine owns and which are yours, how git keeps
the history, and how to open the logbook in Obsidian.

## Where it lives

The logbook is `~/Seldon` unless you chose another place in the wizard.
`seldon open logbook` prints the path. It is a normal folder: no
database, no hidden format. Everything in it reads well without Seldon.

## Folders and files

```text
Seldon/
├── AGENTS.md          rules for every agent
├── PROJECT.md         what this machine is for
├── STATUS.md          generated summary
├── DECISIONS.md       index of decisions
├── inbox/             ideas and findings not sorted yet
├── journal/2026/2026-10-02.md     daily notes
├── ledger/2026-10.jsonl           events, one JSON object per line
├── ledger/2026-10.md              generated view of the month
├── decisions/ADR-0001-….md        decisions
├── work/queued/ work/active/ work/completed/   cases
├── areas/<area>/README.md         long-lived topics
├── system/            the dossier: packages, services, Omarchy, hardware, plugins, deviations
├── memory/            what agents learned; memory/lessons.md first
├── resources/         references, links, downloaded docs
├── outputs/           generated reports: REBUILD.md, import reports
├── archive/           retired material
└── .seldon/           engine settings, the active case
```

| Path | What it is | Who writes it |
|---|---|---|
| `AGENTS.md` | the rules agents follow in this logbook | the template, then you |
| `PROJECT.md` | what the machine is for, what must not happen on it | you |
| `STATUS.md` | active cases, open drift, latest events | the engine (`seldon status`) |
| `DECISIONS.md` | the entry page for `decisions/`; the table between its markers is reserved for the engine, which does not fill it yet | you, outside the markers |
| `inbox/` | anything you want to sort later | you |
| `journal/` | one file per day; entries are `## HH:MM · actor · case` headings | the engine appends, you add text |
| `ledger/*.jsonl` | the events; append-only | the engine only |
| `ledger/*.md` | a readable view of each month, with links to cases | the engine (generated) |
| `decisions/` | one ADR per decision | `seldon decide` creates, you write |
| `work/` | one file per case, in the folder of its status | `seldon plan` creates and moves, you write |
| `work/<case-id>/` | optional files for one case: scripts, diffs | you |
| `areas/<area>/` | a README per topic (`hyprland`, `themes`, `packages`, `dev-env`, `plugins`, `shell`); optional `AGENTS.md` with local rules | you |
| `system/` | the dossier | the engine between markers, you around them |
| `memory/` | lessons and topic notes for agents | agents and you |
| `outputs/` | `REBUILD.md`, `IMPORT-omarchy-agent.md` | the engine (generated) |
| `.seldon/` | `logbook.toml`, the active case, templates, import markers | the engine only |

File and folder names are English and lower case. The text is in your
language: headings and frontmatter keys stay English, so the engine can
read them in every language.

## What the engine owns

Never edit these by hand:

- `ledger/*.jsonl`. It is append-only. A mistake is corrected with a new
  event, never by changing a line.
- Generated files: `STATUS.md`, `ledger/*.md`, `outputs/REBUILD.md`.
  Their first line says `<!-- generated by seldon; do not edit -->`. The
  next command writes them again.
- In a case's frontmatter: `status`, `events`, `agents`, and the folder
  the file lies in. The `seldon plan` commands change them.
- Text between `<!-- seldon:begin … -->` and `<!-- seldon:end -->`.
- `.seldon/`.

If you change one of these by mistake, `git -C ~/Seldon checkout -- <file>`
takes it back.

## What you own

Everything else is yours: a case's *Intent*, *Plan* and *Result*, the
journal text, `PROJECT.md`, `AGENTS.md`, `areas/`, `memory/`,
`decisions/`, `inbox/`, `resources/`, and the text around the generated
parts of `system/`. Edit them in any editor. The engine reads them and
keeps your text.

Two things help the engine help you:

- In a case's *Plan*, name packages and paths exactly as they will appear
  (`zed`, `~/.config/hypr/bindings.lua`). When a change matches, Seldon
  proposes the case for it.
- In `system/deviations.md`, fill the *reason* column. `seldon rebuild`
  carries your reasons into the rebuild guide.

The plugin sees an edit after the next engine command, at the latest at
the next capture. To see edits at once, run the
[watcher](11-update-and-uninstall.md#the-optional-watcher).

## A case file

```markdown
---
id: C-2026-004
type: case
title: "Install Zed as a second editor"
status: active
zone: red
risk: R2
priority: normal
area: dev-env
created: 2026-10-01
started: 2026-10-01
closed:
snapshotBefore: 112
agents: [agent:claude-code]
events: [01J9…, 01J9…]
tags: []
---
# C-2026-004 — Install Zed as a second editor

## Intent
## Plan
- Goal:
- Steps:
- Affected paths:
- Rollback:
- Verification:
## Log
- 2026-10-01 10:12 · created (zone red, risk R2) · human
## Result
```

The *Log* is append-only. The engine adds a line for each step; you and
your agents add dated lines below. Keep the frontmatter flat: one value
or one `[a, b]` list per key.

## Git

The logbook is a git repository. Each engine command commits with a
message that starts with `seldon:`. The commit includes your own edits
since the last command. So:

- `git -C ~/Seldon log --oneline` is the history of your machine;
- `git -C ~/Seldon diff` shows what you changed since the last command;
- any earlier state is one `git checkout` away.

Seldon never pushes. To back the logbook up, add a remote and push it
yourself, to a private repository: the logbook names your packages, paths
and machine.

## Obsidian

The logbook opens as an Obsidian vault. If you answered yes to the
Obsidian question, `.obsidian/` holds two settings:

- daily notes in `journal/` with the format `YYYY/YYYY-MM-DD`, so
  Obsidian's "today" note is Seldon's journal file;
- `.seldon/`, `.claude/`, `.codex/` and the case work folders
  (`work/C-…/`) excluded from search and the graph.

To add them later, copy those two settings in Obsidian (Settings, Daily
notes and Files and links, Excluded files). Then open the folder in
Obsidian with "Open folder as vault".

Seldon needs no Obsidian plugin. Cases link to each other and to the
ledger views with `[[C-2026-004]]`, so the graph shows which events
belong to which case. Dataview or Bases work on the frontmatter if you
want tables; Seldon does not depend on them.

## Moving or copying the logbook

To move it, move the folder and point the config at the new place:
change `logbook` in `~/.config/seldon/config.toml`. The engine's state
(`~/.local/state/seldon/`) belongs to one logbook. When you point it at
another, the collectors start over from the current state.

To keep a second logbook, for a test, run `seldon init --path <DIR>`.
Note that `init` sets the new folder as `logbook` in the config. Change
it back, or use `--logbook <DIR>` for single commands.
